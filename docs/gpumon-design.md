# gpumon - 遠端 GPU 監看工具規格

## 1. 目標

做一個可在 **Windows / macOS** 執行的 GUI 應用程式, 透過 **SSH** 連線到一台或多台 Linux 主機, 即時顯示遠端 GPU 的使用率, 記憶體, 溫度, 功耗, 各程序用量等資訊, 呈現方式仿 `nvtop`.

系統需求如下:

- **本機.** Windows (amd64) 或 macOS (arm64).
- **遠端主機.** Linux x86_64, 可用一般使用者帳號以 SSH 登入, 不需要 root.
- **遠端的系統元件.** 遠端必須以 glibc 為 C 函式庫. 不支援以 musl 為 C 函式庫的發行版, 此為設計選擇, 原因見 5.1. 以 musl 為 C 函式庫的發行版包括 Alpine Linux, Chimera Linux, Adélie Linux, OpenWrt, Talos, KISS Linux, 以及 Void Linux 與 Gentoo 的 musl 版本; 完整清單見 musl 官方 wiki 的 [Projects using musl](https://wiki.musl-libc.org/projects-using-musl).
- **遠端的放置路徑.** 遠端程式固定放在家目錄下的 `~/.gpumon/`, 不可變更. 遠端的家目錄必須可寫且可執行.

## 2. 設計原則

以下兩項為最高原則, 優先於本節其餘各條 (第 7 條除外) 與本文件所有章節:

- **使用者友善為最高指導原則.** 所有設計以使用者友善為準, 除非技術上做不到; 以技術上做不到為由放棄友善做法時, 須說明具體原因.
- **設計規格不是聖經.** 本文件任何條目若有錯誤, 或達不到目標, 即推翻之, 不為符合文件而犧牲結果.

其餘原則如下:

1. **不需要 root.** 以一般使用者帳號 SSH 登入即可運作.
2. **遠端不常駐.** 遠端只放一個執行檔, 不安裝服務, 不留背景程序.
3. **遠端不需預先安裝任何工具.** 不依賴 nvtop, nvidia-smi 等, 由本機自動上傳所需程式.
4. **跨廠牌.** 支援 NVIDIA (NVML), AMD (sysfs), Intel (sysfs / fdinfo).
5. **GUI 一律以 200 ms 取樣**, 使用者不需設定取樣間隔. 遠端程式仍可在執行期間調整取樣間隔, 供命令列手動測試使用.
6. **監看不干擾被監看對象.** 不主動改變遠端系統設定 (例如 persistence mode).
7. **不儲存密碼.** 登入密碼與金鑰密碼不寫入磁碟, 也不存入作業系統的密碼儲存區; 暫留於記憶體者於不再需要時立即銷毀. 此項為安全考量, 不因使用者友善原則而放寬.

## 3. 整體架構

```
本機 GUI (Windows / macOS)
  │
  │  一條 SSH 連線, 上面開多個通道
  │
  ├─ SFTP 通道, 檢查與上傳 gpumon 執行檔
  └─ exec 通道, 執行 gpumon --loop
        stdin  ← 本機送指令 (JSON Lines)
        stdout → 遠端送資料 (JSON Lines)
        stderr → 遠端錯誤日誌
```

- 遠端程式 `gpumon` 的生命週期完全綁在 exec 通道上, 通道關閉即結束.
- 每台主機一條 SSH 連線, 一個 gpumon 程序.

## 4. 連線流程

```
1. 建立 SSH 連線 (支援金鑰, 密碼, ~/.ssh/config)
2. 執行 `uname -sm`, 不是 Linux x86_64 即顯示錯誤並斷線
3. 取得遠端的程式版號與協定版本, 決定是否上傳遠端程式 (規則見下文 "遠端程式的更新"), 再比對協定版本 (規則見下文 "協定版本的比對"), 不可用即顯示錯誤並斷線
4. 開 exec 通道, 以完整路徑執行 <家目錄>/.gpumon/gpumon --loop, 並以 --interval 傳入 200
5. 讀取第一行 devices 訊息, 其 `protocol` 與步驟 3 所定的協定版本不同即顯示錯誤並斷線
6. 逐行讀取 sample 訊息, 更新畫面
7. 視窗關閉, 使用者中斷連線或斷線 → 關閉通道 → gpumon 結束
8. 非預期斷線時自動重新連線, 重做步驟 1 至 6, 不跳出視窗; 規則見下文 "連線結束的情形"
```

GUI 於遠端執行的指令一律以 `sh -c '<指令>'` 的形式送出, 使其不受遠端帳號的登入 shell 種類影響. 步驟 4 的指令為 `exec <完整路徑> --loop --interval <毫秒>`, 使遠端的 sh 直接由遠端程式取代. 遠端程式未於 stdout 輸出任何內容即以非零的結束碼結束時, 判定為遠端程式無法執行.

**用語**

連線流程有兩種不同的比對, 對象與用途皆不同:

| 用語 | 定義 | 取得方式 | 用途 |
|---|---|---|---|
| 程式版號 | 8.2 所定的 x.y.z[-stage.N], 不含 commit 與 dirty 字樣 | GUI 的程式版號為建置時注入的值; 遠端的程式版號由 `--version` 的輸出取得 | 決定是否上傳並覆寫遠端程式 |
| 協定版本 | 5.4 devices 訊息的 `protocol`, 為一個整數 | GUI 的協定版本為它所實作的最新協定版本; 遠端的協定版本由 `--version` 的輸出取得, devices 訊息的 `protocol` 為同一個值 | 決定 GUI 能否與該遠端程式溝通 |

GUI 不比對雜湊值, 也不比對 commit.

**遠端程式的更新 (步驟 3)**

遠端程式的完整路徑為 `<家目錄>/.gpumon/gpumon`, 其中 `<家目錄>` 為遠端帳號家目錄的絕對路徑, 由 GUI 執行 `printf %s "$HOME"` 取得.

GUI 執行 `<完整路徑> --version`, 自輸出取得遠端的程式版號與協定版本, 輸出格式見 5.7. 檔案不存在, 指令的結束碼不為 0, 或輸出不符合格式時, 視為無法取得遠端的程式版號.

GUI 依下表決定處理方式:

| 遠端的狀況 | 遠端程式是否正在執行 | 處理方式 |
|---|---|---|
| 無法取得遠端的程式版號 | 不檢查 | 上傳 |
| 遠端的程式版號等於 GUI 的程式版號 | 不檢查 | 不上傳, 使用遠端現有的程式 |
| 遠端的程式版號高於 GUI 的程式版號 | 不檢查 | 不上傳, 使用遠端現有的程式 |
| 遠端的程式版號低於 GUI 的程式版號 | 否 | 上傳並覆寫 |
| 遠端的程式版號低於 GUI 的程式版號 | 是 | 不上傳, 使用遠端現有的程式 |

程式版號的高低依下列順序比較, 前一項相同時才比較下一項:

1. x, y, z 三個數字依序比較, 數字大者為高.
2. 階段由低至高為 alpha, beta, rc, 無階段. 無階段即正式版.
3. 階段後的數字 N, 數字大者為高.

遠端程式是否正在執行, 判斷方式如下:

- GUI 執行 `ls -l /proc/[0-9]*/exe 2>/dev/null`.
- 輸出的任一列中, ` -> ` 之後的文字等於完整路徑, 或等於完整路徑後接 ` (deleted)` 時, 判定為正在執行.
- 此指令只能讀出同一帳號的程序所執行的檔案. 其他帳號的遠端程式位於各自的家目錄, 不在判斷範圍內.

上傳的步驟如下, 任一步驟失敗即顯示錯誤並斷線:

1. `<家目錄>/.gpumon/` 不存在時建立該目錄, 權限為 0700.
2. 以 SFTP 把 GUI 內嵌的遠端程式上傳為同一目錄下的 `gpumon.tmp`, 該檔已存在時覆寫.
3. 把 `gpumon.tmp` 的權限設為 0755.
4. 以 OpenSSH 的 `posix-rename@openssh.com` 擴充把 `gpumon.tmp` 更名為 `gpumon`, 取代既有檔案.

上傳前的確認規則如下:

- 上表的處理方式為上傳, 或為上傳並覆寫時, GUI 於上傳的步驟 1 之前跳出通知視窗, 使用者按下確認鍵後才開始上傳. 處理方式為不上傳時不跳出視窗.
- 通知視窗顯示主機名稱與遠端的放置路徑 `~/.gpumon/gpumon`, 並說明本次為首次上傳或更新. 更新時另列出遠端現有的程式版號與即將上傳的程式版號.
- 通知視窗只有一個確認鍵, 沒有取消鍵.
- 等待使用者確認的時間不計入建立連線與遠端操作的逾時.
- 多台主機同時需要上傳時, 每台主機各一個通知視窗, 依序顯示, 同一時間只顯示一個.
- 自動重新連線時需要上傳者, 同樣跳出通知視窗, 等待使用者確認的時間不計為重試失敗.
- 等待使用者確認期間, 使用者對該主機按下 "中斷連線" 或程式結束時, 該次連線中止, 不上傳, 通知視窗關閉, 不顯示錯誤視窗.
- 等待使用者確認期間, GUI 每 5 秒送出一次 SSH keepalive. 送出失敗或 10 秒內未收到回覆時判定為連線中斷, 通知視窗關閉; 首次連線時依檢查出錯誤而斷線處理, 自動重新連線時計為該次重試失敗.

上傳方式的說明:

- 遠端程式固定放在 `<家目錄>/.gpumon/`, 此路徑不可變更. **不要放 `/tmp`** (可能掛載為 noexec, 且多人共用).
- 先上傳到 `gpumon.tmp` 再更名, 上傳中斷時不會留下內容不完整的 `gpumon`. `gpumon.tmp` 與 `gpumon` 放在同一目錄, 因為 rename 不能跨掛載點.
- 不可直接寫入 `gpumon`. 該檔正在執行時, 直接寫入會失敗, 錯誤為 Text file busy.
- 標準的 SFTP rename 遇目的檔已存在即失敗, 故必須使用 `posix-rename@openssh.com` 擴充.

**協定版本的比對 (步驟 3 與步驟 5)**

步驟 3 決定是否上傳之後, GUI 比對即將使用的遠端程式的協定版本. 步驟 3 有上傳時, 該值為 GUI 自己的協定版本; 沒有上傳時, 該值為 `--version` 輸出的協定版本. 比對在啟動遠端程式之前進行, 結果如下:

| 遠端的協定版本 | 結果 |
|---|---|
| 等於 GUI 的協定版本 | 可用 |
| 低於 GUI 的協定版本 | 可用, GUI 改以遠端的協定版本與遠端程式溝通 |
| 高於 GUI 的協定版本 | 不可用. GUI 顯示錯誤並斷線, 錯誤訊息說明遠端程式較新, 並請使用者更新本機的 GPU Monitor |

步驟 5 讀到的 devices 訊息, 其 `protocol` 必須等於上述的值, 不相等時顯示錯誤並斷線.

協定版本的遞增規則與 GUI 對舊協定版本的處理見 5.4.

**連線結束的情形**

連線結束的情形分為三類, 畫面反應各不相同:

| 類別 | 成因 | 畫面反應 |
|---|---|---|
| 使用者中斷連線 | 使用者對該主機按下 "中斷連線" | 不顯示任何視窗, 該主機直接轉為未連線狀態, 既有歷史仍可查閱 |
| 檢查出錯誤而斷線 | GUI 在連線流程中檢查出錯誤後自行關閉連線, 例如平台不符, 遠端程式上傳失敗, 遠端程式無法執行, 第一行不是 devices 訊息, 遠端的協定版本高於 GUI 的協定版本, devices 訊息的 `protocol` 與 `--version` 輸出的協定版本不同 | 顯示明確的錯誤訊息, 不自動重新連線; 錯誤視窗關閉後該主機轉為未連線狀態, 既有歷史仍可查閱 |
| 非預期斷線 | 網路中斷, 逾時, 遠端程式自行結束 | 不顯示任何視窗, 該主機轉為重新連線中狀態, GUI 自動重新連線 |

使用者按下 "連線" 後, 於收到 devices 訊息之前發生的任何失敗, 包括無法建立 SSH 連線, 認證失敗與逾時, 皆依檢查出錯誤而斷線處理, 不自動重新連線. 非預期斷線只發生於收到 devices 訊息之後.

本機依下列任一情形判定為非預期斷線:

- SSH 連線回報錯誤, 或 exec 通道關閉.
- 連續 15 秒未收到遠端的任何訊息, 即連續 3 次心跳無回應. 此時間與 5.6 的看門狗相同, 本機判定斷線時遠端程式亦已自行結束.

自動重新連線的規則如下:

- 重試以心跳為節奏, 最多 5 次. 判定斷線時立即重試第一次, 之後於每次心跳的時刻重試一次, 即每 5 秒一次.
- 一次重試於 5 秒內未能建立 SSH 連線即計為失敗, 連線建立後至收到 devices 訊息之前逾時亦計為失敗. 等待 devices 訊息的上限為 15 秒, 使用者按下 "連線" 的首次連線亦同. 一次重試超過 5 秒才結束時, 下一次重試順延至其後的第一個心跳時刻. 收到 devices 訊息即為重新連線成功, 重試次數歸零.
- 第 5 次重試失敗後停止重試, 該主機轉為未連線狀態, 側欄顯示斷線原因.
- 重新連線中的主機於側欄顯示斷線原因與已重試的次數, 分頁上的狀態圖示同步顯示為重新連線中, 並提供 "中斷連線" 操作; 使用者按下後停止重試, 該主機轉為未連線狀態.
- 重試時認證失敗, 或檢查出上表第二類的錯誤時, 停止重試, 依檢查出錯誤而斷線處理.
- 重新連線成功後接續寫入原記錄檔, 並寫入一筆斷線記錄, 規則見 6.2 的 "記錄檔". 監看畫面接續顯示, 斷線期間依 6.2 的無資料時段標示.

## 5. 遠端程式 gpumon 規格

### 5.1 建置

- 語言為 Go, 與 GUI 同一個 Go module, JSON 協定的型別定義只寫一份, 兩端共用.
- NVML 以 purego 於執行期 dlopen 載入, 不使用 cgo. 因 dlopen 需要系統的動態載入器, 執行檔為動態連結 glibc, 只依賴 glibc 所提供的函式庫 (ld-linux, libc.so.6, libdl.so.2 與 libpthread.so.0), 不是完全靜態. 有 NVIDIA 驅動的主機必有 glibc. 不支援 musl 為設計選擇, 只有 AMD 或 Intel GPU 的 musl 主機亦不支援.
- 只建置 `linux/amd64` 一個版本, 內嵌在本機 GUI 的安裝包裡 (`go:embed`), 只能由 GUI 上傳到遠端, 不另行散布.
- 啟動時間需在數十毫秒內.
- 版本取自與 GUI 共用的版本套件 (見第 8 節), GUI 內嵌的遠端程式與該 GUI 的程式版號相同.

### 5.2 資料來源

| 廠牌 | 資料來源 | 說明 |
|---|---|---|
| NVIDIA | NVML (`libnvidia-ml.so.1`) | 用 `dlopen` 動態載入, 找不到就略過. `nvmlInit` 只在啟動時呼叫一次. 可取得所有使用者的程序列表. |
| AMD | `/sys/class/drm/card*/device/` (`gpu_busy_percent`, `mem_info_vram_used`, `mem_info_vram_total`), hwmon (溫度, 功耗, 時脈) | 純讀檔案, 不需初始化. 各程序用量來自 `/proc/*/fdinfo`, 非 root 只看得到自己的程序. |
| Intel | sysfs (`/sys/class/drm/card*/gt/gt*/rps_cur_freq_mhz` 等), `/proc/*/fdinfo` 的 `drm-engine-*` 欄位 | i915 與 xe 驅動欄位不同. 累計值由本機相減算出使用率. 非 root 只看得到自己的程序. |

參考實作為 nvtop 的 `src/extract_gpuinfo_*.c` (GPLv3, 只參考做法, 自行重寫).

### 5.3 NVIDIA 初始化延遲的處理

- 若遠端沒有程序在用 GPU 且未開 persistence mode, `nvmlInit` 可能需要一秒以上.
- 本設計**不處理** persistence mode (需要 root).
- 因為 gpumon 在 SSH 連線期間持續執行, 初始化只發生一次, 之後取樣不再有延遲.
- GUI 在第一次初始化期間顯示 "正在連線" 即可.

### 5.4 通訊協定 (JSON Lines)

**遠端 → 本機 (stdout)**

啟動後第一行:
```json
{"type":"devices","protocol":1,"version":"0.1.0","hostname":"gpu01",
 "gpus":[{"id":0,"vendor":"nvidia","name":"NVIDIA RTX 4090","mem_total":25769803776,"uuid":"GPU-xxxx","power_max_w":600,"clock_gpu_max":2850,"clock_mem_max":10501,
          "pci_vendor":"10de","pci_device":"2684","pci_subsys_vendor":"10de","pci_subsys_device":"165b"}]}
```

之後每個取樣週期一行:
```json
{"type":"sample","ts":1730700000.123,
 "gpus":[{"id":0,"util":87,"mem_used":12884901888,"temp":71,"power_w":312,
          "clock_gpu":2520,"clock_mem":10501,"fan":45,
          "enc":0,"dec":0,
          "procs":[{"pid":4321,"user":"alice","mem":12000000000,"util":80,"cmd":"python train.py"}]}]}
```

其他:
```json
{"type":"ack","cmd":"set_interval","ms":500}
{"type":"error","ts":1730700000.123,"msg":"nvml timeout"}
{"type":"pong"}
```

- `ts` 由遠端打時間戳記. 遠端程式啟動時讀取一次系統時鐘, 之後每筆的 `ts` 等於該讀數加上單調時鐘 (monotonic clock) 量得的經過時間, 故相鄰兩筆 `ts` 的差值不受遠端校時影響, 也不受 SSH 傳輸抖動影響. 本機只取用 `ts` 的差值, 不取用其絕對值, 換算方式見 6.2 的 "時間基準".
- `error` 訊息同樣帶 `ts`, 產生方式與 sample 相同, 供本機把錯誤對應到取樣時刻.
- devices 訊息的 `protocol` 為協定版本, 型別為整數, 目前的值為 1; `version` 為遠端程式的程式版號.
- 協定版本的遞增規則如下. 協定的變更只新增欄位, 訊息種類或指令, 且未實作該變更的程式可以忽略新增的部分時, 協定版本不變; 其他變更一律把協定版本加 1.
- 為使協定版本相同的程式可以互通, 兩端皆忽略訊息內不認得的欄位; 遠端程式收到不認得的 `cmd` 時回 `error` 訊息; 本機收到不認得的 `type` 時記錄到日誌, 不中斷.
- GUI 保留所有舊協定版本的處理能力, 可與協定版本等於或低於自己的遠端程式溝通, 比對規則見第 4 章.
- devices 訊息內每張 GPU 的 `pci_vendor`, `pci_device`, `pci_subsys_vendor`, `pci_subsys_device` 依序為 PCI 的廠商代碼, 產品代碼, 子系統廠商代碼, 子系統產品代碼. 四者的型別皆為字串, 內容為 4 位小寫十六進位數字, 不含 `0x` 前綴, 例如 `"10de"`. 四個值讀自該 GPU 於 sysfs 的 PCI 裝置目錄 (`/sys/class/drm/card*/device/`) 下的 `vendor`, `device`, `subsystem_vendor`, `subsystem_device` 四個檔案, 不需 root; 讀不到時該值為空字串. AMD 的讀取結果為推斷, 未實測. NVIDIA 的 GPU 以 NVML 回報的 PCI 位址讀取 `/sys/bus/pci/devices/<位址>/` 下的同名檔案.
- NVIDIA 的 `mem_used` 不含驅動保留的部分, 與 nvidia-smi 顯示的值一致; `power_max_w` 為目前生效的功耗上限.
- `procs` 的元素中, `cmd` 超過 512 位元組時截斷; `user` 查不到帳號名稱時為 UID 的十進位數字.
- devices 訊息內每張 GPU 的 `power_max_w`, `clock_gpu_max`, `clock_mem_max` 依序為功耗上限 (瓦), GPU 時脈上限 (MHz), 記憶體時脈上限 (MHz), 型別皆為整數, 供 GUI 把功耗與時脈換算為百分比. 取不到的欄位自該 GPU 的物件中省略. NVIDIA 可取得三個值. 測試主機上的 Intel 內建顯示晶片 (i915 驅動) 只可取得 GPU 時脈上限. AMD 的取得方式尚未查證.
- AMD / Intel 的各程序累計值 (engine time) 以原始累計值回傳, 由本機保留上一筆自行相減, 遠端保持無狀態. `procs` 的元素為此另有四個成員, 皆為以引擎名稱為鍵的物件, 值為整數, 取不到時省略: `engines` 為各引擎的累計忙碌時間, 單位為奈秒, 讀自 fdinfo 的 `drm-engine-<引擎>` (i915 與 amdgpu); `engine_capacity` 為各類引擎的數量, 讀自 `drm-engine-capacity-<引擎>`, 省略時為 1; `cycles` 與 `total_cycles` 讀自 xe 驅動的 `drm-cycles-<引擎>` 與 `drm-total-cycles-<引擎>`, 兩者各自的差值相除即為使用率. AMD 與 xe 驅動的讀取結果為推斷, 未實測.
- `procs` 的元素中, `util` 只有 NVIDIA 提供. Intel 的 sample 訊息不含整張 GPU 的 `util`, 由本機以各程序的累計值算出.
- 本機計算使用率的方式如下. 一個程序於一個引擎的使用率, 有 `cycles` 與 `total_cycles` 時為 `cycles` 的差值除以 `total_cycles` 的差值與 `engine_capacity` 的乘積, 否則為 `engines` 的差值除以兩筆 `ts` 的差值與 `engine_capacity` 的乘積. 程序的使用率取其各引擎中的最大值. Intel 整張 GPU 的使用率為先逐引擎加總所有程序, 再取最大的引擎, 並限制於 0 至 100. 新出現的程序與累計值變小的引擎不計入; 每次連線的第一筆取樣沒有使用率. AMD 整張 GPU 的使用率仍取遠端送出的 `util`. 此算法以假資料驗證, 未於有負載的 Intel 或 AMD 主機實測.

sample 訊息內每張 GPU 的數值欄位如下, 數值皆為整數. 取不到的欄位自該 GPU 的物件中省略. `procs` 為程序列表, 不列於此表.

| 欄位 | 意義 | 單位 |
|---|---|---|
| `util` | GPU 使用率 | 百分比 |
| `mem_used` | 已使用的記憶體 | 位元組 |
| `temp` | 溫度 | 攝氏度 |
| `power_w` | 功耗 | 瓦 |
| `clock_gpu` | GPU 時脈 | MHz |
| `clock_mem` | 記憶體時脈 | MHz |
| `fan` | 風扇轉速. NVIDIA 回報的值為驅動設定的目標轉速, 可能超過 100, 照原值回傳 | 百分比 |
| `enc` | 編碼器使用率 | 百分比 |
| `dec` | 解碼器使用率 | 百分比 |

**本機 → 遠端 (stdin)**

```json
{"cmd":"set_interval","ms":500}
{"cmd":"sample_now"}
{"cmd":"set_fields","fields":["util","mem_used"]}
{"cmd":"ping"}
```

- `set_interval` 下限 200 ms, 上限 10 s; 省略 `ms` 時等同 1000, 即回到預設間隔.
- `set_interval` 的 `ms` 超出範圍時回 `error` 訊息, 取樣間隔維持不變.
- `set_fields` 省略 `fields` 時等同回傳全部欄位. 可選取的名稱為上表的數值欄位與 `procs`; `id` 一律輸出. 遠端程式回 `{"type":"ack","cmd":"set_fields","fields":[...]}`, 其 `fields` 為實際套用的欄位. `fields` 含不認得的名稱時回 `error` 訊息, 不套用.
- `ping` 作為心跳 (見 5.6).

**簡寫形式 (僅供手動測試)**

stdin 的每一行依首字元分類, 以 `{` 開頭為 JSON 指令, 以 `/` 開頭為簡寫, 其餘皆為不合法輸入, 回 `error` 訊息而不猜測. 簡寫的指令名與 JSON 的 `cmd` 完全相同, 參數以空白分隔, 不另設別名; 回應一律仍為 JSON, 不因輸入形式改變. GUI 只送 JSON.

| 簡寫 | 等同的 JSON |
|---|---|
| `/set_interval 500` | `{"cmd":"set_interval","ms":500}` |
| `/set_interval` | `{"cmd":"set_interval"}` |
| `/set_fields util mem_used` | `{"cmd":"set_fields","fields":["util","mem_used"]}` |
| `/set_fields` | `{"cmd":"set_fields"}` |
| `/sample_now`, `/ping` | 同名 JSON 指令 |
| `/help` | 簡寫專用, 把可用指令與用法輸出到 stderr, 不進 stdout 的資料流 |

### 5.5 主迴圈

```go
ticker := time.NewTicker(interval)
cmds := make(chan Command)
go readStdin(cmds)          // 獨立 goroutine 讀 stdin, EOF 時關閉 channel

for {
    select {
    case <-ticker.C:
        sample := collect()                   // 在另一個 goroutine 中執行, 帶逾時
        if err := writeLine(sample); err != nil {
            return                            // stdout 寫入失敗 = 本機已斷線
        }
    case cmd, ok := <-cmds:
        if !ok { return }                     // stdin EOF = 本機關閉通道
        handle(cmd)
    case <-sigs:                              // SIGHUP / SIGTERM / SIGINT
        return
    case <-watchdog:                          // 心跳逾時
        return
    }
}
```

細節:
- **啟動後立即取第一筆樣本**, 不等待第一個取樣間隔, 之後才依間隔取樣.
- **stdout 每行後 flush** (管線模式下預設全緩衝).
- **取樣放在另一個 goroutine 並設逾時**, NVML 偶爾會卡住 (例如 GPU 重設中), 逾時就輸出 error 訊息, 不要卡住主迴圈. 逾時為 3 秒. 逾時後才完成的取樣結果捨棄; 取樣尚未完成期間到來的取樣時刻與 `sample_now` 略過, 不重複開始取樣.
- stdin 的空白行不回應, 但視為收到輸入, 重設看門狗. 單行超過 64 KiB 時回 `error` 訊息.
- **不要** 使用 nohup, setsid 或任何讓程序脫離 session 的手段.
- 結束前呼叫 `nvmlShutdown()`.

### 5.6 結束條件 (三道保險 + 看門狗)

| 事件 | 觸發情境 |
|---|---|
| stdin 讀到 EOF | 本機正常關閉通道 |
| stdout 寫入得到 EPIPE | 本機已不再讀取 |
| SIGHUP | sshd 在連線中斷時送出 |
| 看門狗逾時 | 超過 15 秒沒收到任何 stdin 訊息, 即連續 3 次心跳未到 (本機每 5 秒送 `ping`) |

看門狗用來處理網路無聲中斷 (拔網線, 筆電休眠, NAT 逾時). 遠端 sshd 預設 `ClientAliveInterval=0` 不會主動偵測, 沒有看門狗時 gpumon 可能長時間殘留.

### 5.7 命令列介面

| 用法 | 行為 |
|---|---|
| `gpumon` | 手動除錯用. 輸出一行 devices 與一行 sample 後結束 |
| `gpumon --loop` | GUI 使用. 持續取樣, 由 stdin 指令控制, 直到 5.6 的任一結束條件成立 |
| `--interval <ms>` | 取樣間隔, 預設 1000, 範圍與 `set_interval` 相同 (200 至 10000). 兩種模式皆適用, `--loop` 模式下為初始值 |
| `--steps <N>` | 取 N 筆 sample 後結束, 預設 1. 只用於不帶 `--loop` 的模式, 與 `--loop` 併用視為不合法 |
| `--version` | 於 stdout 輸出一行版本資訊後以結束碼 0 結束, 格式見下文 |
| `--help` | 輸出用法說明後結束 |

- 不認得的旗標或不合法的值, 輸出用法說明到 stderr 並以非零碼結束.
- 找不到任何支援的 GPU 時仍輸出 devices 訊息, `gpus` 為空陣列, 不視為錯誤; 由 GUI 顯示此主機沒有可監看的 GPU.
- 結束碼如下. stdin 讀到 EOF 或收到訊號而結束時為 0; stdout 寫入失敗, 看門狗逾時, 或不帶 `--loop` 時最後一筆取樣逾時為 1; 旗標不合法為 2.
- 手動測試 `--loop` 模式時, 可在終端機直接輸入 5.4 的 `/` 簡寫指令, 例如 `/set_interval 500` 或 `/sample_now`, 不必手打 JSON.
- 遠端程式的所有輸出一律使用英文, 包含用法說明, stderr 的日誌與 `error` 訊息的 `msg`.

`--version` 的輸出固定為一行, 以換行字元結尾, stdout 不含其他內容. 格式如下:

```
gpumon <完整版本字串> (protocol <協定版本>)
```

範例:

```
gpumon 0.1.0+3f2a9c1 (protocol 1)
gpumon 0.2.0-beta.3+3f2a9c1-dirty (protocol 2)
gpumon 0.1.0+unknown (protocol 1)
```

- 開頭固定為 `gpumon`.
- `<完整版本字串>` 的格式見 8.2, 其中 `+` 之前的部分為程式版號.
- `<協定版本>` 為該遠端程式的協定版本, 以十進位整數表示, 不補零.
- `gpumon`, `<完整版本字串>` 與左括號之間各以一個空白字元分隔; `protocol` 與 `<協定版本>` 之間以一個空白字元分隔.
- 去除結尾的換行字元後, 整行必須符合下列正規表示式. GUI 以此判斷輸出是否符合格式:

```
^gpumon (0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)(-(alpha|beta|rc)\.(0|[1-9][0-9]*))?\+([0-9a-f]{7}|unknown)(-dirty)? \(protocol ([1-9][0-9]*)\)$
```

## 6. 本機 GUI 規格

### 6.1 技術選擇

- Go + Wails 3 + React + TypeScript. SSH 以 `golang.org/x/crypto/ssh` 實作.
- 目標平台為 Windows (amd64) 與 macOS (arm64).
- Wails 釘選 v3.1.0, 需 Go 1.26 以上.
- GUI 的視覺設計以設計稿為前端實作的依據. 設計稿含淺色與深色兩種模式, 介面文字為英文, 其存放位置與視覺規範見 6.5.
- 主視窗首次開啟的大小為 1280 x 800. 程式記住使用者調整後的大小與位置, 下次開啟時還原; 記住的位置已不在任何螢幕的範圍內時, 改以首次開啟的大小顯示於主螢幕中央. 大小指含標題列與邊框的視窗外框. 視窗頂端高 32 的標題列區域與任一螢幕的工作區域重疊達寬 100 (視窗較窄時取視窗的寬度) 且高 16 時, 判定為仍在螢幕的範圍內, 單位為與裝置無關的像素. 視窗處於最小化, 最大化, 全螢幕或隱藏狀態時不記錄大小與位置. 大小與位置於最後一次移動或縮放後 500 ms 寫入設定檔, 程式結束前另寫入一次; 寫入失敗時只記錄到日誌.
- **淺色與深色模式.** 預設跟隨作業系統外觀設定自動切換, 執行中系統切換時即時跟隨, 不需重啟. 設定頁面提供外觀選項, 為跟隨系統, 淺色, 深色三種; 選擇淺色或深色時不再跟隨系統, 並記住選擇. 跟隨系統的做法為純前端, Go 端不參與, 前端啟動時執行下列程式, 偵測結果為深色時在 html 元素加上 dark class, 並監聽系統設定變化:

```ts
function applyColorScheme(matches: boolean): void {
  document.documentElement.classList.toggle("dark", matches);
}
const darkMediaQuery = window.matchMedia("(prefers-color-scheme: dark)");
applyColorScheme(darkMediaQuery.matches);
darkMediaQuery.addEventListener("change", (event: MediaQueryListEvent) => {
  applyColorScheme(event.matches);
});
```

色彩全部定義為 CSS 變數, 淺色值寫在 `:root`, 深色值寫在 `html.dark` 下覆寫, 元件與圖表只引用變數, 不寫死顏色; `:root` 另宣告 `color-scheme: light dark`, 使捲軸與表單控件等原生元件一併跟隨. 曲線顏色, 最大最小淡色帶與無資料灰底亦納入變數. 變數的名稱與數值見 6.5. 系統匣圖示不經前端, macOS 用範本圖示 (template icon) 由系統自動配色, Windows 另提供一張深色模式用的圖示, 由 Wails 於系統外觀變更時自動切換. 應用程式圖示為藍色圓角方磚上的白色章魚, 眼睛位於臉部; 系統匣圖示為單色的章魚剪影, 觸手與應用程式圖示相同, 頭部圓頂較大, 眼睛加大並位於圓頂內. macOS 26 的深色圖示樣式下, 應用程式圖示仍為藍底白章魚, 不採用系統自動轉換的深色版 (未實測). 圖示的向量母版與由其產生的衍生圖檔放在 `assets/icon/`, 衍生圖檔由該目錄的 `generate.sh` 產生並納入版控, 母版更動時須重新執行並一併提交. 圖示為自製素材, 不列入第三方授權清單.

### 6.2 功能

- **視窗配置.** 視窗左側為固定側欄, 右側為主區域. 側欄上半為主機清單, 每台主機顯示 user@addr, 連線狀態, 以及 "連線" 或 "中斷連線" 按鍵, 並提供編輯與刪除操作; 清單末端為 "新增主機" 按鍵. 主機依新增的先後排列, 順序不隨連線變動. 側欄下半為 "記錄檔" 與 "設定" 兩個入口. 主區域顯示監看畫面, 歷史畫面, 記錄檔清單或設定頁面其中之一. 點選側欄的主機時主區域顯示監看畫面, 並切換至該主機的分頁. 點選 "記錄檔" 時顯示記錄檔清單; 已有開啟中的記錄檔時顯示歷史畫面, 歷史畫面提供返回記錄檔清單的操作.
- **控制項的位置.** 主區域頂端為工具列. 監看畫面的工具列左側為各主機的分頁, 分頁上帶有該主機的狀態圖示, 右端為縮放控制項 (見 "顯示範圍"); "連線" 與 "中斷連線" 按鍵只位於側欄. 歷史畫面的工具列由左至右為返回記錄檔清單的按鍵, 標題, 固定時刻的標籤 (有固定時刻時才顯示), 縮放控制項與 "顯示全部" 按鍵. 記錄檔清單的工具列顯示檔案總數與總大小, 並提供全選, 開啟與刪除按鍵. 設定頁面由上而下為外觀, 語言與曲線三項, 每項左側為標題與說明, 右側為選項; 選擇後立即生效並記住. 曲線一項為縱向排列的勾選清單, 每列依序為勾選框, 曲線顏色與曲線名稱, 說明文字為 "Drawn on the monitor and history screens.". 側欄的每台主機佔三行, 依序為狀態圖示與 user@addr, 狀態文字與斷線原因, 以及 "連線" 或 "中斷連線" 按鍵與編輯, 刪除按鍵.
- **主機表單.** 新增與編輯主機使用同一個表單, 欄位為位址, 連接埠, 使用者名稱, 金鑰檔. 位址為必填, 可填主機名稱, IP 位址或 `~/.ssh/config` 的 Host 名稱. 連接埠留空時取 `~/.ssh/config` 的設定, 無設定時為 22. 使用者名稱留空時取 `~/.ssh/config` 的設定, 無設定時表單要求填寫. 金鑰檔留空時取 `~/.ssh/config` 的設定, 無設定時依 6.3 的金鑰搜尋順序; 欄位旁提供選擇檔案的按鍵. 表單不含密碼欄位, 密碼於連線時依 6.3 要求輸入.
- **主機管理.** 新增, 編輯與刪除主機. 主機以 user@addr 識別, 同一台主機以不同帳號登入視為不同主機. 連線中或重新連線中的主機不可編輯, 也不可刪除, 須先中斷連線.
- **監看畫面與歷史畫面.** 畫面分為監看畫面與歷史畫面兩種, 前景一次只顯示其中一種, 可隨時切換. 監看畫面顯示主機的即時狀況, 歷史畫面顯示使用者選擇的記錄檔. 前景為歷史畫面時, 連線中的主機在背景繼續取樣與存檔.
- **多主機監看.** 監看畫面以分頁顯示主機, 每台主機一個分頁, 一次只顯示一台主機. 分頁之下的內容區由上而下為該主機每張 GPU 的 GPU 卡片, 最後為一張程序卡片, 卡片之間有間距; 監看畫面沒有主機標題列, 不顯示遠端主機名稱 (歷史畫面的分組標題仍顯示). 連線狀態, 斷線原因與重試次數由側欄與分頁上的狀態圖示提供, "連線" 與 "中斷連線" 只位於側欄. 內容超出視窗高度時, 工具列固定於主區域頂端, 其下的內容區整體上下捲動. 主機有連線中, 重新連線中, 未連線三種狀態. 使用者按下 "連線" 至收到 devices 訊息之前, 狀態顯示為 "正在連線". 未連線的主機不顯示曲線; 重新連線中的主機照常顯示斷線前的讀數與曲線, 顯示範圍的右緣停在最後一筆取樣的時刻. 監看畫面沒有 GPU 卡片時, 內容區只顯示一行說明文字, 不放按鍵. 說明文字依情形為: 未連線時 "Not connected. Use Connect in the sidebar to connect to this host."; 正在連線時 (按下 "連線" 至收到 devices 訊息之前) "Connecting to this host."; 已連線而尚未收到第一筆取樣時 "Waiting for the first sample."; 沒有可監看的 GPU 時 "This host has no GPU that GPU Monitor can monitor.".
- **每張 GPU 的顯示內容.** GPU 卡片的版面如下, 內容仿 nvtop. 卡片頂端的標題列橫跨整張卡片, 左側為收合箭頭, GPU 編號與完整的型號名稱, 名稱過長時截斷並於滑鼠停留時顯示完整名稱, 右側為曲線圖例, 圖例過長時在標題列內換行. 標題列之下左側為文字讀數, 右側為曲線圖; 曲線圖的繪圖區頂端對齊讀數頂端, 時間軸刻度底端對齊讀數底端, 繪圖區高度隨之填滿, 最低 92 (與裝置無關的像素); 視窗較窄而曲線圖折到讀數下方時, 繪圖區高 92. 文字讀數包括使用率, 記憶體的已使用量與總量, 溫度, 風扇轉速, 功耗, GPU 時脈與記憶體時脈, 一律顯示實際數值與單位. 使用率與記憶體另附橫條, 功耗在取得功耗上限時一併顯示上限, 取不到的數值顯示 "N/A". 曲線圖的縱軸為 0 至 100, 預設畫使用率與記憶體佔比兩條曲線, 記憶體佔比為已使用量除以總量. 使用者可加選溫度, 風扇轉速, 功耗, GPU 時脈, 記憶體時脈的曲線, 同一張圖的曲線數上限等於曲線顏色的數目, 曲線顏色共 7 種, 定義見 6.5, 每種顏色在淺色與深色背景下皆須可清楚辨識; 此選擇為全域設定, 於設定頁面勾選, 所有主機與歷史畫面共用, 並記住選擇. 加選的曲線中, 溫度以 0 至 100 度對應縱軸全高, 風扇轉速以其百分比對應縱軸, 功耗與時脈以各自的上限 (見 5.4) 為滿刻度. 顯示範圍內的溫度超過 100 度, 風扇轉速超過 100%, 功耗或時脈超過其上限, 或取不到功耗, 時脈的上限時, 該曲線改以顯示範圍內的最大值為滿刻度, 圖例標示滿刻度的實際數值, 曲線不截平. 取不到記憶體總量時不畫記憶體佔比的曲線. 加選的曲線於顯示範圍內沒有任何數值時不畫, 也不列入圖例. 滑鼠移到曲線圖上時, 顯示該時刻每條曲線的實際數值與單位; 數值提示預設顯示於游標右側, 游標超過曲線圖寬度的 62% 時改顯示於游標左側, 使其不超出曲線圖的邊界.
- **GPU 卡片的收合.** 每張 GPU 卡片可個別收合, 收合後只留標題列一行, 不顯示讀數, 曲線圖與圖例; 點選該標題即恢復顯示. 收合狀態依主機與 GPU 分別記住, GPU 以 devices 訊息的 `id` 識別, 重新連線與重新啟動程式後維持不變, 監看畫面與歷史畫面共用. 收合只影響顯示, 該 GPU 的取樣與存檔照常進行, 程序卡片照常列出該 GPU 上的程序.
- **程序卡片.** 每台主機一張, 列出該主機所有 GPU 上的程序 (GPU 編號, PID, 使用者, 記憶體, 指令), 表格的 GPU 欄以與 GPU 卡片標題相同的 GPU 編號標籤顯示. 指令欄每列只顯示一行, 過長時以省略號截斷, 滑鼠停留時顯示完整指令; 表格寬度不超出卡片. 監看畫面顯示最新一筆. 沒有任何程序時, 表格顯示一列說明文字. 程序記錄存入記錄檔 (見 "記錄內容"), 供歷史畫面查閱. 程序卡片可個別收合, 收合後只留標題列一行, 標題文字與展開時相同. 收合狀態依主機分別記住, 重新連線與重新啟動程式後維持不變, 監看畫面與歷史畫面共用; 收合只影響顯示, 取樣與存檔照常進行.
- **取樣間隔.** 所有主機的取樣間隔固定為 200 ms, 不提供調整. 依 NVIDIA 的 NVML 文件, NVIDIA 回報的使用率為驅動程式於一段取樣期間內的平均值, 期間依產品為 1/6 秒至 1 秒; 200 ms 不短於其中最短的期間. 連線時以 `--interval` 傳入 200, GUI 不送出 `set_interval`. 視窗最小化或切到背景時取樣間隔不變, 該時段的資料照常存入記錄檔.
- **關閉與最小化.** 關閉視窗即結束程式, 所有連線中斷, 遠端 gpumon 隨之結束. 有主機處於連線中或重新連線中狀態時, 關閉前跳出確認視窗, 說明將中斷的主機數, 選項為 "結束" 與 "取消"; 沒有此種主機時直接結束. 匣圖示選單的 "結束" 適用相同的確認. 最小化時隱藏視窗到 Windows 系統匣或 macOS 選單列, 連線與取樣持續; 點匣圖示顯示視窗, 匣圖示選單提供 "顯示視窗" 與 "結束". 以左鍵點匣圖示顯示視窗, 以右鍵點匣圖示開啟選單; Windows 的匣圖示另有滑鼠提示文字, 重新連線中時顯示另一句. macOS 於最小化後保留 Dock 圖示, 點 Dock 圖示亦顯示視窗. 確認視窗中 Enter 等同 "結束", Esc 等同 "取消". 程式收到終端機的 Ctrl+C 或 SIGTERM 時不經確認直接結束, 結束過程照常中斷連線, 存檔並銷毀密碼. macOS 於有主機連線中時登出或關機, 確認視窗會使系統的登出或關機中止.
- **主選單.** 程式提供主選單, macOS 顯示於螢幕頂端的選單列, Windows 顯示於主視窗頂端. 選單只含各平台慣例上應有的項目, 不重複視窗內已有的功能. macOS 的選單依序為 GPU Monitor, Edit, Window, Help. GPU Monitor 選單含 "About GPU Monitor", "Settings...", 系統標準的服務與隱藏項目, 以及 "Quit GPU Monitor"; Edit 與 Window 選單只含系統標準項目; Help 選單含 "Third-Party Licenses". Windows 的選單依序為 File 與 Help. File 選單含 "Settings" 與 "Exit"; Help 選單含 "Third-Party Licenses" 與 "About GPU Monitor". macOS 的 "Settings..." 的快速鍵為 Cmd+, , "Quit GPU Monitor" 的快速鍵為 Cmd+Q. 語言為繁體中文時, macOS 系統標準項目的用語依 macOS 的慣例, 例如拷貝與貼上. "Settings" 顯示設定頁面, 與側欄的 "設定" 入口相同. "Quit GPU Monitor" 與 "Exit" 的行為與關閉視窗相同, 適用相同的確認. 選單文字隨語言設定切換. 主選單於 Wails 3.1.0 的行為未實測. Wails v3.0.0-beta.8 於 Windows 深色模式下, 程式還原視窗的大小與位置後, 主選單的項目初次顯示時不繪出 (wails issue #4462), 3.1.0 是否仍發生未查證; 實作時須於 Windows 實機驗證, 仍發生時須在記住視窗大小與位置 (見 6.1) 與 Windows 的主選單之間取捨.
- **關於視窗.** "About GPU Monitor" 與 "Third-Party Licenses" 開啟同一個獨立視窗, 稱為關於視窗. 關於視窗內有 "關於" 與 "第三方授權" 兩個分頁, 開啟時顯示的分頁由所點選的選單項目決定. 關於視窗首次開啟的大小為 600 x 600, 同一時間只有一個; 視窗已開啟時再次點選選單項目, 只切換分頁並把視窗移至最前. Windows 的關於視窗不顯示主選單. 關於分頁頂端顯示應用程式圖示, 其右為應用程式名稱, 完整版本字串 (見 8.2), 建置時間, Go 版本, 作業系統與其版本, 平台與 WebView 版本; Windows 另顯示 WebView2 執行期的版本. 關於分頁提供 "複製資訊" 按鍵, 把上述資訊以純文字複製到剪貼簿, 第一行為應用程式名稱, 其後每行為 "標籤: 值", 標籤依目前的語言; 按下後按鍵文字變為 "Copied" 1.5 秒. 關於視窗每次開啟皆為 600 x 600 並置中, 不記住大小與位置, 最小為 420 x 360; 視窗標題隨語言切換. 建置時間以本機時區顯示為 `YYYY-MM-DD HH:MM:SS`. WebView 版本取自 WebView 的識別字串; macOS 的 WKWebView 所回報的版本固定為 605.1.15, 不反映實際的 WebKit 版本.
- **第三方授權分頁.** 分頁上方為直接引用與間接引用兩張表, 每列為元件名稱與授權種類, 元件名稱連結至其官方網站或原始碼儲存庫, 連結以系統預設瀏覽器開啟. 分頁下方為授權條文, 同種授權只列一次全文, 各元件的著作權聲明分別保留. 內容超出視窗高度時內容區上下捲動, 兩個分頁的切換列固定於視窗頂端. 點選表中的授權種類時, 內容區捲動至對應的條文. 授權條文一律顯示英文原文, 不隨語言設定翻譯. 元件名稱顯示其套件名稱, 例如 `react` 與 `golang.org/x/crypto`. 兩張表內的元件依序為 Go 的相依套件, npm 的相依套件, 其他素材. 判斷授權條文是否相同時, 忽略換行的位置, 引號的寫法與分隔線的長度; 同種授權而條文不同者分別列出全文, 第二份起於名稱後加上編號, 例如 "BSD-3-Clause (2)". 清單的涵蓋範圍與產生方式見 8.6.
- **時間基準.** 所有取樣時刻一律以本機時鐘表示, 不採用遠端時鐘的絕對值. 每次連線收到第一筆取樣時, 記下當時的本機時刻與該筆的 `ts` 作為基準; 之後每筆的取樣時刻等於基準的本機時刻加上該筆 `ts` 與第一筆 `ts` 的差值. 基準在該次連線期間不變, 本機時鐘於連線期間被調整不影響時間軸; 重新連線後重新記錄基準. 曲線圖與記錄檔皆採用此取樣時刻. 各台主機的取樣時刻皆以同一個本機時鐘表示, 故歷史畫面中不同主機的記錄檔可直接對齊, 查閱歷史時可依本機時間尋找.
- **記錄檔.** 使用者每次按下 "連線" 所建立的連線產生一個記錄檔, 於收到第一筆取樣時建立, 連線在此之前失敗時不產生檔案, 該主機的 GPU 張數為 0 時亦不產生檔案. 自動重新連線成功後接續寫入原記錄檔, 並於第一筆取樣之前寫入一筆斷線記錄, 內容為斷線的時刻與原因. 重新連線後 devices 訊息的 GPU 張數或各 GPU 的 `id` 與原記錄檔不同, 或第一筆取樣的時刻早於原記錄檔最後一筆記錄的時刻時, 改為產生另一個檔案. 使用者中斷連線後再次連線時產生另一個檔案. 記錄檔存於作業系統的應用程式資料目錄, 每台主機一個目錄. 連線期間只在檔尾附加, 取樣先進記憶體, 每 5 秒批次附加一次, 程式異常結束最多遺失 5 秒. 判定非預期斷線時與主機轉為未連線時, 各另行附加一次. 記錄檔建立失敗時記錄到日誌, 該次連線不存檔, 畫面照常顯示讀數. 主機轉為未連線狀態後程式不再修改該檔案, 也不自動刪除. 檔內每次連線各有一個時間基準, 各筆記錄的時刻不遞減; 不同記錄檔之間的時刻重疊 (發生於本機時鐘被調回之後) 不需處理. 記錄檔為自訂的二進位附加格式, 定義見 6.4, 不用 SQLite, 避免引入 cgo 相依. 依 6.4 的記錄長度計算, 8 張 GPU 每日約 74 MB, 2 張 GPU 每日約 22 MB, 皆不含程序記錄, 對 SSD 耐寫度可忽略.
- **記錄內容.** 每張 GPU 的數值取樣 (使用率, 記憶體, 溫度, 功耗, 時脈, 風扇, 編解碼) 與取樣時刻, 每筆附帶當時的取樣間隔. 遠端送出的 `error` 訊息連同其時刻一併存入. 程序以程序記錄存入, 程序的組成 (GPU 編號與 PID 的集合) 與上一筆程序記錄不同時寫入一筆, 組成不變時每 60 秒寫入一筆.
- **格式版本.** 記錄檔的檔頭記載格式版本. GUI 保留所有舊版本的讀取能力, 任何版本的記錄檔皆可開啟, 格式變更不影響既有檔案.
- **記憶體.** 記憶體只保留兩種取樣, 一是尚未存檔者, 二是目前顯示中者, 以緊湊的數值陣列儲存, 不以 JSON 物件存放. 顯示範圍加長或歷史畫面捲動時, 再由記錄檔讀取所需範圍. 監看畫面收到新取樣時, 只把新取樣併入目前顯示中的曲線資料, 不重新讀取整段顯示範圍; 顯示範圍為 24 小時且主機有 8 張 GPU 時, 曲線仍須隨每筆取樣更新.
- **讀取記錄檔.** 讀取某時刻的資料時, 以每筆記錄內存的取樣時刻搜尋位置, 不以筆數乘以取樣間隔推算, 故無資料時段與取樣間隔變更皆不影響定位. 檔尾若有寫入未完成的記錄 (發生於程式異常結束), 讀取時略過該筆, 其餘內容照常顯示. 連線中的記錄檔可同時被讀取.
- **記錄檔清單.** 列出所有記錄檔, 依主機分組, 每個檔案顯示起訖時刻與大小, 每台主機另顯示佔用空間的總計. 使用者由此清單選擇檔案開啟於歷史畫面, 也可勾選任意多個檔案刪除, 或一鍵全選; 刪除前跳出確認視窗列出將刪除的檔案數與總大小. 程式不設保留期, 不自動刪除任何記錄檔, 磁碟空間由使用者自行管理. 連線中的記錄檔不可刪除, 清單中以灰色標示並說明原因. 檔案依其說明區所記的主機分組. 無法開啟或格式不符的檔案另列於清單末端, 顯示路徑, 大小與無法開啟的原因, 不計入任何主機的總計, 仍可刪除. 刪除的對象限於記錄檔目錄內副檔名為 `.gpurec` 的一般檔案, 不跟隨符號連結. 每台主機的檔案由新到舊排列. 工具列的檔案總數與總大小不含無法開啟的檔案. "全選" 選取所有檔案, 全部已選時再按一次即取消全選; "開啟" 只作用於可開啟的檔案, "刪除" 只作用於可刪除的檔案, 按鍵上顯示其作用的檔案數. 刪除失敗的檔案以 "Operation Failed" 視窗逐一列出. 清單於進入畫面時與刪除後重新讀取, 不定時更新. 記錄檔的長度少於 1 小時時以分鐘顯示, 少於 48 小時時以小時與分鐘顯示, 其餘以日與小時顯示; 大小以 1024 進位的 KB, MB, GB 顯示.
- **無資料時段.** 曲線不得跨越無資料的時段連成一線. 相鄰兩筆取樣的時刻差大於後一筆所附取樣間隔的 3 倍, 即判定兩筆之間為無資料時段, 兩筆之間有斷線記錄時亦同; 監看畫面與歷史畫面皆適用此規則. 無資料時段在圖上以灰底區塊標示, 曲線在兩側斷開, 滑鼠移到該區塊時顯示起訖時刻與原因; 該時段內有遠端送出的 `error` 訊息時顯示該訊息的英文原文, 該時段內有斷線記錄時顯示其斷線原因, 位於兩個記錄檔之間時顯示未連線, 其餘顯示原因不明. 同一時段內有 `error` 訊息也有斷線記錄時顯示 `error` 訊息, 同類的記錄有多筆時取時刻最早的一筆. 無資料時段的起訖時刻為其前一筆與後一筆取樣的時刻. 無資料時段的來源包括遠端取樣逾時, GUI 收到無法解析的資料行, 以及遠端程式停頓.
- **歷史畫面.** 顯示使用者由記錄檔清單選擇的一個或多個記錄檔. 每個記錄檔為一個分組, 由上而下排列; 分組以一行分組標題起頭, 顯示遠端主機名稱, user@addr 與起訖時刻, 其下為該記錄檔的 GPU 卡片與程序卡片, 版面與監看畫面相同. 記錄檔分組之間的間距大於卡片之間的間距. 分組的程序卡片顯示滑鼠在曲線圖上所指時刻的程序; 滑鼠不在曲線圖上時, 有固定時刻則顯示固定時刻的程序, 否則顯示顯示範圍右緣時刻的程序; 所顯示者為該時刻之前最近一筆程序記錄. 所有分組共用同一個顯示範圍, 時間軸上下對齊, 可左右捲動 (見 "左右捲動"), 捲動範圍由所開啟檔案中最早的開始時刻到最晚的結束時刻. 連線中的記錄檔亦可開啟, 顯示開啟當下已存檔的內容, 開啟後不隨檔案增長而更新. 歷史畫面開啟時顯示捲動範圍的最右端. 縮放時維持不動的時刻見 "顯示範圍". 文字讀數顯示滑鼠於曲線圖上所指時刻的數值; 滑鼠不在曲線圖上時, 有固定時刻則顯示固定時刻的數值, 否則顯示顯示範圍右緣時刻的數值; 所指時刻附近沒有取樣時顯示 "N/A". 程序卡片的標題顯示所示程序記錄的時刻. 各分組依主機排列, 同一台主機的記錄檔由早到晚排列. 記錄檔起訖時刻之外的時段依無資料時段標示. 開啟中的記錄檔被刪除時, 自歷史畫面移除其分組; 讀取失敗的記錄檔顯示以檔名為標題的分組, 其下一張卡片顯示原因, 不影響其他分組.
- **固定時刻.** 點選任一曲線圖即把該時刻設為固定時刻, 整個歷史畫面共用一個. 曲線圖的數值提示最下方以淡色小字說明此操作, 沒有固定時刻時為 "Click to pin this time, drag to move left or right", 已有固定時刻時為 "Click to pin this time instead, drag to move left or right". 固定時刻位於顯示範圍內時, 每張曲線圖在該時刻畫一條主文字色的虛線. 有固定時刻時, 工具列顯示 "Pinned <時刻>" 標籤, 開啟的記錄檔皆在同一天時只顯示時刻, 否則含日期, 標籤上的 ✕ 按鍵清除固定時刻; 未開啟對話框時按 Esc 亦可清除. 變更顯示範圍或捲動使固定時刻離開畫面時, 固定時刻與標籤保留, 讀數與程序卡片照常顯示固定時刻的資料. 離開歷史畫面 (返回記錄檔清單或經側欄切換至其他畫面), 或所開啟的記錄檔改變時, 固定時刻清除. 固定時刻不存入設定檔. 沒有 GPU 的記錄檔, 分組標題之下以一張卡片顯示 "This recording has no GPU.".
- **左右捲動.** 歷史畫面以曲線圖上的平移與慣性捲動, 曲線圖兩側的邊緣自動捲動, 觸控板的橫向滑動, 以及按住 Shift 的滾輪移動顯示範圍. 在曲線圖上按下滑鼠主鍵後移動超過 4 (與裝置無關的像素, 本條下同) 即進入平移, 顯示範圍隨游標的水平位移移動, 曲線跟著游標移動 (往右拖顯示較早的時間), 按住期間游標離開曲線圖仍持續平移; 按下後未移動超過 4 就放開視為點選. 平移結束放開時不設定固定時刻. 放開前約 100 ms 內的水平速度達每秒 300 以上時, 顯示範圍以該速度沿同一方向繼續移動並平順減速, 約 1 秒內停下; 低於此速度則停在放開處. 慣性捲動中在曲線圖上按下即停止, 這一次按下不設定固定時刻; 以其他方式改變顯示範圍或視窗失去焦點時亦停止. 繪圖區上的游標為手形, 平移中為抓取的手形; 平移與慣性捲動中隱藏數值提示, 也不啟動邊緣自動捲動. 邊緣區為每張曲線圖繪圖區內最左側與最右側各 24 (與裝置無關的像素); 游標在邊緣區停留 300 ms 後開始捲動, 右側往較晚的時間, 左側往較早的時間, 速度固定為每秒移動顯示範圍長度的 10%. 游標離開邊緣區或曲線圖, 到達捲動範圍的邊界, 或視窗失去焦點時立即停止. 捲動進行中, 數值提示與讀數照常依游標所指的時刻更新, 點選照常設定固定時刻. 某一側還有資料可捲動時, 歷史畫面的每張曲線圖在該側顯示淡色漸層與箭頭, 該側正在捲動時箭頭改為強調色. 游標位於曲線圖上時, 觸控板的橫向滑動與按住 Shift 的滾輪依滑動距離與繪圖區寬度的比例移動顯示範圍; 未按 Shift 的垂直滾動照常上下捲動內容. 按住 Ctrl 或 ⌘ 的滾輪與觸控板的捏合用於縮放 (見 "顯示範圍"), 不捲動. 處於顯示全部狀態, 或捲動範圍不長於顯示範圍時, 不顯示捲動提示, 也不捲動. 監看畫面的曲線圖沒有上述捲動行為.
- **顯示範圍.** 曲線圖顯示的時間範圍稱為顯示範圍, 其長度由使用者以無段縮放調整, 預設 5 分鐘. 監看畫面的長度為 1 分鐘至 24 小時; 歷史畫面的長度最短 1 分鐘, 最長為捲動範圍的長度, 捲動範圍短於 1 分鐘時即為捲動範圍的長度. 監看畫面的顯示範圍的右緣固定為所顯示主機最新一筆取樣的時刻, 不取系統時鐘, 不可捲動. 顯示範圍內, 該主機先前各次連線的記錄一併顯示於監看畫面, 各次連線之間依無資料時段標示. 監看畫面的所有主機共用一個顯示範圍, 歷史畫面的所有分組共用另一個; 兩者的長度分別記住. 純本機設定, 改變時只重畫, 不通知遠端.
- **縮放.** 縮放的方式如下:
  - **縮放控制項.** 監看畫面與歷史畫面的工具列各有一組縮放控制項, 由左至右為縮小按鍵與放大按鍵, 不顯示長度的數值; 顯示範圍由時間軸兩端的時刻呈現. 縮小按鍵使長度變為兩倍, 放大按鍵使長度變為一半, 結果超出長度範圍時取最接近的邊界; 已達邊界的按鍵停用. 按鍵的滑鼠提示文字於 macOS 為 "Zoom out (⌘ + scroll wheel, or pinch on the trackpad)" 與 "Zoom in (⌘ + scroll wheel, or pinch on the trackpad)", 於 Windows 為 "Zoom out (Ctrl + scroll wheel, or pinch on the touchpad)" 與 "Zoom in (Ctrl + scroll wheel, or pinch on the touchpad)".
  - **滾輪與捏合.** 游標位於曲線圖上時, 按住 Ctrl 的滾輪 (macOS 另可按住 ⌘) 與觸控板的捏合縮放顯示範圍. 滾輪往下 (遠離使用者) 加長, 往上縮短; 每 100 單位的滾動量 (約為滑鼠滾輪一格) 使長度乘以或除以 1.25, 不足 100 單位時依比例連續變化. 滾動量以像素為單位; 以行為單位者每行計 16, 以頁為單位者每頁計繪圖區的高度. 捏合時長度隨兩指的距離成反比變化, 兩指張開為縮短. 結果超出長度範圍時取最接近的邊界. 捏合在 Chromium 核心的 WebView 中以按住 Ctrl 的滾輪事件送出, 在 macOS 的 WKWebView 中可能改以 WebKit 專屬的手勢事件送出, 兩者皆須處理; 於 macOS 觸控板上的行為未實測. 游標不在曲線圖上時, 上述操作不縮放顯示範圍.
  - **縮放時維持不動的時刻.** 監看畫面的右緣維持為最新一筆取樣的時刻, 只改變左緣. 歷史畫面以滾輪或捏合縮放時, 游標所指的時刻維持於游標下方, 捏合事件不帶游標位置時取游標最後所在的位置; 以按鍵縮放時, 畫面中心的時刻維持不變. 縮放後顯示範圍超出捲動範圍時, 平移至捲動範圍內.
  - **顯示全部.** 歷史畫面的 "顯示全部" 按鍵使顯示範圍涵蓋所開啟檔案中最早的開始時刻到最晚的結束時刻, 此狀態下按鍵以強調色的底色, 文字與邊框顯示為選取狀態, 縮小按鍵停用. 以任何方式縮短長度即離開此狀態; 以任何方式把長度加長至捲動範圍的長度即進入此狀態. 此狀態與長度一併記住, 處於此狀態時記住的長度為捲動範圍的長度, 但不短於 1 分鐘. 下次開啟歷史畫面時, 處於此狀態者, 或所記住的長度不短於新的捲動範圍長度者, 皆顯示全部.
  - **控制項的顯示與記住.** 歷史畫面的縮放控制項與 "顯示全部" 按鍵於記錄檔載入後才顯示. 長度改變時畫面立即更新, 停止改變 400 ms 後才寫入設定檔; 寫入失敗時依 "狀態文字與錯誤的顯示" 跳出 "Operation Failed" 視窗, 畫面上的長度維持不變.
- **降採樣.** 顯示範圍內取樣筆數多於像素寬度時, 依像素分桶取最大, 最小與平均, 曲線以平均描繪並以淡色帶顯示最大與最小, 避免尖峰消失. 某個像素範圍內沒有任何取樣時該處留空, 不以前後數值內插.
- 圖表 x 軸以取樣時刻為準, 能處理不等距的取樣點 (間隔被改變後).
- **中斷連線.** 連線中的每台主機皆提供 "中斷連線" 操作. 使用者按下後 GUI 關閉該主機的連線, 遠端 gpumon 隨之結束, 該主機直接轉為未連線狀態, 既有歷史仍可查閱, 不顯示任何視窗; 其他主機的連線不受影響. 之後可按 "連線" 重新監看.
- **斷線處理.** 非預期斷線 (網路中斷, 逾時, 遠端程式自行結束) 時不跳出視窗, 該主機轉為重新連線中狀態, GUI 依第 4 章的規則自動重新連線. GUI 檢查出錯誤而自行斷線時 (例如平台不符, 遠端的協定版本高於 GUI 的協定版本), 顯示明確的錯誤訊息, 不自動重新連線, 錯誤視窗關閉後該主機轉為未連線狀態. 錯誤視窗同一時間只有一個, 視窗已開啟時, 之後檢查出的錯誤附加於其中, 逐台列出. 畫面隨時顯示連線狀態.
- **上傳通知視窗.** 連線流程需要上傳或更新遠端程式時, 於上傳前跳出通知視窗, 規則見第 4 章 "遠端程式的更新". 首次上傳時視窗的標題為 "上傳遠端程式", 更新時為 "更新遠端程式", 視窗的外觀沿用既有對話框的樣式. 視窗內的欄位標籤為 "Location", "Current version" 與 "New version". 視窗不可用 Esc 或點擊視窗外的區域關閉; 按下 Enter 等同按下確認鍵.
- **對話框的顯示順序.** 密碼輸入視窗, 上傳通知視窗, 連線錯誤視窗與 "Operation Failed" 視窗依出現的先後排成一列, 畫面上同一時間只顯示最早出現的一個, 該視窗關閉後才顯示下一個.
- **狀態文字與錯誤的顯示.** 重新連線中的狀態文字為 "Reconnecting, retry n of 5 - 原因", 重試達上限而轉為未連線時為 "Disconnected after 5 retries - 原因". 錯誤視窗中每台主機佔兩行, 上行為依語言設定顯示的錯誤說明, 下行以較小的字顯示後端的英文原文. 連線以外的操作失敗時 (例如設定寫入失敗), 另以標題為 "Operation Failed" 的視窗顯示.
- 每 5 秒送 `ping` 心跳.
- 收到無法解析的行 (例如遠端警告) 記錄到日誌, 不中斷.
- **語言.** 介面語言預設為英文, 不隨作業系統的語言設定變動. 設定頁面提供語言選項, 目前為 English 與繁體中文兩種, 使用者可隨時切換; 切換後立即生效, 不需重新啟動, 並記住選擇. 語言設定涵蓋視窗內的所有文字, 對話框, 系統匣或選單列的選單, 以及 GUI 產生的錯誤訊息. 應用程式名稱 "GPU Monitor" 不翻譯, 遠端程式送出的 `error` 訊息照英文原文顯示, 日期與時間的格式不隨語言變動, 安裝包只有英文. 所有介面文字集中於語言資源檔, 每種語言一個檔案, 程式內不寫死介面文字; 新增語言時增加一個資源檔與一個選項. 某段文字在所選語言的資源檔中沒有對應內容時, 顯示英文.

### 6.3 SSH 認證

- 支援 SSH 金鑰 (含 ssh-agent), 密碼, `~/.ssh/config` 的 Host 設定.
- **金鑰搜尋.** 未指定金鑰檔時依 OpenSSH 慣例順序嘗試本機預設私鑰 (依序為 `~/.ssh/id_rsa`, `id_ecdsa`, `id_ed25519`), 皆不可用時才要求輸入密碼; 密碼不進日誌與錯誤訊息. 主機表單指定的金鑰檔不存在或無法解析時顯示錯誤, 不改用其他金鑰或密碼.
- **認證順序.** 比照 OpenSSH, 依序為 ssh-agent 提供的金鑰, 金鑰檔, keyboard-interactive, 密碼.
- **ssh-agent.** macOS 經 `SSH_AUTH_SOCK` 連線. Windows 經 named pipe `\\.\pipe\openssh-ssh-agent` 連線, 不支援 Pageant (未實測).
- **Host key.** 採 accept-new 語意, 未收錄於 `~/.ssh/known_hosts` 的主機自動寫入, 已收錄但不符者拒絕連線並明確告知使用者. 寫入 `~/.ssh/known_hosts` 失敗時仍允許連線, 與 OpenSSH 相同.
- **逾時.** 建立連線與每一次遠端操作 (執行指令, SFTP 上傳) 皆設逾時上限, 超時視為遠端無回應, 依第 4 章 "連線結束的情形" 處理. 建立連線的上限為 10 秒, 等待使用者輸入密碼的時間不計入, 經跳板主機時每一段各自計時; 執行一個遠端指令的上限為 10 秒; 上傳遠端程式的上限為 60 秒. 自動重新連線時建立連線的上限依第 4 章為 5 秒.
- 不記住密碼, 每次連線由使用者輸入. 密碼不寫入磁碟, 也不存入作業系統的密碼儲存區.
- **密碼的輸入次數.** 一次連線中, 登入密碼遭遠端拒絕時再次要求輸入, 最多要求 3 次, 第 3 次仍遭拒絕即判定為認證失敗. 每一個有密碼保護的金鑰檔, 金鑰密碼錯誤時再次要求輸入, 最多要求 3 次; 輸入視窗留空送出時略過該金鑰. 使用者於輸入視窗按下 "取消" 時中止該次連線, 不顯示錯誤視窗. 自動重新連線不要求輸入, 規則見下一條.
- **密碼的暫留與銷毀.** 主機處於連線中或重新連線中狀態時, 登入密碼暫留於記憶體, 供自動重新連線使用. 主機轉為未連線狀態或程式結束時立即銷毀, 包括自動重新連線達到重試次數上限的情形. 程式自行保管的密碼以位元組陣列存放, 銷毀時以零覆寫 (推斷, 未實測). SSH 函式庫與密碼輸入視窗內的密碼副本無法覆寫, 只能等待記憶體回收, 此為已知且接受的限制.
- **有密碼保護的金鑰.** 金鑰檔有密碼保護且 ssh-agent 未提供該金鑰時, 跳出視窗要求輸入金鑰密碼. 金鑰密碼不寫入磁碟, 也不存入作業系統的密碼儲存區, 解密完成後立即以零覆寫. 解密後的金鑰暫留於記憶體的期間與登入密碼相同, 銷毀時解除引用.
- **`~/.ssh/config` 的取用範圍.** 取用 HostName, User, Port, IdentityFile, ProxyJump, ProxyCommand 六個設定項目, 並依 Include 讀入其他設定檔, 其餘忽略. 設有 ProxyJump 時經由跳板主機連線, 設有 ProxyCommand 時經由該指令建立連線. 兩者皆有設定時以先出現者為準, 值為 `none` 時視為未設定. Match 區塊整段忽略. Include 的相對路徑以設定檔所在的目錄為準, IdentityFile 的相對路徑以本機的家目錄為準. 設定值支援 `%h`, `%p`, `%r`, `%n`, `%d`, `%u`, `%%` 七種代碼. 跳板主機未設定使用者名稱時, 取本機的使用者名稱. ProxyJump 與 ProxyCommand 經由真實的跳板主機連線, 以及兩者於 Windows 的行為, 皆未實測.

### 6.4 記錄檔格式

本節定義 6.2 所述記錄檔的二進位格式, 格式版本為 1.

**通則**

- 多位元組整數一律為 little-endian. 文字一律為 UTF-8.
- 時刻一律為 int64, 數值為 Unix 時間的微秒數, 即自 1970-01-01 00:00:00 UTC 起經過的微秒數, 以本機時鐘為準 (見 6.2 的 "時間基準").
- 檔案由固定區, 說明區, 記錄區三部分依序組成, 三者之間沒有填充位元組.
- 本節的位移皆由 0 起算, 長度與位移的單位皆為位元組.

**存放位置與檔名**

- 記錄檔位於應用程式資料目錄下的 `history/<主機目錄>/`.
- `<主機目錄>` 為該主機的 user@addr, 其中不屬於英文字母, 數字, `.`, `_`, `@`, `-` 的字元逐一換成 `_`. 換算結果為空字串或只由 `.` 組成時不建立記錄檔, 以免路徑超出 `history/`.
- 檔名為 `<YYYYMMDD-HHMMSS>.gpurec`, 日期與時間為 `t_wall_0` (定義見說明區) 換算成本機時區後的值. 同名檔案已存在時, 於 `.gpurec` 之前依序加上 `-2`, `-3`, 直到不重複為止.

**固定區**

固定區位於檔案位移 0, 長度固定為 16.

| 位移 | 長度 | 型別 | 內容 |
|---|---|---|---|
| 0 | 8 | 位元組 | 識別字串, 固定為 ASCII 字元 `GPUMONRC`, 十六進位為 47 50 55 4D 4F 4E 52 43 |
| 8 | 2 | uint16 | 格式版本, 本節所述格式的值為 1 |
| 10 | 2 | uint16 | GPU 張數, 以下稱 N, 等於 devices 訊息 `gpus` 陣列的元素個數 |
| 12 | 4 | uint32 | 說明區的長度, 以下稱 M |

- N 為 0 時不建立記錄檔.
- 讀取時識別字串不符者不是記錄檔, 拒絕開啟. 格式版本為 GUI 不認得的值時拒絕開啟, 並顯示該版本號.

**說明區**

說明區位於檔案位移 16, 長度為 M, 內容為一個 JSON 物件, 結尾不含換行. 成員如下:

| 成員 | JSON 型別 | 內容 |
|---|---|---|
| `host` | 字串 | 該主機的 user@addr, 與主機管理中的值相同 |
| `t_wall_0` | 整數 | 本機收到該檔案第一次連線第一筆 sample 訊息的時刻 |
| `ts_0` | 數值 | 該檔案第一次連線第一筆 sample 訊息的 `ts` 原值 |
| `devices` | 物件 | 該檔案第一次連線收到的 devices 訊息, 所有成員原樣存入 |

範例:

```json
{"host":"alice@10.0.0.5","t_wall_0":1730700000123456,"ts_0":1730700000.123,
 "devices":{"type":"devices","protocol":1,"version":"0.1.0","hostname":"gpu01",
  "gpus":[{"id":0,"vendor":"nvidia","name":"NVIDIA RTX 4090","mem_total":25769803776,"uuid":"GPU-xxxx","power_max_w":600,"clock_gpu_max":2850,"clock_mem_max":10501,
           "pci_vendor":"10de","pci_device":"2684","pci_subsys_vendor":"10de","pci_subsys_device":"165b"}]}}
```

- 每張 GPU 的編號, 廠牌名稱, 型號名稱, 記憶體總量, 序號與四個 PCI 代碼, 皆位於 `devices.gpus` 陣列的各元素內.
- 說明區於建立檔案時寫入一次, 之後不再變動.
- 讀取時略過不認得的成員.

**記錄區**

- 記錄區的起始位移為 `16 + M`, 一路延伸到檔尾.
- 每筆記錄的長度相同, 以下稱 R, `R = 11 + 20 * N`. N 為 2 時 R 為 51.
- 第 k 筆記錄 (k 由 0 起算) 位於檔案位移 `16 + M + k * R`.
- 記錄筆數為 `(檔案長度 - 16 - M)` 除以 R 的商. 餘數不為 0 時, 檔尾的餘數部分為寫入未完成的記錄, 讀取時略過.
- 記錄依寫入的先後排列, 各筆的時刻不遞減. 任何記錄算出的時刻早於前一筆記錄的時刻時, 以前一筆記錄的時刻計.
- 一次附加於寫入中途失敗時, 把檔案截回該次附加之前的長度, 待下次附加時重試, 檔尾不留下不完整的記錄.
- 取樣記錄與錯誤記錄的時刻依所屬連線的時間基準計算, 公式為 `t_base + round((ts - ts_base) * 1000000)`. `t_base` 與 `ts_base` 依序為本機收到該次連線第一筆 sample 訊息的時刻與該筆的 `ts`, `round` 為四捨五入至最接近的整數. 檔案第一次連線的 `t_base` 與 `ts_base` 即說明區的 `t_wall_0` 與 `ts_0`; 自動重新連線後的基準不存入檔案.

每筆記錄的配置如下, 位移為記錄內的位移:

| 位移 | 長度 | 型別 | 內容 |
|---|---|---|---|
| 0 | 1 | uint8 | 種類. 1 為取樣記錄, 2 為錯誤記錄, 3 為接續記錄, 4 為程序記錄, 5 為斷線記錄. 讀取時遇到其他值即略過該筆 |
| 1 | 8 | int64 | 時刻 |
| 9 | 2 | uint16 | 依種類而定 |
| 11 | `20 * N` | 依種類而定 | 依種類而定 |

**取樣記錄 (種類 1)**

本機每收到一筆 sample 訊息, 寫入一筆取樣記錄.

- 時刻依記錄區所定的公式計算, 其中 `ts` 為該筆 sample 訊息的 `ts`.
- 位移 9 為取樣間隔, 單位為毫秒. 其值為 GUI 最近一次收到的 `set_interval` 之 `ack` 訊息的 `ms`; 該次連線尚未收到此種 `ack` 時, 其值為 gpumon 啟動時的取樣間隔, 即 `--interval` 的值, 未指定 `--interval` 時為 1000.
- 位移 11 起為 N 個 GPU 區塊, 每個區塊長度為 20. 第 i 個區塊 (i 由 0 起算) 位於記錄內位移 `11 + 20 * i`, 對應說明區 `devices.gpus` 陣列的第 i 個元素. sample 訊息內的 GPU 以 `id` 與該元素的 `id` 配對.

GPU 區塊的配置如下, 位移為區塊內的位移:

| 位移 | 長度 | 型別 | 來源欄位 | 單位 | 代表無值的數值 |
|---|---|---|---|---|---|
| 0 | 1 | uint8 | `util` | 百分比 | 255 |
| 1 | 1 | uint8 | `fan` | 百分比 | 255 |
| 2 | 1 | uint8 | `enc` | 百分比 | 255 |
| 3 | 1 | uint8 | `dec` | 百分比 | 255 |
| 4 | 2 | int16 | `temp` | 攝氏度 | 32767 |
| 6 | 2 | uint16 | `power_w` | 瓦 | 65535 |
| 8 | 2 | uint16 | `clock_gpu` | MHz | 65535 |
| 10 | 2 | uint16 | `clock_mem` | MHz | 65535 |
| 12 | 8 | uint64 | `mem_used` | 位元組 | 18446744073709551615 |

- 各欄位的數值取自 sample 訊息中該 GPU 的同名欄位.
- 某欄位在 sample 訊息中被省略時, 該欄位存入代表無值的數值. sample 訊息中沒有該 GPU 時, 該區塊的所有欄位皆存入代表無值的數值.
- 數值超出該型別的有效範圍時, 存入最接近的有效值. 有效範圍的上限為代表無值的數值減 1, 下限為該型別的最小值.

**錯誤記錄 (種類 2) 與接續記錄 (種類 3)**

本機每收到一則 error 訊息, 寫入一筆錯誤記錄, 訊息文字放不下時其後緊接一筆或多筆接續記錄. 同一則訊息的所有記錄於同一次附加中寫入, 彼此相鄰.

- 訊息文字為 error 訊息的 `msg`. 其 UTF-8 編碼超過 1024 位元組時, 自結尾逐一刪去整個字元, 直到不超過 1024 位元組為止. 處理後的位元組數以下稱 L.
- 錯誤記錄的時刻依記錄區所定的公式計算, 其中 `ts` 為該則 error 訊息的 `ts`. 位移 9 為 L. 位移 11 起存放訊息文字的前 `20 * N` 個位元組.
- 接續記錄的時刻與所屬錯誤記錄相同. 位移 9 固定為 0. 位移 11 起依序存放訊息文字尚未存放的部分, 每筆 `20 * N` 個位元組.
- 一則訊息所用的記錄總數 (錯誤記錄加接續記錄) 為 L 除以 `20 * N` 後無條件進位的值; L 為 0 時為 1.
- 最後一筆記錄內未用到的位元組填入 0x00.
- 該次連線第一筆 sample 訊息之前收到的 error 訊息不存入記錄檔.

**程序記錄 (種類 4)**

本機依 6.2 "記錄內容" 所定的時機寫入程序記錄, 內容放不下時其後緊接一筆或多筆接續記錄. 同一筆程序記錄的所有記錄於同一次附加中寫入, 彼此相鄰.

- 內容為該筆 sample 訊息內各 GPU 的 `procs` 合併而成的 JSON 陣列, 結尾不含換行. 陣列的每個元素為 `procs` 的一個元素, 另加成員 `gpu`, 其值為該 GPU 的 `id`.
- 內容的 UTF-8 編碼超過 65535 位元組時, 自陣列結尾逐一刪去整個元素, 直到不超過 65535 位元組為止. 處理後的位元組數以下稱 P.
- 程序記錄的時刻與同一筆 sample 訊息的取樣記錄相同, 寫於該取樣記錄之後. 位移 9 為 P. 位移 11 起存放內容的前 `20 * N` 個位元組.
- 接續記錄的時刻與所屬程序記錄相同. 位移 9 固定為 0. 位移 11 起依序存放內容尚未存放的部分, 每筆 `20 * N` 個位元組.
- 一筆程序記錄所用的記錄總數 (程序記錄加接續記錄) 為 P 除以 `20 * N` 後無條件進位的值.
- 最後一筆記錄內未用到的位元組填入 0x00.

**斷線記錄 (種類 5)**

自動重新連線成功並接續寫入原記錄檔時, 本機於該次連線第一筆取樣記錄之前寫入一筆斷線記錄, 原因文字放不下時其後緊接一筆或多筆接續記錄.

- 時刻為本機判定斷線的時刻; 該時刻早於前一筆記錄的時刻時, 以前一筆記錄的時刻計.
- 原因文字為 GUI 判定的斷線原因, 一律為英文. 其截短方式, 位移 9 與位移 11 起的存放方式, 接續記錄的配置與記錄總數的算法, 皆與錯誤記錄相同.

### 6.6 設定檔

本節定義 GUI 所記住的設定的儲存方式. 需記住的項目見 6.1 與 6.2 各條.

**存放位置**

- 應用程式資料目錄於 macOS 為 `~/Library/Application Support/gpumon/`, 於 Windows 為 `%LOCALAPPDATA%\gpumon\`. Windows 不使用隨帳號漫遊的 `%APPDATA%`, 因為記錄檔位於同一目錄且容量大.
- 設定檔為該目錄下的 `settings.json`, 記錄檔位於該目錄下的 `history/` (見 6.4).
- 設定檔的權限為 0600, 應用程式資料目錄的權限為 0700.
- 環境變數 `GPUMON_DATA_DIR` 有值時, 程式以其所指的目錄為應用程式資料目錄. 此功能供測試使用, 使測試不寫入真實的應用程式資料目錄.

**內容**

- 設定檔為一個 JSON 物件, 成員 `version` 為格式版本, 目前的值為 1.
- 頂層成員 `monitor_span_ms` 與 `history_span_ms` 依序為監看畫面與歷史畫面的顯示範圍長度, 單位為毫秒, 預設皆為 300000. 頂層成員 `history_all` 為歷史畫面是否處於顯示全部狀態, 預設為否. 頂層成員 `collapsed_procs` 為程序卡片已收合的主機識別字串陣列. 設定檔不含取樣間隔.
- 設定檔不含登入密碼, 金鑰密碼或任何憑證.
- 曲線的選擇可以為空, 即使用者取消所有曲線.

**主機的識別**

- 比對主機是否相同時, 位址不分大小寫, 使用者名稱區分大小寫, 連接埠不列入比對.
- 位址與使用者名稱不得含 `@` 或空白字元.
- 新增主機時已有相同的主機, 即拒絕新增.
- 主機表單的使用者名稱留空時, 實際的使用者名稱取 `~/.ssh/config` 為該位址設定的 User; 無設定時拒絕儲存, 由表單要求填寫. 畫面顯示的主機名稱, 記錄檔的 `host` 成員與其目錄名稱, 一律為 "實際的使用者名稱@位址". 兩台主機的此名稱相同時視為相同的主機.
- 編輯主機後, 該主機的排列位置維持不變; 編輯使主機的識別改變時, GPU 卡片與程序卡片的收合狀態隨之轉移至新的識別. 刪除主機時一併清除其收合狀態.

**寫入與讀取**

- 寫入時先寫入同一目錄的暫存檔, 再更名取代設定檔, 程式於寫入中途異常結束時不留下內容不完整的設定檔.
- 設定檔不存在時使用預設值.
- 設定檔的內容無法解析時, 把原檔更名為 `settings.json.corrupt-<時間>` 保留, 程式以預設值啟動.
- 設定檔的格式版本高於程式所認得者時, 把原檔更名為 `settings.json.v<版本>-<時間>` 保留, 程式取用其中認得的成員.
- 不認得的成員略過. 型別不符的成員改用預設值, 其餘成員照常取用.
- 設定檔沒有 `monitor_span_ms` 與 `monitor_range`, 而有更早版本同時顯示所用的共用顯示範圍 `shared_range` 時, 以該選項的長度作為監看畫面的長度. 舊版的顯示方式與各主機的顯示範圍讀取時略過, 下次寫入後不再保留. 舊版設定檔中頂層與各主機項目的 `interval_ms` 同樣讀取時略過, 下次寫入後不再保留.
- 設定檔沒有 `monitor_span_ms` 而有舊版以選項表示的監看畫面顯示範圍 `monitor_range` 時, 以該選項的長度作為監看畫面的長度. 設定檔沒有 `history_span_ms` 而有舊版的歷史畫面顯示範圍 `history_range` 時, 同樣換算其長度; 其值為 "all" 時, 歷史畫面處於顯示全部狀態, 長度取預設值. 舊版成員於下次寫入後不再保留.
- 顯示範圍長度與視窗大小超出合法範圍時取最接近的合法值; 歷史畫面的長度於設定檔中只限制為不短於 1 分鐘, 開啟歷史畫面時再依捲動範圍限制. 其他設定的值不合法時改用預設值.

## 8. 建置, 版本與打包

本節做法沿用 ~/myproj/remote 專案的 build.sh, msi/gui.wxs.in 與 internal/version/version.go, .pkg 部分為新增. 8.6 的做法沿用 ~/myproj/cheese 專案 app/ 的 build.sh 與 scripts/gen-licenses.sh.

### 8.1 建置環境

- 全部於 macOS 上建置, 含 Windows 與 Linux 目標, 不需 Windows 或 Linux 機器.
- 單一 Go module, `cmd/cli` 為遠端程式, `cmd/gui` 為本機 GUI; 共用套件放 `internal/`.
- macOS 26 起使用的圖示為 `assets/icon/gpumon.icon`, 由 Icon Composer 建立, 背景為 `#1d5fd1`, 預設與深色外觀相同, 前景為由 `assets/icon/app-foreground.svg` 產生的章魚圖層. `generate.sh` 以 Xcode 26 以上的 actool 將其編譯為 `assets/icon/Assets.car` 並納入版控, 因此只有重新產生圖示時需要 Xcode, 建置腳本不需要. 章魚造型更動時, 須在 Icon Composer 中以新產生的圖層替換並存檔.
- 應用程式圖示由 `assets/icon/app.svg` 產生, 取其 `.icns` 放入 .app, 其 `.ico` 於建置 Windows 執行檔前由建置腳本以獨立的工具 module `scripts/syso` 轉為只含圖示資源的 `cmd/gui/rsrc_windows_amd64.syso` (建置中間檔, 不入版控, 不含 application manifest), 由 Go 連結進執行檔. 圖示以資源 ID 3 存放, Wails 以此作為 Windows 視窗圖示, 檔案總管亦以此顯示執行檔圖示.
- 本機 GUI 執行檔名為 gpumon (Windows 為 gpumon.exe), 應用程式顯示名稱為 "GPU Monitor" (視窗標題, 安裝包的產品名稱, 開始功能表與 .app 名稱皆用此名).
- 遠端程式建置產出名為 gpumon.bin, 由 GUI 內嵌並上傳, 上傳後遠端檔名為 gpumon.
- 建置順序為先建 `linux/amd64` 的 gpumon.bin, 再建 GUI (GUI 以 `go:embed` 嵌入剛建好的 gpumon.bin), 最後打包.
- GUI 的 Windows 目標以 CGO_ENABLED=0 建置, 加 `-H windowsgui` 避免多餘的 console 視窗; macOS 目標需 cgo, 以 CGO_CFLAGS, CGO_LDFLAGS 與 -extldflags 三處統一指定 -mmacosx-version-min.
- 建置腳本須同時相容 bash 與 zsh. 建置腳本只可直接執行, 以 `source` 執行時拒絕建置.
- macOS 的最低版本為 13.0, 即 Go 1.27 的連結器所支援的最舊版本.
- Wails 的命令列工具以 `go.mod` 的 tool 指示釘選, 建置腳本以 `go tool wails3` 執行, 不使用本機另行安裝的版本.
- 建置腳本的選項只有 `--all` 與其簡寫 `-a`. 未傳入時只建置執行檔, 即遠端程式與兩個平台的 GUI 執行檔; 傳入時另建置 8.3 與 8.4 的安裝包.

### 8.2 版本

- 版本單一來源為 `internal/version/version.go` 的常數 `VERSION`, SemVer 形式 x.y.z[-stage.N] (stage 為 alpha, beta 或 rc).
- 程式版號直接編輯該常數, 不另設維護腳本. 其中 x, y, z, N 皆為不補零的十進位整數. 建置腳本於建置前檢查該常數是否符合此格式, 不符合即中止建置.
- Commit hash 與建置時間於建置期以 `-ldflags -X` 注入同一套件的變數; 未經建置腳本時顯示 unknown.
- 完整版本字串為 x.y.z[-stage.N]+<commit>[-dirty], 用於產出檔名與 `--version` 的輸出. `<commit>` 為 commit hash 的前 7 個字元, 未經建置腳本建置時為 `unknown`; 建置時工作目錄有未提交的修改才加上 `-dirty`, 未追蹤的檔案亦視為未提交的修改. MSI Product Version 與 macOS Info.plist 的版本欄位只接受純數字, 另剝除為 x.y.z.
- GUI 與其內嵌的遠端程式注入同一份版本套件, 兩者的程式版號必然相同. 遠端主機上現有的遠端程式可能由其他版本的 GUI 上傳, 其程式版號不一定與本機的 GUI 相同, 處理方式見第 4 章.

### 8.3 Windows 安裝包 (.msi)

- 以 wixl (Homebrew 的 msitools 套件) 於 macOS 編譯, 建置腳本於缺少時自動安裝.
- 來源為 WiX XML 範本 `msi/gui.wxs.in`, 建置腳本以 sed 替換 `@VERSION@` (純數字) 與 `@FULLVERSION@` (完整版本) 後產出 `msi/gui.wxs`, 產出檔不入版控.
- UpgradeCode 為固定 GUID, 寫定後不得變更, 變更即視為另一產品.
- ProductCode 設為 `*`, 每次編譯自動產生新 GUID, 搭配 MajorUpgrade 達成安裝新版自動移除舊版; AllowSameVersionUpgrades 設 yes 允許同版本覆蓋, 降級維持拒絕.
- 安裝範圍 perUser, 不需管理員權限, 安裝目錄為 `%LOCALAPPDATA%\Programs\<廠商>\<產品名>`. 廠商為 Augustus Chen, 產品名為 GPU Monitor.
- REINSTALLMODE 設 amus, 強制重寫所有檔案, 避免升級時無版本檔案被判定不必複製, 隨後又被舊產品移除.
- 於 "新增或移除程式" 顯示的圖示為 `assets/icon/gpumon.ico`, 由 `<Icon>` 元素內嵌並以 ARPPRODUCTICON 指定.
- 含開始功能表與桌面捷徑. 開始功能表的捷徑直接置於程式清單, 不另設資料夾. wixl 不支援 `<UI>` 元素, 無法在安裝過程詢問使用者, 故捷徑不做成可勾選項.
- Windows 需 WebView2 執行期, Windows 10 / 11 內建.
- 安裝包不簽章.

### 8.4 macOS 安裝包 (.pkg)

- 先組 .app bundle (Contents/MacOS 放執行檔, Contents/Resources 放 gpumon.icns 與 Assets.car, Contents/Info.plist 寫入 CFBundleVersion 與 CFBundleShortVersionString, 皆為純數字版本, 以及 LSMinimumSystemVersion, 指向 Assets.car 中圖示的 CFBundleIconName 與指向 gpumon.icns 的 CFBundleIconFile). 兩個鍵與 actool 產生的 Info.plist 片段相同; 各版本 macOS 實際採用哪一份圖示未實測.
- 以 macOS 內建的 `pkgbuild` 將 .app 打成 component package, 安裝目標為 /Applications; 再以 `productbuild` 包成可散布的 .pkg.
- Bundle identifier 為 `io.github.nexgus.gpumon`. .app 於 .pkg 內設為不可重新定位, Installer 固定安裝至 /Applications. .pkg 只可安裝於 arm64 的機器.
- 同名 .app 由 Installer 覆蓋, 達成升級.
- 安裝包與 .app 皆不簽章, 也不送交 Apple 公證.

### 8.5 產出與歸檔

- 產出放 `bin/` (不入版控), 檔名帶完整版本, 例如 `gpumon-<完整版本>-windows-amd64.msi`, `gpumon-<完整版本>-darwin-arm64.pkg` 與 `gpumon-<完整版本>-linux-amd64.bin`.
- 建置前把 `bin/` 內舊版產出依版本段歸檔至 `bin/archive/<版本>/`.
- 每次建置於 `bin/` 建立名為 `gpumon` 的符號連結, 以相對路徑指向該次建置的 macOS 執行檔, 供直接執行最新的建置. 此連結不隨舊產出歸檔, 由下次建置取代.

### 8.6 第三方授權清單

關於視窗的第三方授權分頁 (見 6.2) 所顯示的清單, 涵蓋隨安裝包散布的所有第三方元件, 分為三類:

| 類別 | 範圍 | 直接引用與間接引用的判定 |
|---|---|---|
| Go 的相依套件 | 實際編譯進 GUI 執行檔 (darwin 與 windows 兩個目標) 與內嵌的遠端程式 (linux 目標) 的 module | `go.mod` 的 require 未標為 indirect 者為直接引用, 其餘為間接引用 |
| 前端的 npm 相依套件 | 實際打包進前端產出的套件 | `package.json` 的 dependencies 所列者為直接引用, 其餘為間接引用 |
| 其他素材 | 字型, 圖示等既非 Go module 也非 npm 套件的素材, 由一份人工維護的清單記載 | 一律為直接引用 |

- 授權條文逐字取自各元件的授權檔, 元件附有 NOTICE 檔時一併納入.
- npm 套件未隨附授權檔時, 取專案內 `licenses/npm/<套件名稱>/` 所存的授權條文, 該條文逐字抄自該元件的原始碼儲存庫. 其他素材的清單為 `licenses/other-materials.json`.
- 任一元件找不到授權條文時, 建置中止.
- 清單由腳本產生為前端的資料檔, 該檔納入版本控管.
- 建置腳本每次建置皆重新產生清單, 不設選項. 其他素材的授權條文存於專案內, 產生清單不需網路.
- 清單內容依固定順序排列. 相依套件與其他素材沒有變動時, 重新產生的資料檔與原檔完全相同.

## 9. 測試環境

- 測試主機為 sweetener@10.90.20.55, 用於遠端程式的手動測試與端到端連線測試.
- 該主機的主機名稱為 ai-x-dev, 有 2 張 NVIDIA RTX PRO 6000 Blackwell Workstation Edition (驅動版本 580.178.04) 與 1 張 Intel 內建顯示晶片 (PCI 代碼 8086:a780, i915 驅動), 沒有 AMD 的 GPU.
