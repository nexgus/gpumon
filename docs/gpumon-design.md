# gpumon - 遠端 GPU 監看工具規格

## 1. 目標

做一個可在 **Windows / macOS** 執行的 GUI 應用程式, 透過 **SSH** 連線到一台或多台 Linux 主機, 即時顯示遠端 GPU 的使用率, 記憶體, 溫度, 功耗, 各程序用量等資訊, 呈現方式仿 `nvtop`.

系統需求如下:

- **本機.** Windows (amd64) 或 macOS (arm64).
- **遠端主機.** Linux x86_64, 可用一般使用者帳號以 SSH 登入, 不需要 root.
- **遠端的系統元件.** 遠端必須以 glibc 為 C 函式庫. 不支援以 musl 為 C 函式庫的發行版, 此為設計選擇, 原因見 5.1. 以 musl 為 C 函式庫的發行版包括 Alpine Linux, Chimera Linux, Adélie Linux, OpenWrt, Talos, KISS Linux, 以及 Void Linux 與 Gentoo 的 musl 版本; 完整清單見 musl 官方 wiki 的 [Projects using musl](https://wiki.musl-libc.org/projects-using-musl).
- **遠端的放置路徑.** 遠端程式固定放在家目錄下的 `~/.gpumon/`, 不可變更. 遠端的家目錄必須可寫且可執行.

## 2. 設計原則

以下兩項為最高原則, 優先於本節其餘各條 (第 7 條除外) 與本文件所有章節:

- **使用者友善為最高指導原則.** 所有設計以使用者友善為準, 除非技術上做不到; 以技術上做不到為由放棄友善做法時, 須說明具體原因.
- **設計規格不是聖經.** 本文件任何條目若有錯誤, 或達不到目標, 即推翻之, 不為符合文件而犧牲結果.

其餘原則如下:

1. **不需要 root.** 以一般使用者帳號 SSH 登入即可運作.
2. **遠端不常駐.** 遠端只放一個執行檔, 不安裝服務, 不留背景程序.
3. **遠端不需預先安裝任何工具.** 不依賴 nvtop, nvidia-smi 等, 由本機自動上傳所需程式.
4. **跨廠牌.** 支援 NVIDIA (NVML), AMD (sysfs), Intel (sysfs / fdinfo).
5. **GUI 一律以 200 ms 取樣**, 使用者不需設定取樣間隔. 遠端程式仍可在執行期間調整取樣間隔, 供命令列手動測試使用.
6. **監看不干擾被監看對象.** 不主動改變遠端系統設定 (例如 persistence mode).
7. **不儲存密碼.** 登入密碼與金鑰密碼不寫入磁碟, 也不存入作業系統的密碼儲存區; 暫留於記憶體者於不再需要時立即銷毀. 此項為安全考量, 不因使用者友善原則而放寬.

## 3. 整體架構

```
本機 GUI (Windows / macOS)
  │
  │  一條 SSH 連線, 上面開多個通道
  │
  ├─ SFTP 通道, 檢查與上傳 gpumon 執行檔
  └─ exec 通道, 執行 gpumon --loop
        stdin  ← 本機送指令 (JSON Lines)
        stdout → 遠端送資料 (JSON Lines)
        stderr → 遠端錯誤日誌
```

- 遠端程式 `gpumon` 的生命週期完全綁在 exec 通道上, 通道關閉即結束.
- 每台主機一條 SSH 連線, 一個 gpumon 程序.

## 4. 連線流程

```
1. 建立 SSH 連線 (支援金鑰, 密碼; ~/.ssh/config 只用於查詢 HostName); 以密碼登入後依 6.3 詢問是否設定免密碼登入
2. 執行 `uname -sm`, 不是 Linux x86_64 即顯示錯誤並斷線
3. 取得遠端的程式版號, 內容雜湊值與協定版本, 決定是否上傳遠端程式 (規則見下文 "遠端程式的更新"), 再比對協定版本 (規則見下文 "協定版本的比對"), 不可用即顯示錯誤並斷線
4. 開 exec 通道, 以完整路徑執行 <家目錄>/.gpumon/gpumon --loop, 並以 --interval 傳入 200
5. 讀取第一行 devices 訊息, 其 `protocol` 與步驟 3 所定的協定版本不同即顯示錯誤並斷線
6. 逐行讀取 sample 訊息, 更新畫面
7. 視窗關閉, 使用者中斷連線或斷線 → 關閉通道 → gpumon 結束
8. 非預期斷線時自動重新連線, 重做步驟 1 至 6, 不跳出視窗; 規則見下文 "連線結束的情形"
```

GUI 於遠端執行的指令一律以 `sh -c '<指令>'` 的形式送出, 使其不受遠端帳號的登入 shell 種類影響. 步驟 4 的指令為 `exec <完整路徑> --loop --interval <毫秒>`, 使遠端的 sh 直接由遠端程式取代. 遠端程式未於 stdout 輸出任何內容即以非零的結束碼結束時, 判定為遠端程式無法執行.

**用語**

連線流程有三種不同的比對, 對象與用途皆不同:

| 用語 | 定義 | 取得方式 | 用途 |
|---|---|---|---|
| 程式版號 | 8.2 所定的 x.y.z[-stage.N], 不含 commit 與 dirty 字樣 | GUI 的程式版號為建置時注入的值; 遠端的程式版號由 `--version` 的輸出取得 | 決定是否上傳並覆寫遠端程式 |
| 內容雜湊值 | 遠端程式檔案內容的 SHA-256 雜湊值, 以小寫十六進位表示, 取前 7 個字元 | GUI 的內容雜湊值由其內嵌的遠端程式計算; 遠端的內容雜湊值由 `--version` 的輸出取得, 該值由遠端程式讀取自身的檔案計算 | 程式版號相同時, 決定是否上傳並覆寫遠端程式 |
| 協定版本 | 5.4 devices 訊息的 `protocol`, 為一個整數 | GUI 的協定版本為它所實作的最新協定版本; 遠端的協定版本由 `--version` 的輸出取得, devices 訊息的 `protocol` 為同一個值 | 決定 GUI 能否與該遠端程式溝通 |

同一程式版號的遠端程式於開發期間可能有不同的內容, 故程式版號相同時再比對內容雜湊值. 內容雜湊值只隨遠端程式的檔案內容改變; 只改動 GUI, 前端或文件時, 重新建置的遠端程式內容不變 (建置方式見 8.2), 不會引起更新. GUI 不比對 commit.

**遠端程式的更新 (步驟 3)**

遠端程式的完整路徑為 `<家目錄>/.gpumon/gpumon`, 其中 `<家目錄>` 為遠端帳號家目錄的絕對路徑, 由 GUI 執行 `printf %s "$HOME"` 取得.

GUI 執行 `<完整路徑> --version`, 自輸出取得遠端的程式版號, 內容雜湊值與協定版本, 輸出格式見 5.7. 檔案不存在, 指令的結束碼不為 0, 或輸出不符合格式時, 視為無法取得遠端的程式版號.

遠端的程式版號為 0.3.0 以上, 輸出中程式版號之後為 `+` 與恰好 7 個十六進位字元, 且其後沒有 `-dirty` 時, 該 7 個字元為遠端的內容雜湊值; 其餘情形視為遠端沒有內容雜湊值. 遠端程式自 0.3.0 起輸出內容雜湊值, 更早的版本於該位置輸出 commit hash, 兩者的格式相同, 故以程式版號區分. 程式版號的高低依下文的順序比較, 0.3.0 的 alpha, beta 與 rc 版皆低於 0.3.0.

GUI 依下表決定處理方式:

| 遠端的狀況 | 遠端程式是否正在執行 | 處理方式 |
|---|---|---|
| 無法取得遠端的程式版號 | 不檢查 | 上傳 |
| 遠端的程式版號高於 GUI 的程式版號 | 不檢查 | 不上傳, 使用遠端現有的程式 |
| 遠端的程式版號等於 GUI 的程式版號, 且兩者的內容雜湊值相同 | 不檢查 | 不上傳, 使用遠端現有的程式 |
| 遠端的程式版號等於 GUI 的程式版號, 且兩者的內容雜湊值不同, 或遠端沒有內容雜湊值 | 否 | 上傳並覆寫 |
| 遠端的程式版號等於 GUI 的程式版號, 且兩者的內容雜湊值不同, 或遠端沒有內容雜湊值 | 是 | 不上傳, 使用遠端現有的程式 |
| 遠端的程式版號低於 GUI 的程式版號 | 否 | 上傳並覆寫 |
| 遠端的程式版號低於 GUI 的程式版號 | 是 | 不上傳, 使用遠端現有的程式 |

程式版號的高低依下列順序比較, 前一項相同時才比較下一項:

1. x, y, z 三個數字依序比較, 數字大者為高.
2. 階段由低至高為 alpha, beta, rc, 無階段. 無階段即正式版.
3. 階段後的數字 N, 數字大者為高.

遠端程式是否正在執行, 判斷方式如下:

- GUI 執行 `ls -l /proc/[0-9]*/exe 2>/dev/null`.
- 輸出的任一列中, ` -> ` 之後的文字等於完整路徑, 或等於完整路徑後接 ` (deleted)` 時, 判定為正在執行.
- 此指令只能讀出同一帳號的程序所執行的檔案. 其他帳號的遠端程式位於各自的家目錄, 不在判斷範圍內.

上傳的步驟如下, 任一步驟失敗即顯示錯誤並斷線:

1. `<家目錄>/.gpumon/` 不存在時建立該目錄, 權限為 0700.
2. 以 SFTP 把 GUI 內嵌的遠端程式上傳為同一目錄下的 `gpumon.tmp`, 該檔已存在時覆寫.
3. 把 `gpumon.tmp` 的權限設為 0755.
4. 以 OpenSSH 的 `posix-rename@openssh.com` 擴充把 `gpumon.tmp` 更名為 `gpumon`, 取代既有檔案.

上傳前的確認規則如下:

- 上表的處理方式為上傳, 或為上傳並覆寫時, GUI 於上傳的步驟 1 之前跳出通知視窗, 使用者按下確認鍵後才開始上傳. 處理方式為不上傳時不跳出視窗.
- 通知視窗顯示主機名稱與遠端的放置路徑 `~/.gpumon/gpumon`, 並說明本次為首次上傳或更新. 更新時的說明文字一律為 "{主機} 上的遠端程式與此 GPU Monitor 內附的不同，將予以取代。按下「確認」後開始更新。", 不因版號高低或內容不同而分別.
- 更新時另列出遠端現有的程式版號, 即將上傳的程式版號, 遠端現有的內容雜湊值與即將上傳的內容雜湊值. 程式版號與內容雜湊值分列顯示, 不合併為一個字串.
- 遠端現有的內容雜湊值取自 `--version` 的輸出, GUI 不為此另外執行指令或讀取遠端檔案. 遠端沒有內容雜湊值時 (判定方式見上文), 該欄顯示 `unknown`.
- 通知視窗只有一個確認鍵, 沒有取消鍵.
- 等待使用者確認的時間不計入建立連線與遠端操作的逾時.
- 多台主機同時需要上傳時, 每台主機各一個通知視窗, 依序顯示, 同一時間只顯示一個.
- 自動重新連線時需要上傳者, 同樣跳出通知視窗, 等待使用者確認的時間不計為重試失敗.
- 等待使用者確認期間, 使用者對該主機按下 "中斷連線" 或程式結束時, 該次連線中止, 不上傳, 通知視窗關閉, 不顯示錯誤視窗.
- 等待使用者確認期間, GUI 每 5 秒送出一次 SSH keepalive. 送出失敗或 10 秒內未收到回覆時判定為連線中斷, 通知視窗關閉; 首次連線時依檢查出錯誤而斷線處理, 自動重新連線時計為該次重試失敗.

上傳方式的說明:

- 遠端程式固定放在 `<家目錄>/.gpumon/`, 此路徑不可變更. **不要放 `/tmp`** (可能掛載為 noexec, 且多人共用).
- 先上傳到 `gpumon.tmp` 再更名, 上傳中斷時不會留下內容不完整的 `gpumon`. `gpumon.tmp` 與 `gpumon` 放在同一目錄, 因為 rename 不能跨掛載點.
- 不可直接寫入 `gpumon`. 該檔正在執行時, 直接寫入會失敗, 錯誤為 Text file busy.
- 標準的 SFTP rename 遇目的檔已存在即失敗, 故必須使用 `posix-rename@openssh.com` 擴充.

**協定版本的比對 (步驟 3 與步驟 5)**

步驟 3 決定是否上傳之後, GUI 比對即將使用的遠端程式的協定版本. 步驟 3 有上傳時, 該值為 GUI 自己的協定版本; 沒有上傳時, 該值為 `--version` 輸出的協定版本. 比對在啟動遠端程式之前進行, 結果如下:

| 遠端的協定版本 | 結果 |
|---|---|
| 等於 GUI 的協定版本 | 可用 |
| 低於 GUI 的協定版本 | 可用, GUI 改以遠端的協定版本與遠端程式溝通 |
| 高於 GUI 的協定版本 | 不可用. GUI 顯示錯誤並斷線, 錯誤訊息說明遠端程式較新, 並請使用者更新本機的 GPU Monitor |

步驟 5 讀到的 devices 訊息, 其 `protocol` 必須等於上述的值, 不相等時顯示錯誤並斷線.

協定版本的遞增規則與 GUI 對舊協定版本的處理見 5.4.

**連線結束的情形**

連線結束的情形分為三類, 畫面反應各不相同:

| 類別 | 成因 | 畫面反應 |
|---|---|---|
| 使用者中斷連線 | 使用者對該主機按下 "中斷連線" | 不顯示任何視窗, 該主機直接轉為未連線狀態, 既有歷史仍可查閱 |
| 檢查出錯誤而斷線 | GUI 在連線流程中檢查出錯誤後自行關閉連線, 例如平台不符, 遠端程式上傳失敗, 遠端程式無法執行, 第一行不是 devices 訊息, 遠端的協定版本高於 GUI 的協定版本, devices 訊息的 `protocol` 與 `--version` 輸出的協定版本不同 | 顯示明確的錯誤訊息, 不自動重新連線; 錯誤視窗關閉後該主機轉為未連線狀態, 既有歷史仍可查閱 |
| 非預期斷線 | 網路中斷, 逾時, 遠端程式自行結束 | 不顯示任何視窗, 該主機轉為重新連線中狀態, GUI 自動重新連線 |

使用者按下 "連線" 後, 於收到 devices 訊息之前發生的任何失敗, 包括無法建立 SSH 連線, 認證失敗與逾時, 皆依檢查出錯誤而斷線處理, 不自動重新連線. 非預期斷線只發生於收到 devices 訊息之後.

本機依下列任一情形判定為非預期斷線:

- SSH 連線回報錯誤, 或 exec 通道關閉.
- 連續 15 秒未收到遠端的任何訊息, 即連續 3 次心跳無回應. 此時間與 5.6 的看門狗相同, 本機判定斷線時遠端程式亦已自行結束.

自動重新連線的規則如下:

- 重試以心跳為節奏, 最多 5 次. 判定斷線時立即重試第一次, 之後於每次心跳的時刻重試一次, 即每 5 秒一次.
- 一次重試於 5 秒內未能建立 SSH 連線即計為失敗, 連線建立後至收到 devices 訊息之前逾時亦計為失敗. 等待 devices 訊息的上限為 15 秒, 使用者按下 "連線" 的首次連線亦同. 一次重試超過 5 秒才結束時, 下一次重試順延至其後的第一個心跳時刻. 收到 devices 訊息即為重新連線成功, 重試次數歸零.
- 第 5 次重試失敗後停止重試, 該主機轉為未連線狀態, 側欄顯示斷線原因, 監看畫面的分頁保留 (見 6.2 的 "多主機監看").
- 重新連線中的主機於側欄顯示斷線原因與已重試的次數, 分頁上的狀態圖示同步顯示為重新連線中, 並提供 "中斷連線" 操作; 使用者按下後停止重試, 該主機轉為未連線狀態, 其分頁立即移除.
- 重試時認證失敗, 或檢查出上表第二類的錯誤時, 停止重試, 依檢查出錯誤而斷線處理.
- 重新連線成功後接續寫入原記錄檔, 並寫入一筆斷線記錄, 規則見 6.2 的 "記錄檔". 監看畫面不接續斷線前的曲線, 規則見 6.2 的 "顯示範圍".

## 5. 遠端程式 gpumon 規格

### 5.1 建置

- 語言為 Go, 與 GUI 同一個 Go module, JSON 協定的型別定義只寫一份, 兩端共用.
- NVML 以 purego 於執行期 dlopen 載入, 不使用 cgo. 因 dlopen 需要系統的動態載入器, 執行檔為動態連結 glibc, 只依賴 glibc 所提供的函式庫 (ld-linux, libc.so.6, libdl.so.2 與 libpthread.so.0), 不是完全靜態. 有 NVIDIA 驅動的主機必有 glibc. 不支援 musl 為設計選擇, 只有 AMD 或 Intel GPU 的 musl 主機亦不支援.
- 只建置 `linux/amd64` 一個版本, 內嵌在本機 GUI 的安裝包裡 (`go:embed`), 只能由 GUI 上傳到遠端, 不另行散布.
- 啟動時間需在數十毫秒內.
- 版本取自與 GUI 共用的版本套件 (見第 8 節), GUI 內嵌的遠端程式與該 GUI 的程式版號相同.

### 5.2 資料來源

| 廠牌 | 資料來源 | 說明 |
|---|---|---|
| NVIDIA | NVML (`libnvidia-ml.so.1`) | 用 `dlopen` 動態載入, 找不到就略過. `nvmlInit` 只在啟動時呼叫一次. 可取得所有使用者的程序列表. |
| AMD | `/sys/class/drm/card*/device/` (`gpu_busy_percent`, `mem_info_vram_used`, `mem_info_vram_total`), hwmon (溫度, 功耗, 時脈) | 純讀檔案, 不需初始化. 各程序用量來自 `/proc/*/fdinfo`, 非 root 只看得到自己的程序. |
| Intel | sysfs (`/sys/class/drm/card*/gt/gt*/rps_cur_freq_mhz` 等), `/proc/*/fdinfo` 的 `drm-engine-*` 欄位 | i915 與 xe 驅動欄位不同. 累計值由本機相減算出使用率. 非 root 只看得到自己的程序. |

參考實作為 nvtop 的 `src/extract_gpuinfo_*.c` (GPLv3, 只參考做法, 自行重寫).

### 5.3 NVIDIA 初始化延遲的處理

- 若遠端沒有程序在用 GPU 且未開 persistence mode, `nvmlInit` 可能需要一秒以上.
- 本設計**不處理** persistence mode (需要 root).
- 因為 gpumon 在 SSH 連線期間持續執行, 初始化只發生一次, 之後取樣不再有延遲.
- GUI 在第一次初始化期間顯示 "正在連線" 即可.

### 5.4 通訊協定 (JSON Lines)

**遠端 → 本機 (stdout)**

啟動後第一行:
```json
{"type":"devices","protocol":1,"version":"0.1.0","hostname":"gpu01",
 "gpus":[{"id":0,"vendor":"nvidia","name":"NVIDIA RTX 4090","mem_total":25769803776,"uuid":"GPU-xxxx","power_max_w":600,"clock_gpu_max":2850,"clock_mem_max":10501,
          "pci_vendor":"10de","pci_device":"2684","pci_subsys_vendor":"10de","pci_subsys_device":"165b"}]}
```

之後每個取樣週期一行:
```json
{"type":"sample","ts":1730700000.123,
 "gpus":[{"id":0,"util":87,"mem_used":12884901888,"temp":71,"power_w":312,
          "clock_gpu":2520,"clock_mem":10501,"fan":45,
          "enc":0,"dec":0,
          "procs":[{"pid":4321,"user":"alice","mem":12000000000,"util":80,"cmd":"python train.py"}]}]}
```

其他:
```json
{"type":"ack","cmd":"set_interval","ms":500}
{"type":"error","ts":1730700000.123,"msg":"nvml timeout"}
{"type":"pong"}
```

- `ts` 由遠端打時間戳記. 遠端程式啟動時讀取一次系統時鐘, 之後每筆的 `ts` 等於該讀數加上單調時鐘 (monotonic clock) 量得的經過時間, 故相鄰兩筆 `ts` 的差值不受遠端校時影響, 也不受 SSH 傳輸抖動影響. 本機只取用 `ts` 的差值, 不取用其絕對值, 換算方式見 6.2 的 "時間基準".
- `error` 訊息同樣帶 `ts`, 產生方式與 sample 相同, 供本機把錯誤對應到取樣時刻.
- devices 訊息的 `protocol` 為協定版本, 型別為整數, 目前的值為 1; `version` 為遠端程式的程式版號.
- 協定版本的遞增規則如下. 協定的變更只新增欄位, 訊息種類或指令, 且未實作該變更的程式可以忽略新增的部分時, 協定版本不變; 其他變更一律把協定版本加 1.
- 為使協定版本相同的程式可以互通, 兩端皆忽略訊息內不認得的欄位; 遠端程式收到不認得的 `cmd` 時回 `error` 訊息; 本機收到不認得的 `type` 時記錄到日誌, 不中斷.
- GUI 保留所有舊協定版本的處理能力, 可與協定版本等於或低於自己的遠端程式溝通, 比對規則見第 4 章.
- devices 訊息內每張 GPU 的 `pci_vendor`, `pci_device`, `pci_subsys_vendor`, `pci_subsys_device` 依序為 PCI 的廠商代碼, 產品代碼, 子系統廠商代碼, 子系統產品代碼. 四者的型別皆為字串, 內容為 4 位小寫十六進位數字, 不含 `0x` 前綴, 例如 `"10de"`. 四個值讀自該 GPU 於 sysfs 的 PCI 裝置目錄 (`/sys/class/drm/card*/device/`) 下的 `vendor`, `device`, `subsystem_vendor`, `subsystem_device` 四個檔案, 不需 root; 讀不到時該值為空字串. AMD 的讀取結果為推斷, 未實測. NVIDIA 的 GPU 以 NVML 回報的 PCI 位址讀取 `/sys/bus/pci/devices/<位址>/` 下的同名檔案.
- NVIDIA 的 `mem_used` 不含驅動保留的部分, 與 nvidia-smi 顯示的值一致; `power_max_w` 為目前生效的功耗上限.
- `procs` 的元素中, `cmd` 超過 512 位元組時截斷; `user` 查不到帳號名稱時為 UID 的十進位數字.
- devices 訊息內每張 GPU 的 `power_max_w`, `clock_gpu_max`, `clock_mem_max` 依序為功耗上限 (瓦), GPU 時脈上限 (MHz), 記憶體時脈上限 (MHz), 型別皆為整數, 供 GUI 把功耗與時脈換算為百分比. 取不到的欄位自該 GPU 的物件中省略. NVIDIA 可取得三個值. 測試主機上的 Intel 內建顯示晶片 (i915 驅動) 只可取得 GPU 時脈上限. AMD 的取得方式尚未查證.
- AMD / Intel 的各程序累計值 (engine time) 以原始累計值回傳, 由本機保留上一筆自行相減, 遠端保持無狀態. `procs` 的元素為此另有四個成員, 皆為以引擎名稱為鍵的物件, 值為整數, 取不到時省略: `engines` 為各引擎的累計忙碌時間, 單位為奈秒, 讀自 fdinfo 的 `drm-engine-<引擎>` (i915 與 amdgpu); `engine_capacity` 為各類引擎的數量, 讀自 `drm-engine-capacity-<引擎>`, 省略時為 1; `cycles` 與 `total_cycles` 讀自 xe 驅動的 `drm-cycles-<引擎>` 與 `drm-total-cycles-<引擎>`, 兩者各自的差值相除即為使用率. AMD 與 xe 驅動的讀取結果為推斷, 未實測.
- `procs` 的元素中, `util` 只有 NVIDIA 提供, 為該程序於最近 5 秒內的平均使用率; 最近 5 秒內沒有使用 GPU 的程序, `util` 為 0. 驅動程式只回報此期間內使用率不為零的程序, 此期間內沒有任何取樣時回報 `NVML_ERROR_NOT_FOUND`, 兩者皆視為查詢成功, 未列出的程序使用率為 0. 查詢失敗時該 GPU 的所有程序皆沒有 `util`, 包括 GPU 不支援此查詢 (依 NVML 的說明, 已啟用 MIG 的 GPU 與早於 Maxwell 的產品不支援), 函式庫中沒有此函數, 以及其他錯誤. NVIDIA 的驅動程式每 200 ms 記錄一次使用率, 每次只記在一個程序名下, 查詢的期間過短時, 數值為整張 GPU 的使用率而非該程序所佔的部分. Intel 的 sample 訊息不含整張 GPU 的 `util`, 由本機以各程序的累計值算出.
- 本機計算使用率的方式如下. 一個程序於一個引擎的使用率, 有 `cycles` 與 `total_cycles` 時為 `cycles` 的差值除以 `total_cycles` 的差值與 `engine_capacity` 的乘積, 否則為 `engines` 的差值除以兩筆 `ts` 的差值與 `engine_capacity` 的乘積. 程序的使用率取其各引擎中的最大值. Intel 整張 GPU 的使用率為先逐引擎加總所有程序, 再取最大的引擎, 並限制於 0 至 100. 新出現的程序與累計值變小的引擎不計入; 每次連線的第一筆取樣沒有使用率. AMD 整張 GPU 的使用率仍取遠端送出的 `util`. 監看畫面逐筆沿用此算法; 歷史畫面對所示取樣與前一次取樣的程序列表套用同一算法, 兩次取樣之間有斷線記錄, 程序不在前一次取樣的列表內, 或累計值變小時沒有使用率. 此算法以假資料驗證, 未於有負載的 Intel 或 AMD 主機實測.

sample 訊息內每張 GPU 的數值欄位如下, 數值皆為整數. 取不到的欄位自該 GPU 的物件中省略. `procs` 為程序列表, 不列於此表.

| 欄位 | 意義 | 單位 |
|---|---|---|
| `util` | GPU 使用率 | 百分比 |
| `mem_used` | 已使用的記憶體 | 位元組 |
| `temp` | 溫度 | 攝氏度 |
| `power_w` | 功耗 | 瓦 |
| `clock_gpu` | GPU 時脈 | MHz |
| `clock_mem` | 記憶體時脈 | MHz |
| `fan` | 風扇轉速. NVIDIA 回報的值為驅動設定的目標轉速, 可能超過 100, 照原值回傳 | 百分比 |
| `enc` | 編碼器使用率 | 百分比 |
| `dec` | 解碼器使用率 | 百分比 |

**本機 → 遠端 (stdin)**

```json
{"cmd":"set_interval","ms":500}
{"cmd":"sample_now"}
{"cmd":"set_fields","fields":["util","mem_used"]}
{"cmd":"ping"}
```

- `set_interval` 下限 200 ms, 上限 10 s; 省略 `ms` 時等同 1000, 即回到預設間隔.
- `set_interval` 的 `ms` 超出範圍時回 `error` 訊息, 取樣間隔維持不變.
- `set_fields` 省略 `fields` 時等同回傳全部欄位. 可選取的名稱為上表的數值欄位與 `procs`; `id` 一律輸出. 遠端程式回 `{"type":"ack","cmd":"set_fields","fields":[...]}`, 其 `fields` 為實際套用的欄位. `fields` 含不認得的名稱時回 `error` 訊息, 不套用.
- `ping` 作為心跳 (見 5.6).

**簡寫形式 (僅供手動測試)**

stdin 的每一行依首字元分類, 以 `{` 開頭為 JSON 指令, 以 `/` 開頭為簡寫, 其餘皆為不合法輸入, 回 `error` 訊息而不猜測. 簡寫的指令名與 JSON 的 `cmd` 完全相同, 參數以空白分隔, 不另設別名; 回應一律仍為 JSON, 不因輸入形式改變. GUI 只送 JSON.

| 簡寫 | 等同的 JSON |
|---|---|
| `/set_interval 500` | `{"cmd":"set_interval","ms":500}` |
| `/set_interval` | `{"cmd":"set_interval"}` |
| `/set_fields util mem_used` | `{"cmd":"set_fields","fields":["util","mem_used"]}` |
| `/set_fields` | `{"cmd":"set_fields"}` |
| `/sample_now`, `/ping` | 同名 JSON 指令 |
| `/help` | 簡寫專用, 把可用指令與用法輸出到 stderr, 不進 stdout 的資料流 |

### 5.5 主迴圈

```go
ticker := time.NewTicker(interval)
cmds := make(chan Command)
go readStdin(cmds)          // 獨立 goroutine 讀 stdin, EOF 時關閉 channel

for {
    select {
    case <-ticker.C:
        sample := collect()                   // 在另一個 goroutine 中執行, 帶逾時
        if err := writeLine(sample); err != nil {
            return                            // stdout 寫入失敗 = 本機已斷線
        }
    case cmd, ok := <-cmds:
        if !ok { return }                     // stdin EOF = 本機關閉通道
        handle(cmd)
    case <-sigs:                              // SIGHUP / SIGTERM / SIGINT
        return
    case <-watchdog:                          // 心跳逾時
        return
    }
}
```

細節:
- **啟動後立即取第一筆樣本**, 不等待第一個取樣間隔, 之後才依間隔取樣.
- **stdout 每行後 flush** (管線模式下預設全緩衝).
- **取樣放在另一個 goroutine 並設逾時**, NVML 偶爾會卡住 (例如 GPU 重設中), 逾時就輸出 error 訊息, 不要卡住主迴圈. 逾時為 3 秒. 逾時後才完成的取樣結果捨棄; 取樣尚未完成期間到來的取樣時刻與 `sample_now` 略過, 不重複開始取樣.
- stdin 的空白行不回應, 但視為收到輸入, 重設看門狗. 單行超過 64 KiB 時回 `error` 訊息.
- **不要** 使用 nohup, setsid 或任何讓程序脫離 session 的手段.
- 結束前呼叫 `nvmlShutdown()`.

### 5.6 結束條件 (三道保險 + 看門狗)

| 事件 | 觸發情境 |
|---|---|
| stdin 讀到 EOF | 本機正常關閉通道 |
| stdout 寫入得到 EPIPE | 本機已不再讀取 |
| SIGHUP | sshd 在連線中斷時送出 |
| 看門狗逾時 | 超過 15 秒沒收到任何 stdin 訊息, 即連續 3 次心跳未到 (本機每 5 秒送 `ping`) |

看門狗用來處理網路無聲中斷 (拔網線, 筆電休眠, NAT 逾時). 遠端 sshd 預設 `ClientAliveInterval=0` 不會主動偵測, 沒有看門狗時 gpumon 可能長時間殘留.

### 5.7 命令列介面

| 用法 | 行為 |
|---|---|
| `gpumon` | 手動除錯用. 輸出一行 devices 與一行 sample 後結束 |
| `gpumon --loop` | GUI 使用. 持續取樣, 由 stdin 指令控制, 直到 5.6 的任一結束條件成立 |
| `--interval <ms>` | 取樣間隔, 預設 1000, 範圍與 `set_interval` 相同 (200 至 10000). 兩種模式皆適用, `--loop` 模式下為初始值 |
| `--steps <N>` | 取 N 筆 sample 後結束, 預設 1. 只用於不帶 `--loop` 的模式, 與 `--loop` 併用視為不合法 |
| `--version` | 於 stdout 輸出一行版本資訊後以結束碼 0 結束, 格式見下文 |
| `--help` | 輸出用法說明後結束 |

- 不認得的旗標或不合法的值, 輸出用法說明到 stderr 並以非零碼結束.
- 找不到任何支援的 GPU 時仍輸出 devices 訊息, `gpus` 為空陣列, 不視為錯誤; 由 GUI 顯示此主機沒有可監看的 GPU.
- 結束碼如下. stdin 讀到 EOF 或收到訊號而結束時為 0; stdout 寫入失敗, 看門狗逾時, 或不帶 `--loop` 時最後一筆取樣逾時為 1; 旗標不合法為 2.
- 手動測試 `--loop` 模式時, 可在終端機直接輸入 5.4 的 `/` 簡寫指令, 例如 `/set_interval 500` 或 `/sample_now`, 不必手打 JSON.
- 遠端程式的所有輸出一律使用英文, 包含用法說明, stderr 的日誌與 `error` 訊息的 `msg`.

`--version` 的輸出固定為一行, 以換行字元結尾, stdout 不含其他內容. 格式如下:

```
gpumon <完整版本字串> (protocol <協定版本>)
```

範例:

```
gpumon 0.3.0+9b41c7e (protocol 1)
gpumon 0.4.0-beta.3+9b41c7e (protocol 2)
gpumon 0.3.0 (protocol 1)
```

- 開頭固定為 `gpumon`.
- `<完整版本字串>` 為程式版號後接 `+` 與內容雜湊值, 即 x.y.z[-stage.N]+<內容雜湊值>. 內容雜湊值的定義見第 4 章的 "用語", 由遠端程式於執行 `--version` 時讀取自身的檔案計算; 讀取失敗時不輸出 `+` 與其後的部分, 只輸出程式版號.
- 遠端程式的完整版本字串不含 commit hash 與 `-dirty`. 內容雜湊值放在舊版遠端程式輸出 commit hash 的位置, 長度同為 7 個字元, 使舊版 GUI 仍能解析新版遠端程式的輸出.
- `<協定版本>` 為該遠端程式的協定版本, 以十進位整數表示, 不補零.
- `gpumon`, `<完整版本字串>` 與左括號之間各以一個空白字元分隔; `protocol` 與 `<協定版本>` 之間以一個空白字元分隔.
- 去除結尾的換行字元後, 整行必須符合下列正規表示式. GUI 以此判斷輸出是否符合格式. 舊版遠端程式於 `+` 之後輸出 commit hash 的前 7 個字元, 其後可能有 `-dirty`, 沒有 commit 時輸出 `+unknown`, 正規表示式一併接受:

```
^gpumon (0|[1-9][0-9]*)\.(0|[1-9][0-9]*)\.(0|[1-9][0-9]*)(-(alpha|beta|rc)\.(0|[1-9][0-9]*))?(?:\+([0-9a-f]{7}|unknown)(-dirty)?)? \(protocol ([1-9][0-9]*)\)$
```

## 6. 本機 GUI 規格

### 6.1 技術選擇

- Go + Wails 3 + React + TypeScript. SSH 以 `golang.org/x/crypto/ssh` 實作.
- 目標平台為 Windows (amd64) 與 macOS (arm64).
- Wails 釘選 v3.1.0, 需 Go 1.26 以上.
- GUI 有淺色與深色兩種模式, 視覺規範見 6.5.
- 主視窗首次開啟的大小為 1280 x 800. 程式記住使用者調整後的大小與位置, 下次開啟時還原; 記住的位置已不在任何螢幕的範圍內時, 改以首次開啟的大小顯示於主螢幕中央. 主視窗有最小寬度, 視窗為最小寬度時, 設定頁面每一列的選項在兩種語言下皆位於標題與說明的右側, GPU 卡片的曲線圖位於讀數的右側; 還原記住的視窗大小時, 寬度小於最小寬度即改為最小寬度. 大小指含標題列與邊框的視窗外框. 視窗頂端高 32 的標題列區域與任一螢幕的工作區域重疊達寬 100 (視窗較窄時取視窗的寬度) 且高 16 時, 判定為仍在螢幕的範圍內, 單位為與裝置無關的像素. 視窗處於最小化, 最大化, 全螢幕或隱藏狀態時不記錄大小與位置. 大小與位置於最後一次移動或縮放後 500 ms 寫入設定檔, 程式結束前另寫入一次; 寫入失敗時只記錄到日誌.
- **淺色與深色模式.** 預設跟隨作業系統外觀設定自動切換, 執行中系統切換時即時跟隨, 不需重啟. 設定頁面提供外觀選項, 為跟隨系統, 淺色, 深色三種; 選擇淺色或深色時不再跟隨系統, 並記住選擇. 跟隨系統的做法為純前端, Go 端不參與, 前端啟動時執行下列程式, 偵測結果為深色時在 html 元素加上 dark class, 並監聽系統設定變化:

```ts
function applyColorScheme(matches: boolean): void {
  document.documentElement.classList.toggle("dark", matches);
}
const darkMediaQuery = window.matchMedia("(prefers-color-scheme: dark)");
applyColorScheme(darkMediaQuery.matches);
darkMediaQuery.addEventListener("change", (event: MediaQueryListEvent) => {
  applyColorScheme(event.matches);
});
```

色彩全部定義為前端樣式表 (CSS) 的自訂屬性 (custom property), 本文件稱為色彩變數. 色彩變數的名稱依 CSS 的規定以兩個減號開頭, 例如 `--accent`, 與遠端程式及建置腳本的命令列選項無關. 色彩變數只供前端樣式引用, 不是設定項; 使用者只能以設定頁面的外觀選項切換整組色彩, 不能變更個別色彩. 淺色值寫在 `:root`, 深色值寫在 `html.dark` 下覆寫, 元件與圖表只引用色彩變數, 不寫死顏色; `:root` 另宣告 `color-scheme: light dark`, 使捲軸與表單控件等原生元件一併跟隨. 曲線顏色, 最大最小淡色帶與無資料灰底亦納入色彩變數. 色彩變數的名稱與數值見 6.5. 系統匣圖示不經前端, macOS 用範本圖示 (template icon) 由系統自動配色, Windows 另提供一張深色模式用的圖示, 由 Wails 於系統外觀變更時自動切換. 應用程式圖示為藍色圓角方磚上的白色章魚, 眼睛位於臉部; 系統匣圖示為單色的章魚剪影, 觸手與應用程式圖示相同, 頭部圓頂較大, 眼睛加大並位於圓頂內. macOS 26 的深色圖示樣式下, 應用程式圖示仍為藍底白章魚, 不採用系統自動轉換的深色版 (未實測). 圖示的向量母版與由其產生的衍生圖檔放在 `assets/icon/`, 衍生圖檔由該目錄的 `generate.sh` 產生並納入版控, 母版更動時須重新執行並一併提交. 圖示為自製素材, 不列入第三方授權清單.

### 6.2 功能

- **視窗配置.** 視窗左側為固定側欄, 右側為主區域. 側欄上半為主機清單, 每台主機顯示 user@addr, 連線狀態, 以及 "連線" 或 "中斷連線" 按鍵, 並提供編輯與刪除操作; 清單末端為 "新增主機" 按鍵. 主機依新增的先後排列, 順序不隨連線變動. 側欄下半為 "記錄檔" 與 "設定" 兩個入口, 其下以一條分隔線隔開側欄的最末一行, 該行以等寬字型的淡色小字顯示 `v` 加上完整版本字串 (見 8.2), 例如 `v0.1.0+3f2a9c1`; 該行不可點選, 過長時截斷, 滑鼠停留時顯示完整內容. 主區域顯示監看畫面, 歷史畫面, 記錄檔清單或設定頁面其中之一. 點選側欄中有分頁的主機時, 主區域顯示監看畫面並切換至該主機的分頁; 點選沒有分頁的主機時, 主區域不切換. 按下側欄某台主機的 "連線" 時, 不論主區域當時顯示哪個畫面, 皆切換至監看畫面與該主機的分頁, 讓使用者看到連線進度; 按下 "中斷連線" 時不切換畫面. 點選 "記錄檔" 時一律顯示記錄檔清單的第一層 (見 "記錄檔清單"). 歷史畫面提供返回記錄檔清單的操作. 主區域離開歷史畫面時即關閉該記錄檔, 不論經由返回按鍵或側欄; 再次查看須由記錄檔清單重新開啟.
- **控制項的位置.** 主區域頂端為工具列. 監看畫面的工具列左側為監視中主機的分頁 (見 "多主機監看"), 分頁上帶有該主機的狀態圖示, 右端為縮放控制項, 由左至右為標籤, 縮小按鍵, 範圍長度與放大按鍵 (見 "顯示範圍"); "連線" 與 "中斷連線" 按鍵只位於側欄. 歷史畫面的工具列由左至右為返回記錄檔清單的按鍵, 標題, 固定時刻的標籤 (有固定時刻時才顯示) 與 "顯示全部" 按鍵; 歷史畫面沒有縮放控制項, 放大以選取時段進行, 縮小以 "顯示全部" 按鍵, 滾輪或捏合進行 (見 "縮放"). 歷史畫面的標題依序為所開啟記錄檔的遠端主機名稱, user@addr 與起訖時刻, 同在一行, 過長時先截斷 user@addr 與起訖時刻, 主機名稱維持完整, 工具列不因標題而換行, 滑鼠停留時顯示完整內容; 固定時刻的標籤緊接於標題之後; 記錄檔讀取完成之前標題為 "History", 讀取失敗時標題為該檔案的檔名. 記錄檔清單分為兩層 (見 "記錄檔清單"), 第一層的工具列只有標題, 第二層的工具列由左至右為返回第一層的 "All Hosts" 按鍵與主機名稱, 右端為刪除按鍵; 每個可開啟的檔案於該列右端各有一個 "開啟" 按鍵. 設定頁面由上而下為外觀, 語言, 容量單位與曲線四項, 排列原則為作用範圍大的項目在上, 範圍小的在下. 外觀與語言作用於整個程式, 容量單位作用於監看畫面, 歷史畫面與記錄檔清單的容量數值, 曲線只作用於曲線圖. 每項左側為標題與說明, 右側為選項, 容量單位一項的選項為兩段式切換鍵, 版面與外觀一項相同; 設定頁面的卡片佔滿主區域的寬度, 選項永遠位於標題與說明的右側, 靠卡片右緣對齊; 選擇後立即生效並記住. 曲線一項為縱向排列的勾選清單, 每列依序為勾選框, 曲線顏色與曲線名稱, 說明文字為 "Drawn on the monitor and history screens.". 側欄的每台主機佔三行, 依序為狀態圖示與 user@addr, 狀態文字與斷線原因, 以及 "連線" 或 "中斷連線" 按鍵與編輯, 刪除按鍵.
- **主機表單.** 新增與編輯主機使用同一個表單, 欄位由上至下為位址, 連接埠, 使用者名稱, 金鑰檔與勾選框 "只使用指定的金鑰檔". 位址為必填, 可填主機名稱, IP 位址或 `~/.ssh/config` 的 Host 名稱. 使用者名稱為必填, 留空時於該欄位下方顯示 "請輸入使用者名稱。", 且不儲存. 連接埠留空即為 22. 金鑰檔為選填, 可指定任何位置的檔案, 留空即只用預設名稱的金鑰檔, 規則見 6.3 的 "金鑰檔的來源"; 欄位旁提供選擇檔案的按鍵, 新增表單於欄位下方說明 "密碼於連線時要求輸入。". 勾選框位於金鑰檔欄位 (含瀏覽按鍵與其下方說明) 的正下方, 因為它是金鑰檔的附屬設定; 勾選時 ssh-agent 的金鑰只保留與金鑰檔相同者, 意義同 OpenSSH 的 IdentitiesOnly. 表單不含密碼欄位, 密碼於連線時依 6.3 要求輸入.
- **主機表單的 `~/.ssh/config` 預填.** GPU Monitor 對 `~/.ssh/config` 只作參考, 讀取錯誤不中止任何操作, 也不詢問使用者. 主機表單的位址欄位失去焦點, 且位址不為空並與上次查詢的位址不同時, 讀取該位址 (視為 Host 名稱) 的設定, 填入使用者本次開啟表單以來尚未手動修改的欄位. 連接埠欄位填入 Port; 金鑰檔欄位填入第一個不是 `none` 的 IdentityFile, 展開 `~` 與 % 記號, 相對路徑以家目錄為基準, 結果為絕對路徑; "只使用指定的金鑰檔" 勾選框依 IdentitiesOnly 設定. 設定檔沒有的項目維持原狀. 以瀏覽按鍵選擇的金鑰檔視為手動修改. 新增與編輯表單皆適用; 編輯表單開啟時不查詢, 位址改變才查詢. 查詢結果有警告時 (警告的產生見 6.3 的 "`~/.ssh/config` 的取用範圍"), 表單底部顯示 "~/.ssh/config 有無法解析的內容，已略過該部分。", 位置在錯誤訊息之後, 按鍵之前, 其下以小字逐則列出英文警告. 警告不阻擋儲存. 再次查詢時以新結果取代; 查詢失敗時不顯示.
- **主機管理.** 新增, 編輯與刪除主機. 主機以 "使用者名稱@位址" 識別 (連接埠不是 22 時含連接埠, 見 6.6 "主機的識別"), 同一台主機以不同帳號登入視為不同主機. 連線中或重新連線中的主機不可編輯, 也不可刪除, 須先中斷連線.
- **監看畫面與歷史畫面.** 畫面分為監看畫面與歷史畫面兩種, 前景一次只顯示其中一種, 可隨時切換. 監看畫面顯示主機的即時狀況, 歷史畫面顯示使用者選擇的記錄檔. 前景為歷史畫面時, 連線中的主機在背景繼續取樣與存檔.
- **多主機監看.** 監看畫面以分頁顯示監視中的主機, 一次只顯示一台主機, 分頁的外觀見 6.5 的 "分頁". 監視中指狀態為正在連線, 連線中或重新連線中; 未連線的主機沒有分頁, 只出現在側欄, 因為主機很多時分頁列只須容納正在看的主機. 分頁的順序依側欄的主機順序. 使用者按下側欄的 "中斷連線" 時, 該主機的分頁立即移除. 主機因重試用盡而轉為未連線時 (並非使用者按下 "中斷連線"), 分頁保留; 重新連線時發生不可重試的錯誤, 或連線中的主機直接轉為未連線時亦同. 此種分頁稱為保留分頁, 因為分頁不得在使用者沒有操作時無聲消失; 保留分頁的狀態圖示為未連線, 名稱右側帶有關閉鍵, 按下即移除該分頁, 使用者對該主機按下 "連線" 時分頁轉為正在連線. 使用者按下 "連線" 後分頁立即出現, 不等待連線結果; 連線要求失敗時分頁隨即移除. 新增主機時主區域不切換, 因為新主機尚未連線而沒有分頁. 保留分頁只存在於程式執行期間; 從未連上的主機連線失敗時不保留分頁. 目前分頁被移除時改顯示剩餘分頁中的第一個; 沒有任何分頁時分頁列為空, 內容區只顯示一行說明文字 "No host is being monitored. Use Connect in the sidebar to start monitoring a host.". 分頁之下的內容區由上而下為該主機每張 GPU 的 GPU 卡片, 最後為一張程序卡片, 卡片之間有間距; 監看畫面沒有主機標題列, 不顯示遠端主機名稱 (歷史畫面的工具列標題仍顯示). 連線狀態, 斷線原因與重試次數由側欄與分頁上的狀態圖示提供, "連線" 與 "中斷連線" 只位於側欄. 內容超出視窗高度時, 工具列固定於主區域頂端, 其下的內容區整體上下捲動. 主機有連線中, 重新連線中, 未連線三種狀態. 使用者按下 "連線" 至收到 devices 訊息之前, 狀態顯示為 "正在連線". 未連線的主機不顯示曲線; 重新連線中的主機照常顯示斷線前的讀數與曲線, 顯示範圍的右緣停在最後一筆取樣的時刻. 監看畫面沒有 GPU 卡片時, 內容區只顯示一行說明文字, 不放按鍵. 說明文字依情形為: 保留分頁 (未連線) 時為一行說明, 含斷線原因, 並指引由側欄重新連線; 正在連線時 (按下 "連線" 至收到 devices 訊息之前) "Connecting to this host."; 已連線而尚未收到第一筆取樣時 "Waiting for the first sample."; 沒有可監看的 GPU 時 "This host has no GPU that GPU Monitor can monitor.".
- **每張 GPU 的顯示內容.** GPU 卡片的版面如下, 內容仿 nvtop. 卡片頂端的標題列橫跨整張卡片, 左側為收合箭頭, GPU 編號與完整的型號名稱, 名稱過長時截斷並於滑鼠停留時顯示完整名稱, 右側為曲線圖例, 圖例過長時在標題列內換行. 標題列之下左側為文字讀數, 右側為曲線圖; 曲線圖永遠位於讀數的右側, 不折到讀數下方, 寬度隨視窗變化並填滿讀數右側的空間. 時間軸刻度的數目隨曲線圖的寬度減少, 使刻度文字不互相重疊, 兩端的刻度永遠顯示. 曲線圖的繪圖區頂端對齊讀數頂端, 時間軸刻度底端對齊讀數底端, 繪圖區高度隨之填滿. 文字讀數包括使用率, 記憶體的已使用量, 總量與佔比, 溫度, 風扇轉速, 功耗, GPU 時脈與記憶體時脈, 一律顯示實際數值與單位, 記憶體的單位依容量單位設定. 使用率與記憶體另附橫條, 橫條所代表的百分比位於橫條右端的正上方; 記憶體列因此由左至右為用量與佔比, 佔比與使用率的數值上下對齊, 取整數, 用量以次要文字色顯示. 取不到記憶體總量時不顯示佔比. 功耗在取得功耗上限時一併顯示上限, 取不到的數值顯示 "N/A". 曲線圖的縱軸為 0 至 100, 預設畫使用率與記憶體佔比兩條曲線, 記憶體佔比為已使用量除以總量. 使用者可加選溫度, 風扇轉速, 功耗, GPU 時脈, 記憶體時脈的曲線, 同一張圖的曲線數上限等於曲線顏色的數目, 曲線顏色共 7 種, 定義見 6.5, 每種顏色在淺色與深色背景下皆須可清楚辨識; 此選擇為全域設定, 於設定頁面勾選, 所有主機與歷史畫面共用, 並記住選擇. 加選的曲線中, 溫度以 0 至 100 度對應縱軸全高, 風扇轉速以其百分比對應縱軸, 功耗與時脈以各自的上限 (見 5.4) 為滿刻度. 數值提示與文字讀數仍顯示原值, 不受換算影響. 整個記錄檔內的溫度超過 100 度, 風扇轉速超過 100%, 功耗或時脈超過其上限, 或取不到功耗, 時脈的上限時, 該曲線改以該項數值於整個記錄檔的最大值為滿刻度, 圖例標示滿刻度的實際數值並說明其為記錄檔內的最大值, 曲線不截平. 滿刻度因此不隨捲動與縮放改變, 同一段曲線的高度維持不變. 監看畫面的記錄檔為寫入中的記錄檔, 含自動重新連線之前寫入同一檔的取樣, 滿刻度隨新取樣出現更高的數值而更新. 歷史畫面於整個記錄檔的最大值計算完成之前不畫加選的曲線, 也不列入圖例; 計算失敗時改以顯示範圍內的最大值代替. 多條曲線於畫面上重疊時, 重疊的區段沿曲線分割為等長的色段, 由重疊的曲線依圖例順序輪流上色, 使每條曲線皆看得到; 例如紅, 黃, 綠三條曲線重疊時, 該區段依序為紅黃綠紅黃綠. 兩條曲線於畫面上的垂直距離小於線寬即為重疊, 以畫面上的位置為準, 不以原始數值為準. 只有該區段實際重疊的曲線參與輪流, 其餘曲線照常畫出. 色段的長度固定, 不隨縮放改變; 色段跟隨曲線一起捲動, 同一時刻的區段維持同一顏色. 降採樣時的淡色帶不參與輪流. 取不到記憶體總量時不畫記憶體佔比的曲線. 加選的曲線於顯示範圍內沒有任何數值時不畫, 也不列入圖例. 滑鼠移到曲線圖上時, 顯示該時刻每條曲線的實際數值與單位; 數值提示預設顯示於游標右側, 游標超過曲線圖寬度的 62% 時改顯示於游標左側, 使其不超出曲線圖的邊界. 同一畫面的所有 GPU 曲線圖共用滑鼠所指的時刻 (監看畫面為同一台主機的所有曲線圖, 歷史畫面為該記錄檔的所有曲線圖, 不同畫面之間不共用); 滑鼠移到任一張曲線圖上時, 每張 GPU 曲線圖皆在同一時刻畫出垂直游標與各自的數值提示, 提示的位置規則同上, 依該圖游標的位置決定. 每張圖的游標各自吸附至該 GPU 最接近該時刻的取樣點; 該 GPU 在此時刻沒有取樣點時, 該圖不畫游標也不顯示提示. 該時刻落在該 GPU 的無資料時段時, 滑鼠所在的曲線圖顯示無資料時段的說明, 其餘曲線圖不畫游標也不顯示提示. 歷史畫面數值提示最下方的操作說明行只顯示於滑鼠所在的曲線圖. 任一張曲線圖處於平移或慣性捲動期間, 所有曲線圖皆隱藏游標與數值提示; 滑鼠離開曲線圖後, 所有曲線圖的游標與數值提示皆消失.
- **GPU 卡片的收合.** 每張 GPU 卡片可個別收合, 收合後只留標題列一行, 不顯示讀數, 曲線圖與圖例; 點選該標題即恢復顯示. 收合狀態依主機與 GPU 分別記住, GPU 以 devices 訊息的 `id` 識別, 重新連線與重新啟動程式後維持不變, 監看畫面與歷史畫面共用. 收合只影響顯示, 該 GPU 的取樣與存檔照常進行, 程序卡片照常列出該 GPU 上的程序.
- **程序卡片.** 每台主機一張, 列出該主機所有 GPU 上的程序 (GPU 編號, PID, 使用者, GPU 使用率, 記憶體, 指令), 表格的 GPU 欄以與 GPU 卡片標題相同的 GPU 編號標籤顯示. 欄位依序為 Pin to top, GPU, PID, USER, GPU UTIL, GPU MEM, COMMAND, 排列原則為操作欄 (Pin to top, 見 "程序的置頂") 在最前, 其後識別欄 (GPU, PID, USER) 在前, 用量欄 (GPU UTIL, GPU MEM) 居中, 指令欄在最後; 用量欄的順序與 GPU 卡片文字讀數的順序相同, 先使用率後記憶體. 使用率欄顯示整數與百分比符號, 例如 42%, 靠右對齊; 取不到使用率的程序顯示半形連字號 "-", 以淡色顯示; 使用率為 0 的程序顯示 0%, 兩者不混用, 使 "沒有使用" 與 "不知道" 可一眼區分. 記憶體取不到時顯示 "N/A". 置頂, GPU, PID, 使用者, 使用率, 記憶體六欄的寬度依欄內最寬的內容自動決定, 指令欄取得其餘寬度. 使用者欄的寬度上限為 16 個字元, 超過時以省略號截斷, 滑鼠停留時顯示完整名稱. 指令欄每列只顯示一行. 指令的顯示超出欄寬時, 指令欄的內容可左右捲動, 其餘各欄與欄位名稱列固定不動, 表格寬度不超出卡片; 程序的識別資料與用量因此永遠看得到. 水平捲軸位於指令欄的正下方, 寬度與指令欄相同, 不隨表格上下捲動; 所示的指令皆可完整顯示時, 捲軸不顯示. 各列共用同一個水平捲動位置, 捲動範圍由所示程序中最長的指令決定; 每列捲動至該列指令的結尾即停止, 可完整顯示的指令不移動. 一列指令的顯示在左端或右端被截斷時, 該端顯示省略號, 可完整顯示的一端不顯示省略號, 使用者由省略號即可得知該端尚有內容; 省略號旁不顯示被裁切的殘字. 滑鼠停留於指令時顯示完整指令. 除拖曳捲軸外, 於表格上以觸控板水平捲動或按住 Shift 轉動滾輪亦可捲動指令欄; 上下方向的滾輪仍捲動表格. 所示的程序改變使捲動範圍變小時, 捲動位置自動收回至範圍內; 卡片收合再展開後, 捲動位置維持不變. 指令欄窄到放不下兩端的省略號時, 該列只顯示一個省略號. 水平捲動位置不存入設定檔. 程序卡片展開時佔滿內容區中 GPU 卡片下方剩餘的高度, 卡片底緣貼齊內容區底部, 表格內容區隨卡片伸縮; 主視窗變高或 GPU 卡片收合時, 表格可顯示的列數隨之增加. 表格內容區的最小高度為 5.5 列; 水平捲軸位於表格內容區之下, 其高度永遠預留且不計入 5.5 列, 捲軸出現時各列不移動. GPU 卡片下方剩餘的高度不足時, 表格內容區維持 5.5 列, 內容區整體上下捲動. 卡片高度不隨程序數量改變, 內容區整體的捲軸不因程序增減而出現或消失. 程序超出表格內容區可顯示的列數時, 表格於卡片內上下捲動, 欄位名稱列固定於頂端, 捲軸位於表格右側; 表格右側永遠預留捲軸的寬度, 捲軸出現時各欄不移動. 監看畫面顯示最新一筆. 沒有任何程序時, 表格顯示一列說明文字. 程序列表存入記錄檔 (見 "記錄內容"), 供歷史畫面查閱. 程序卡片可個別收合, 收合後只留標題列一行, 標題文字與展開時相同. 收合狀態依主機分別記住, 重新連線與重新啟動程式後維持不變, 監看畫面與歷史畫面共用; 收合只影響顯示, 取樣與存檔照常進行.
- **程序的排序.** 程序卡片表格由 GPU 至 COMMAND 的六個欄位名稱皆為按鍵, 名稱右側有一個實心三角形; Pin to top 欄的名稱不是按鍵. 列表永遠依其中一欄排序, 預設為 GPU 欄遞增. 按下其他欄位即改以該欄遞增排序, 按下目前排序的欄位即反轉方向. 未依其排序的欄位, 三角形朝下, 顏色與欄位名稱相同而較淡; 目前排序的欄位, 三角形為強調色, 遞增時朝上, 遞減時朝下, 欄位名稱以主文字色的粗體顯示. 數值相同的程序依 GPU 編號, PID 的順序遞增排列. 沒有使用率的程序與記憶體為 "N/A" 的程序, 於各自的排序欄位不論方向皆排在最後. 使用者與指令兩欄的比較不分大小寫. 排序方式依主機分別記住, 重新連線與重新啟動程式後維持不變, 監看畫面與歷史畫面共用.
- **程序的過濾.** 程序卡片可依 GPU, 使用者, 指令三項條件過濾, 程序須符合所有已設定的條件才顯示, 未設定的條件不參與過濾. GPU 條件為一組 GPU 編號. 使用者與指令條件為文字, 出現於內容的任何位置即符合, 不分大小寫, 前後的空白不計. 程序卡片標題列的右端為 "Filter" 按鍵, 按下後開啟過濾視窗; 已設定任一條件時, 此按鍵以強調色顯示. 標題文字之後, 每個已設定的條件顯示一個標籤, 內容為條件名稱與其值, GPU 條件的值為編號由小到大排列; 值超過 24 個字元時截斷, 滑鼠停留時顯示完整的值. 標籤上的 ✕ 按鍵清除該條件. 卡片收合時, 標籤與 "Filter" 按鍵照常顯示並可操作. 標題不顯示符合的程序數. 該主機有程序而沒有任何程序符合條件時, 表格顯示一列說明文字 "No processes match the filter.". 過濾視窗由上而下為 GPU 的勾選框 (每張 GPU 一列, 顯示 GPU 編號標籤與型號名稱), 使用者與指令的輸入欄, 一段說明文字, 以及 "Clear All", "Cancel", "Apply" 三個按鍵. 沒有 GPU 條件時所有勾選框皆為勾選, 全部勾選即為沒有 GPU 條件; 沒有任何勾選時 "Apply" 停用, 勾選框下方顯示 "Select at least one GPU.". "Apply" 與 Enter 套用視窗內的條件並關閉視窗; "Cancel" 與 Esc 關閉視窗而不變更條件; "Clear All" 把視窗內的三項條件恢復為未設定, 不關閉視窗, 按下 "Apply" 後才生效. 已儲存的 GPU 條件中不屬於該主機目前 GPU 的編號, 於套用時捨棄; 已儲存的編號皆不屬於目前的 GPU 時, 視窗開啟時所有勾選框皆為勾選. 過濾條件依主機分別記住, 重新連線與重新啟動程式後維持不變, 監看畫面與歷史畫面共用. 過濾只影響顯示, 取樣與存檔照常進行.
- **程序的置頂.** 表格的第一欄為 "Pin to top", 每列有一個勾選框, 勾選即把該列置頂, 取消勾選即恢復原位. 點選列上任何位置的結果與點選勾選框相同, 即切換該列的置頂, 其他列不變; 修飾鍵不影響結果. 置頂為各列各自開關且長時間保留的狀態, 不是暫時的選取, 故不採用記錄檔清單的修飾鍵規則. 於列上拖曳以反白文字時不切換置頂. 滑鼠移到列上時該列的底色改變, 表示整列可點選. 置頂而不在所示程序之中的列同樣可點選列取消置頂. 此欄的名稱不使用全大寫, 與其餘各欄區別, 且不是排序按鍵, 因為置頂的列已排在最前面. 置頂的列排在未置頂的列之前, 整列以淡強調色為底色; 置頂的列彼此之間, 以及未置頂的列彼此之間, 皆依目前的排序方式排列. 置頂的列隨表格上下捲動, 不固定於欄位名稱列之下. 置頂的列與其他列同樣受過濾條件影響, 被濾除時置頂仍保留, 清除條件後恢復顯示. 置頂的數量不設上限. 置頂以列為單位, 依 GPU 編號, PID 與指令識別; PID 被不同指令的程序重複使用時, 不視為同一列. 置頂只由使用者取消勾選而解除, 程式不自動解除. 置頂的程序不在所示的程序之中時 (監看畫面為最新一筆取樣不含該程序, 歷史畫面為所示的程序列表不含該程序), 該列仍留在置頂的列之中, 維持置頂的底色, 文字改為淡色, 使用者與指令顯示置頂期間最後一次取得的內容, GPU UTIL 與 GPU MEM 兩欄合併顯示一段說明文字. 監看畫面顯示 "Process exited", 因為曾經出現的程序自最新一筆取樣消失即表示已結束; 歷史畫面顯示 "Process not present", 因為所示的時間點可能早於程序啟動, 也可能晚於程序結束. 兩段文字皆含主詞, 以免被讀成使用率的數值; 此處不顯示 "-", 以免與 "不知道使用率" 混淆. 依 GPU UTIL 或 GPU MEM 排序時, 此類列不論方向皆排在置頂的列的最後. 只要有置頂的列可顯示, 表格即不顯示沒有程序的說明文字. 置頂依主機分別記住, 監看畫面與歷史畫面共用, 重新連線後與分頁移除後皆維持不變. 置頂不存入設定檔, 程式結束時全部清除, 因為置頂的對象是執行中的程序, 其存續期間有限.
- **取樣間隔.** 所有主機的取樣間隔固定為 200 ms, 不提供調整. 依 NVIDIA 的 NVML 文件, NVIDIA 回報的使用率為驅動程式於一段取樣期間內的平均值, 期間依產品為 1/6 秒至 1 秒; 200 ms 不短於其中最短的期間. 連線時以 `--interval` 傳入 200, GUI 不送出 `set_interval`. 視窗最小化或切到背景時取樣間隔不變, 該時段的資料照常存入記錄檔.
- **關閉與最小化.** 關閉視窗即結束程式, 所有連線中斷, 遠端 gpumon 隨之結束. 有主機處於連線中或重新連線中狀態時, 關閉前跳出確認視窗, 說明文字一律為 "所有連線將中斷，監看隨之停止。", 選項為 "結束" 與 "取消"; 沒有此種主機時直接結束. 匣圖示選單的 "結束" 適用相同的確認. 最小化時隱藏視窗到 Windows 系統匣或 macOS 選單列, 連線與取樣持續; 點匣圖示顯示視窗, 匣圖示選單提供 "顯示視窗" 與 "結束". 以左鍵點匣圖示顯示視窗, 以右鍵點匣圖示開啟選單; Windows 的匣圖示另有滑鼠提示文字, 重新連線中時顯示另一句. macOS 於最小化後保留 Dock 圖示, 點 Dock 圖示亦顯示視窗. 確認視窗中 Enter 等同 "結束", Esc 等同 "取消". 程式收到終端機的 Ctrl+C 或 SIGTERM 時不經確認直接結束, 結束過程照常中斷連線, 存檔並銷毀密碼. macOS 於有主機連線中時登出或關機, 確認視窗會使系統的登出或關機中止.
- **單一實例.** 同一使用者同時只能執行一個 GUI. 再次啟動 GUI 時不開啟新的視窗, 新啟動的程式直接結束, 原本的程式顯示主視窗並移至最前; 主視窗最小化或隱藏於系統匣或選單列時一併還原, 效果與匣圖示選單的 "顯示視窗" 相同. 以環境變數 `GPUMON_DATA_DIR` 指定不同資料目錄的 GUI 視為不同的程式, 可同時執行. 命令列版不受此限制.
- **主選單.** 程式提供主選單, macOS 顯示於螢幕頂端的選單列, Windows 顯示於主視窗頂端. 選單只含各平台慣例上應有的項目, 不重複視窗內已有的功能. macOS 的選單依序為 GPU Monitor, Edit, Window, Help. GPU Monitor 選單含 "About GPU Monitor", "Settings...", 系統標準的服務與隱藏項目, 以及 "Quit GPU Monitor"; Edit 與 Window 選單只含系統標準項目; Help 選單含 "Third-Party Licenses". Windows 的選單依序為 File 與 Help. File 選單含 "Settings" 與 "Exit"; Help 選單含 "Third-Party Licenses" 與 "About GPU Monitor". macOS 的 "Settings..." 的快速鍵為 Cmd+, , "Quit GPU Monitor" 的快速鍵為 Cmd+Q. 語言為繁體中文時, macOS 系統標準項目的用語依 macOS 的慣例, 例如拷貝與貼上. "Settings" 顯示設定頁面, 與側欄的 "設定" 入口相同. "Quit GPU Monitor" 與 "Exit" 的行為與關閉視窗相同, 適用相同的確認. 選單文字隨語言設定切換. 主選單於 Wails 3.1.0 的行為未實測. Wails v3.0.0-beta.8 於 Windows 深色模式下, 程式還原視窗的大小與位置後, 主選單的項目初次顯示時不繪出 (wails issue #4462), 3.1.0 是否仍發生未查證; 實作時須於 Windows 實機驗證, 仍發生時須在記住視窗大小與位置 (見 6.1) 與 Windows 的主選單之間取捨.
- **關於視窗.** "About GPU Monitor" 與 "Third-Party Licenses" 開啟同一個獨立視窗, 稱為關於視窗. 關於視窗內有 "關於" 與 "第三方授權" 兩個分頁, 皆為資料夾式 (見 6.5 的 "分頁"), 開啟時顯示的分頁由所點選的選單項目決定. 關於視窗首次開啟的大小為 600 x 600, 同一時間只有一個; 視窗已開啟時再次點選選單項目, 只切換分頁並把視窗移至最前. Windows 的關於視窗不顯示主選單. 關於分頁頂端顯示應用程式圖示, 其右為應用程式名稱, 完整版本字串 (見 8.2), 建置時間, Go 版本, 作業系統與其版本, 平台與 WebView 版本; Windows 另顯示 WebView2 執行期的版本. 關於分頁提供 "複製資訊" 按鍵, 把上述資訊以純文字複製到剪貼簿, 第一行為應用程式名稱, 其後每行為 "標籤: 值", 標籤依目前的語言; 按下後按鍵文字變為 "Copied" 1.5 秒. 關於分頁由上而下依序為程式識別 (圖示, 名稱與版本), 環境資訊與其 "複製資訊" 按鍵, 本專案的授權; "複製資訊" 按鍵緊接於環境資訊下方, 授權因篇幅最長且不常查看而置於最末. 授權區顯示專案根目錄 `LICENSE.md` 的全文, 第一段的授權名稱為標題, 其餘依第三方授權分頁的條文排版; 條文一律為英文原文, 不隨語言設定翻譯, 也不列入 "複製資訊" 的內容. 內容超出視窗高度時內容區上下捲動. `LICENSE.md` 於建置時內嵌進前端, 故列為產品路徑 (見 8.2). 關於視窗每次開啟皆為 600 x 600 並置中, 不記住大小與位置, 最小為 420 x 360; 視窗標題隨語言切換. 建置時間以本機時區顯示為 `YYYY-MM-DD HH:MM:SS`. WebView 版本取自 WebView 的識別字串; macOS 的 WKWebView 所回報的版本固定為 605.1.15, 不反映實際的 WebKit 版本.
- **第三方授權分頁.** 分頁上方為直接引用與間接引用兩張表, 每列為元件名稱與授權種類, 元件名稱連結至其官方網站或原始碼儲存庫, 連結以系統預設瀏覽器開啟. 分頁下方為授權條文, 同種授權只列一次全文, 各元件的著作權聲明分別保留. 內容超出視窗高度時內容區上下捲動, 兩個分頁的切換列固定於視窗頂端. 點選表中的授權種類時, 內容區捲動至對應的條文. 授權條文一律顯示英文原文, 不隨語言設定翻譯. 元件名稱顯示其套件名稱, 例如 `react` 與 `golang.org/x/crypto`. 兩張表各自把 Go 的相依套件, npm 的相依套件與其他素材合在一起, 依畫面上顯示的元件名稱排序, 不分大小寫, 名稱只有大小寫不同時再依原字串排序; 名稱開頭的 `@` 照常參與排序, 故 `@` 開頭的 npm 套件排在表首. 授權條文依第一個引用它的元件在表中的順序排列, 直接引用表在前. 判斷授權條文是否相同時, 忽略換行的位置, 引號的寫法與分隔線的長度; 同種授權而條文不同者分別列出全文, 並以條文中 "Neither the name of <機構> nor" 所載的機構名稱區分, 表中的授權種類與條文標題皆於名稱後加上該機構名稱, 例如 "BSD-3-Clause (Google LLC)" 與 "BSD-3-Clause (Google Inc.)"; 只有一份條文的授權不加. 任一份條文沒有這句話, 或兩份所載的機構名稱相同時, 改為第二份起於名稱後加上編號, 例如 "BSD-3-Clause (2)". 清單的涵蓋範圍與產生方式見 8.6.
- **時間基準.** 所有取樣時刻一律以本機時鐘表示, 不採用遠端時鐘的絕對值. 每次連線收到第一筆取樣時, 記下當時的本機時刻與該筆的 `ts` 作為基準; 之後每筆的取樣時刻等於基準的本機時刻加上該筆 `ts` 與第一筆 `ts` 的差值. 基準在該次連線期間不變, 本機時鐘於連線期間被調整不影響時間軸; 重新連線後重新記錄基準. 曲線圖與記錄檔皆採用此取樣時刻. 各台主機的取樣時刻皆以同一個本機時鐘表示, 故歷史畫面中不同主機的記錄檔可直接對齊, 查閱歷史時可依本機時間尋找.
- **記錄檔.** 使用者每次按下 "連線" 所建立的連線產生一個記錄檔, 於收到第一筆取樣時建立, 連線在此之前失敗時不產生檔案, 該主機的 GPU 張數為 0 時亦不產生檔案. 自動重新連線成功後接續寫入原記錄檔, 並於第一筆取樣之前寫入一筆斷線記錄, 內容為斷線的時刻與原因. 重新連線後 devices 訊息的 GPU 張數或各 GPU 的 `id` 與原記錄檔不同, 或第一筆取樣的時刻早於原記錄檔最後一筆記錄的時刻時, 改為產生另一個檔案. 使用者中斷連線後再次連線時產生另一個檔案. 記錄檔存於作業系統的應用程式資料目錄, 每台主機一個目錄. 連線期間只在檔尾附加, 取樣先進記憶體, 每 5 秒批次附加一次, 程式異常結束最多遺失 5 秒. 判定非預期斷線時與主機轉為未連線時, 各另行附加一次. 記錄檔建立失敗時記錄到日誌, 該次連線不存檔, 畫面照常顯示讀數. 主機轉為未連線狀態後程式不再修改該檔案, 也不自動刪除. 檔內每次連線各有一個時間基準, 各筆記錄的時刻不遞減; 不同記錄檔之間的時刻重疊 (發生於本機時鐘被調回之後) 不需處理. 記錄檔為自訂的二進位附加格式 (見 6.4), 不用 SQLite, 避免引入 cgo 相依.
- **記錄內容.** 每張 GPU 的數值取樣 (使用率, 記憶體, 溫度, 功耗, 時脈, 風扇, 編解碼) 與取樣時刻, 每筆附帶當時的取樣間隔. 遠端送出的 `error` 訊息連同其時刻一併存入, 該次連線第一筆取樣之前收到者不存入. 每筆取樣的 GPU 程序列表皆存入, 只存與前一次取樣不同的程序與欄位, 讀取時依序套用差異還原.
- **格式版本.** 記錄檔的檔頭記載格式版本. GUI 保留所有舊版本的讀取能力, 任何版本的記錄檔皆可開啟, 格式變更不影響既有檔案.
- **記憶體.** 記憶體只保留兩種取樣, 一是尚未存檔者, 二是目前顯示中者, 以緊湊的數值陣列儲存, 不以 JSON 物件存放. 顯示範圍加長或歷史畫面捲動時, 再由記錄檔讀取所需範圍. 監看畫面收到新取樣時, 只把新取樣併入目前顯示中的曲線資料, 不重新讀取整段顯示範圍; 顯示範圍為 24 小時且主機有 8 張 GPU 時, 曲線仍須隨每筆取樣更新.
- **讀取記錄檔.** 讀取某時刻的資料時, 以每筆記錄內存的取樣時刻搜尋位置, 不以筆數乘以取樣間隔推算, 故無資料時段與取樣間隔變更皆不影響定位. 檔尾若有寫入未完成的記錄 (發生於程式異常結束), 讀取時略過該筆, 其餘內容照常顯示. 連線中的記錄檔可同時被讀取.
- **記錄檔清單.** 記錄檔清單分為兩層, 先選擇主機, 再管理該主機的檔案, 因為第一層可一次看到每台主機的檔案數與總大小, 主機很多時亦容易尋找. 第一層為主機清單, 工具列只有標題; 每台有記錄檔的主機一列, 由左至右為主機, 已選取數 (有選取時才顯示), 檔案數, 總大小與向右箭頭, 整列可點選; 最後一列為 "Files that cannot be opened"; 第一層沒有方框與刪除按鍵. 第二層為該主機的檔案清單, 工具列由左至右為返回第一層的 "All Hosts" 按鍵, 主機名稱, 右端為刪除按鍵. 一次只顯示並管理一台主機的檔案, 選取與刪除皆只作用於目前所在的主機, 使用者因此不會刪除不在畫面上的其他主機的檔案. 工具列之下為一列標題列與該主機的檔案, 標題列由左至右為主機分組方框, 主機名稱, 該主機的檔案數與總大小; 每個檔案顯示起訖時刻與大小. 某台主機有選取的檔案時, 第一層該主機的列顯示其已選取數, 其他主機是否留有選取因此不必進入即可得知. 由側欄點選 "記錄檔" 進入記錄檔清單時一律顯示第一層; 由歷史畫面返回時回到所開啟檔案之主機的第二層, 還原行為見 "記錄檔的選取". 進入第二層時內容區捲回頂端, 由歷史畫面返回者除外; 返回第一層時第一層亦捲回頂端. 進入 "Files that cannot be opened" 時, 工具列的主機名稱位置顯示該文字. 清單重新讀取而目前所在的主機已無檔案時, 回到第一層. 使用者按下某列的 "開啟" 按鍵即於歷史畫面開啟該檔案, 一次只開啟一個檔案; 無法開啟的檔案沒有 "開啟" 按鍵. 使用者選取任意多個檔案後可一次刪除, 選取的規則見 "記錄檔的選取"; 刪除前跳出確認視窗, 見 "刪除確認視窗". 程式不設保留期, 不自動刪除任何記錄檔, 磁碟空間由使用者自行管理. 連線中的記錄檔不可刪除, 清單中以灰色標示並說明原因. 檔案依記錄檔內記載的主機識別歸類. 無法開啟或格式不符的檔案另列於第一層的最後一列 "Files that cannot be opened", 進入後顯示路徑, 大小與無法開啟的原因, 不計入任何主機的總計, 仍可刪除. 刪除的對象限於記錄檔目錄內副檔名為 `.gpurec` 的一般檔案, 不跟隨符號連結. 每台主機的檔案由新到舊排列. 主機分組方框的規則見 "記錄檔的選取"; "刪除" 只作用於目前所在的主機選取的檔案中可刪除者, 按鍵上顯示其作用的檔案數. 刪除失敗的檔案以 "Operation Failed" 視窗逐一列出. 清單於進入畫面時與刪除後重新讀取, 不定時更新. 記錄檔的長度少於 1 小時時以分鐘顯示, 少於 48 小時時以小時與分鐘顯示, 其餘以日與小時顯示; 大小依容量單位設定顯示.
- **記錄檔的選取.** 記錄檔清單的每一列只有選取與未選取兩種狀態, 清單不另設其他標示. 選取的列整列為淡藍底色 (色彩變數 `--accent-soft`), 列左端的方框打勾. 選取採用檔案管理程式慣用的規則. 所有選取操作只作用於目前所在的主機的檔案, 其他主機的選取不變, 返回第一層或進入其他主機亦不清除選取. 點選列上方框範圍與 "開啟" 按鍵以外的任何位置, 即只選取該列, 其他列取消選取; 該列已選取時維持選取. 按住 Ctrl (macOS 為 Command) 點選列, 切換該列的選取, 其他列不變. 按住 Shift 點選列, 選取起點列至該列之間的所有列, 取代原有選取; 同時按住 Ctrl (macOS 為 Command) 與 Shift 時, 該範圍加入原有選取. 點選方框只切換該列的選取, 不影響其他列; 按住 Shift 點選方框時, 起點列至該列之間的所有列加入選取. 起點列為最近一次未按 Shift 而點選的列; 沒有起點列, 或起點列已不在清單中時, Shift 不起作用. 範圍依畫面由上而下的順序計算, 限於目前所在的主機; 起點列不屬於目前所在的主機時視為沒有起點列. 按住 Shift 點選時不反白列上的文字. 不按修飾鍵的多選以方框進行, 修飾鍵為輔助途徑. 方框範圍為列的左緣至起訖時刻文字之前, 高度為整列, 點選此範圍內任何位置等同點選方框; 滑鼠移入此範圍時方框周圍顯示底色. 標題列的左端有一個方框, 稱為主機分組方框, 有空白, 橫線, 打勾三種外觀, 分別表示該主機的檔案沒有任何選取, 部分選取, 全部選取; 進入 "Files that cannot be opened" 後的標題列亦有方框. 點選主機分組方框時, 該主機的檔案全部已選則全部取消, 否則全部選取, 其他主機的選取不變, 起點列亦不變. 主機分組方框與各列的方框上下對齊, 可點選的範圍與各列相同. 清單不提供跨主機選取或刪除的操作. 日後新增可選取多列的表格時, 選取為暫時且用於指定操作對象者依本條, 各列各自開關且保留的狀態依 "程序的置頂". 按下某列的 "開啟" 按鍵等同先點選該列再開啟, 故由歷史畫面回到記錄檔清單時, 所開啟的檔案為該主機的檔案中唯一選取的列, 是否取消選取由使用者決定. 連線中的記錄檔與無法開啟的檔案皆可選取. 選取與清單的捲動位置於離開記錄檔清單 (開啟檔案, 或經側欄切換至其他畫面) 後保留, 再次進入時還原; 由歷史畫面返回第二層時, 清單的捲動位置同樣還原. 兩者只保留於程式執行期間, 不存入設定檔. 清單重新讀取時, 已不存在的檔案自選取中移除. 由歷史畫面返回第二層時, 若目前所在的主機只有一列為選取, 該列不在可視範圍內時捲入可視範圍, 鍵盤焦點位於該列的 "開啟" 按鍵; 該列沒有 "開啟" 按鍵, 或選取的列不是恰好一列時, 不移動鍵盤焦點.
- **刪除確認視窗.** 按下 "刪除" 時跳出確認視窗, 由上而下為標題, 將刪除的檔案清單, 說明文字與按鍵. 標題為將刪除的檔案數, 說明文字為將釋出的總大小與刪除後無法復原. 檔案清單只列出將刪除的檔案, 不含選取中不可刪除者. 檔案皆屬於目前所在的主機, 清單上方為該主機的名稱, 檔案的順序與記錄檔清單相同; 每個檔案一列, 顯示起訖時刻與大小. 目前所在的是 "Files that cannot be opened" 時, 清單上方為 "Files that cannot be opened", 每列顯示路徑與大小, 路徑與記錄檔清單所顯示者相同, 過長時換行. 檔案清單的高度有上限, 超過時於清單內捲動, 視窗的其餘部分不隨之捲動.
- **無資料時段.** 曲線不得跨越無資料的時段連成一線. 相鄰兩筆取樣的時刻差大於後一筆所附取樣間隔的 3 倍, 即判定兩筆之間為無資料時段, 兩筆之間有斷線記錄時亦同; 監看畫面與歷史畫面皆適用此規則. 無資料時段在圖上以灰底區塊標示, 曲線在兩側斷開, 滑鼠移到該區塊時顯示起訖時刻與原因; 該時段內有遠端送出的 `error` 訊息時顯示該訊息的英文原文, 該時段內有斷線記錄時顯示其斷線原因, 位於記錄檔的起訖之外時顯示未連線, 其餘顯示原因不明. 同一時段內有 `error` 訊息也有斷線記錄時顯示 `error` 訊息, 同類的記錄有多筆時取時刻最早的一筆. 無資料時段的起訖時刻為其前一筆與後一筆取樣的時刻. 無資料時段的來源包括遠端取樣逾時, GUI 收到無法解析的資料行, 以及遠端程式停頓.
- **歷史畫面.** 顯示使用者由記錄檔清單開啟的一個記錄檔. 遠端主機名稱, user@addr 與起訖時刻顯示於工具列的標題 (見 "控制項的位置"), 內容區由上而下為最大值卡片 (見 "最大值卡片"), 該記錄檔的 GPU 卡片與程序卡片, 排列原則為涵蓋範圍大者在上, 最大值卡片涵蓋整個記錄檔, GPU 卡片涵蓋顯示範圍, 程序卡片涵蓋單一時刻. GPU 卡片與程序卡片的版面與監看畫面相同. 程序卡片顯示滑鼠在曲線圖上所指時刻的程序; 滑鼠不在曲線圖上時, 有固定時刻則顯示固定時刻的程序, 否則顯示顯示範圍右緣時刻的程序; 所顯示者為該時刻之前最近一次取樣的程序列表. 其中 Intel 與 AMD 程序的使用率, 以該次取樣與前一次取樣的程序列表的累計值相減算出, 算法與監看畫面相同; 沒有前一次取樣, 兩次取樣之間有斷線記錄, 程序不在前一次取樣的列表內, 或累計值變小時, 沒有使用率. 所有曲線圖共用同一個顯示範圍, 時間軸上下對齊, 可左右捲動 (見 "左右捲動"), 捲動範圍為該記錄檔的開始時刻到結束時刻. 連線中的記錄檔亦可開啟, 顯示開啟當下已存檔的內容, 開啟後不隨檔案增長而更新. 歷史畫面開啟時顯示捲動範圍的最右端. 縮放時維持不動的時刻見 "顯示範圍". 每張 GPU 卡片的文字讀數皆顯示共用的滑鼠所指時刻的數值, 滑鼠移到任一張曲線圖上時所有卡片同步更新; 滑鼠不在曲線圖上時, 有固定時刻則顯示固定時刻的數值, 否則顯示顯示範圍右緣時刻的數值; 所指時刻附近沒有取樣時顯示 "N/A". 固定時刻的數值取時刻不晚於固定時刻的最近一筆取樣的實際數值, 不取降採樣後的平均值, 此筆取樣與程序卡片所示的程序列表屬於同一次取樣; 該筆取樣早於固定時刻的時間超過其所附取樣間隔的 2 倍, 或兩者之間有斷線記錄時顯示 "N/A"; 查詢完成之前維持前一個畫面的讀數. 滑鼠所指時刻與顯示範圍右緣時刻的數值, 於降採樣時為該點的平均值. 程序卡片的標題顯示所示程序列表的取樣時刻. 記錄檔起訖時刻之外的時段依無資料時段標示. 記錄檔讀取失敗時, 工具列的標題為該檔案的檔名, 內容區以一張卡片顯示原因.
- **固定時刻.** 點選任一曲線圖即把該時刻設為固定時刻, 整個歷史畫面共用一個. 曲線圖的數值提示最下方以淡色小字說明此操作, 沒有固定時刻時為 "Click to pin this time; drag to zoom in to a time range; hold Shift and drag to move left or right", 已有固定時刻時為 "Click to pin this time instead; drag to zoom in to a time range; hold Shift and drag to move left or right"; 說明過長時於數值提示內換行. 固定時刻位於顯示範圍內時, 每張曲線圖在該時刻畫一條主文字色的虛線. 有固定時刻時, 工具列顯示 "Pinned <時刻>" 標籤, 記錄檔的起訖時刻在同一天時只顯示時刻, 否則含日期, 標籤上的 ✕ 按鍵清除固定時刻; 未開啟對話框時按 Esc 亦可清除. ✕ 以主文字色顯示, 大小須一眼可見, 滑鼠停留時有圓形底色, 標籤不使工具列變高. 變更顯示範圍或捲動使固定時刻離開畫面時, 固定時刻與標籤保留, 讀數與程序卡片照常顯示固定時刻的資料. 離開歷史畫面 (返回記錄檔清單或經側欄切換至其他畫面) 時, 固定時刻隨記錄檔關閉而清除. 固定時刻不存入設定檔. 沒有 GPU 的記錄檔, 內容區以一張卡片顯示 "This recording has no GPU.".
- **最大值卡片.** 歷史畫面列出整個記錄檔中每張 GPU 每項數值的最大值, 使用者不必自行於曲線圖上尋找. 卡片的外觀與程序卡片相同, 標題為 "Maximum over the whole recording", 可收合, 收合狀態依主機記住; 沒有 GPU 的記錄檔不顯示此卡片. 表格每張 GPU 一列, 欄位由左至右為 GPU, 使用率, 記憶體, 溫度, 風扇轉速, 功耗, GPU 時脈, 記憶體時脈, 順序與欄名皆與 GPU 卡片的文字讀數相同, GPU 欄以 GPU 編號標籤顯示. 數值的格式, 取整與單位與文字讀數相同, 靠右對齊; 記憶體顯示用量與佔比, 佔比以次要文字色顯示, 取不到記憶體總量時不顯示佔比; 功耗不含上限. 最大值的範圍一律為整個記錄檔, 於開啟記錄檔時計算一次, 不隨顯示範圍, 滑鼠位置與固定時刻變動. 某項數值於整個記錄檔皆取不到時, 該格顯示淡色的 "N/A", 不可點選; 計算完成之前數值格留空, 計算失敗時各格顯示 "N/A". 視窗變窄而表格放不下時, 表格於卡片內左右捲動, 卡片不超出內容區. 監看畫面沒有此卡片.
- **最大值的選取.** 某項數值等於其最大值的一段連續取樣稱為一處出現處; 數值改變, 取不到數值, 或兩筆取樣之間有斷線記錄時, 出現處即結束. 一處的時刻為其第一筆取樣的時刻. 最大值卡片的每個數值皆為按鍵, 滑鼠停留時底色改變, 並提示其出現的時刻, 只有一處時為 "Occurred at <時刻>", 多處時為 "First occurred at <時刻>, <n> occurrences". 未選取時, 標題列右側以次要文字色顯示操作說明 "Click a value to pin the time it occurred". 點選數值即選取該格, 整個歷史畫面至多選取一格; 固定時刻隨即設為第 1 處的時刻, 文字讀數與程序卡片顯示該時刻的資料, 讀數中該項的數值等於所點選的最大值. 選取的格以固定時刻標籤的底色 (色彩變數 `--accent-soft`) 與粗體顯示, 使兩者在視覺上相連. 選取後標題列右側改為選取狀態, 多處時為 "<GPU 編號> <項目> max <數值>, occurrence <i> of <n>", 其後為 "‹" 與 "›" 兩個按鍵, 用於前往上一處與下一處, 位於第 1 處時 "‹" 停用, 位於最後一處時 "›" 停用; 只有一處時為 "<GPU 編號> <項目> max <數值>, occurs once", 不顯示兩個按鍵; 文字過長時以省略號截斷, 兩個按鍵維持完整. 卡片收合時標題列右側的文字與按鍵照常顯示. 點選另一格即改選該格, 點選已選取的格則回到第 1 處. 由最大值卡片設定固定時刻時, 顯示範圍的長度不變, 平移至固定時刻位於曲線圖正中央, 到達捲動範圍的邊界時停在邊界; 處於顯示全部狀態時不平移. 以曲線圖點選設定固定時刻時不平移. 有選取的格時, 該格所屬 GPU 的曲線圖沿繪圖區頂端以主文字色的短橫條標出該項位於顯示範圍內的所有出現處, 橫條由該處第一筆取樣畫到最後一筆取樣, 過短時加寬至可辨識的寬度; 橫條不使用曲線色與強調色, 以免與曲線混淆, 該卡片的圖例最後加一項 "<項目> max occurrences" 說明橫條. 該項未被選為曲線時橫條照常顯示, 該 GPU 卡片收合時不顯示. 清除固定時刻 (✕ 或 Esc), 以曲線圖點選改設固定時刻, 或離開歷史畫面時, 選取隨之解除, 橫條與圖例項消失, 標題列右側恢復操作說明. 選取不存入設定檔.
- **左右捲動.** 歷史畫面以曲線圖上按住 Shift 的拖曳平移與慣性捲動, 曲線圖兩側的邊緣自動捲動, 觸控板的橫向滑動, 以及按住 Shift 的滾輪移動顯示範圍. 按住 Shift 並在曲線圖上按下滑鼠主鍵後移動超過 4 (與裝置無關的像素, 本條下同) 即進入平移; 是否平移只依按下滑鼠當下 Shift 是否按住判定, 拖曳中途按下或放開 Shift 不改變. 未按住 Shift 的拖曳為選取時段 (見 "縮放"). 平移時 顯示範圍隨游標的水平位移移動, 曲線跟著游標移動 (往右拖顯示較早的時間), 按住期間游標離開曲線圖仍持續平移; 按下後未移動超過 4 就放開視為點選. 平移結束放開時不設定固定時刻. 放開前約 100 ms 內的水平速度達每秒 300 以上時, 顯示範圍以該速度沿同一方向繼續移動並平順減速, 約 1 秒內停下; 低於此速度則停在放開處. 慣性捲動中在曲線圖上按下即停止, 這一次按下不設定固定時刻; 以其他方式改變顯示範圍或視窗失去焦點時亦停止. 繪圖區上的游標平時為左右方向的樣式, 表示拖曳只選取寬度; 游標位於繪圖區上, 按住 Shift 且可平移時為手形, 平移中為抓取的手形; 平移與慣性捲動中隱藏數值提示, 也不啟動邊緣自動捲動. 邊緣區為每張曲線圖繪圖區內最左側與最右側各 24 (與裝置無關的像素); 游標在邊緣區停留 300 ms 後開始捲動, 右側往較晚的時間, 左側往較早的時間, 速度固定為每秒移動顯示範圍長度的 10%. 游標離開邊緣區或曲線圖, 到達捲動範圍的邊界, 或視窗失去焦點時立即停止. 捲動進行中, 數值提示與讀數照常依游標所指的時刻更新, 點選照常設定固定時刻. 某一側還有資料可捲動時, 歷史畫面的每張曲線圖在該側顯示淡色漸層與箭頭, 該側正在捲動時箭頭改為強調色. 游標位於曲線圖上時, 觸控板的橫向滑動與按住 Shift 的滾輪依滑動距離與繪圖區寬度的比例移動顯示範圍; 未按 Shift 的垂直滾動照常上下捲動內容. 按住 Ctrl 或 ⌘ 的滾輪與觸控板的捏合用於縮放 (見 "顯示範圍"), 不捲動. 處於顯示全部狀態, 或捲動範圍不長於顯示範圍時, 不顯示捲動提示, 也不捲動. 監看畫面的曲線圖沒有上述捲動行為.
- **顯示範圍.** 曲線圖顯示的時間範圍稱為顯示範圍, 其長度由使用者以縮放按鍵, 滾輪或捏合調整 (見 "縮放"); 監看畫面的長度預設 5 分鐘, 歷史畫面於開啟記錄檔時一律顯示全部 (見 "顯示全部"). 監看畫面的長度為 1 分鐘至 24 小時; 歷史畫面的長度最短 1 分鐘, 最長為捲動範圍的長度, 捲動範圍短於 1 分鐘時即為捲動範圍的長度. 監看畫面的顯示範圍的右緣固定為所顯示主機最新一筆取樣的時刻, 不取系統時鐘, 不可捲動. 監看畫面只顯示該主機本次連線的曲線, 不顯示先前各次連線的記錄. 自動重新連線成功後視為另一次連線, 收到其第一筆取樣時清除斷線前的曲線, 由該筆取樣起重新繪製; 重新連線中照常顯示斷線前的曲線. 自動重新連線仍接續寫入原記錄檔, 因此歷史畫面開啟該記錄檔時, 斷線期間依無資料時段標示. 監看畫面的所有主機共用一個顯示範圍, 其長度記住; 歷史畫面另有一個, 其長度不記住. 純本機設定, 改變時只重畫, 不通知遠端.
- **縮放.** 縮放的方式如下:
  - **選取時段.** 歷史畫面的曲線圖上, 未按住 Shift 按下滑鼠主鍵後水平移動超過與平移相同的門檻, 即開始選取時段; 門檻只計水平位移, 未超過就放開視為點選. 選取的時段以佔滿繪圖區全高的淡色色帶標示, 只有左右兩條邊線, 高度不可選取; 游標的上下位置不影響選取, 按住期間游標離開該曲線圖仍持續選取, 水平位置限制於繪圖區內. 選取進行中, 所有 GPU 的曲線圖於同一時段同步顯示色帶, 被拖曳的曲線圖另於色帶上顯示起訖時刻與長度, 例如 "14:20:05 - 14:22:10 (2 m 5 s)", 文字不超出繪圖區. 長度不足 1 分鐘時只列秒, 未滿 1 小時列分與秒, 未滿 48 小時列小時與分, 達 48 小時列天與小時, 為零的末項省略. 放開後顯示範圍即變為所選時段, 不設定固定時刻. 所選時段短於長度下限時, 以其中心加長至下限, 超出捲動範圍時平移至捲動範圍內; 選取進行中色帶與文字即顯示加長後的範圍, 與放開後的顯示範圍一致. 選取進行中按 Esc, 或視窗失去焦點時取消選取, 顯示範圍不變; 此次 Esc 不清除固定時刻. 取消後在放開滑鼠之前繼續拖曳, 不重新開始選取, 放開時也不設定固定時刻. 選取進行中按下 Shift, 游標與行為皆不改變. 選取進行中隱藏數值提示, 也不啟動邊緣自動捲動. 監看畫面的右緣固定為最新一筆取樣的時刻, 沒有選取時段.
  - **縮放控制項.** 監看畫面的工具列有一組縮放控制項, 由左至右為標籤 "Time range", 縮小按鍵, 範圍長度與放大按鍵, 後三者位於同一個外框內, 標籤位於外框的左側, 說明外框內的數值為顯示範圍的長度. 範圍長度少於 1 小時以分鐘顯示, 例如 "5 min", 其餘以小時與分鐘顯示, 例如 "1 h 20 min", 分鐘為零時省略, 例如 "24 h", 寫法與記錄檔的長度相同; 範圍長度帶有單位, 不寫成時分秒, 以免與時間軸上的時刻混淆; 只供顯示, 不可點選; 欄寬固定, 文字長短變化時兩側按鍵不移動; 按鍵, 滾輪與捏合造成的變化皆立即反映. 歷史畫面沒有縮放控制項; 顯示範圍由時間軸兩端的時刻呈現. 按鍵以固定級距調整長度, 級距為 1 分鐘, 5 分鐘, 10 分鐘, 30 分鐘, 1 小時, 3 小時, 6 小時, 12 小時與 24 小時. 縮小按鍵把長度移至較長的相鄰級距, 放大按鍵移至較短的相鄰級距. 長度不在級距上時 (以滾輪或捏合調整後), 縮小按鍵移至比目前長的最近級距, 放大按鍵移至比目前短的最近級距, 例如長度為 7 分鐘時, 縮小後為 10 分鐘, 放大後為 5 分鐘. 已達長度範圍邊界的按鍵停用. 記住的長度不在級距上時不自動變更. 按鍵的滑鼠提示文字於 macOS 為 "Zoom out (⌘ + scroll wheel, or pinch on the trackpad)" 與 "Zoom in (⌘ + scroll wheel, or pinch on the trackpad)", 於 Windows 為 "Zoom out (Ctrl + scroll wheel, or pinch on the touchpad)" 與 "Zoom in (Ctrl + scroll wheel, or pinch on the touchpad)".
  - **滾輪與捏合.** 游標位於曲線圖上時, 按住 Ctrl 的滾輪 (macOS 另可按住 ⌘) 與觸控板的捏合以無段方式縮放顯示範圍, 用於微調, 不受按鍵的級距限制. 滾輪往下 (遠離使用者) 加長, 往上縮短; 每 100 單位的滾動量 (約為滑鼠滾輪一格) 使長度乘以或除以 1.25, 不足 100 單位時依比例連續變化. 滾動量以像素為單位; 以行為單位者每行計 16, 以頁為單位者每頁計繪圖區的高度. 捏合時長度隨兩指的距離成反比變化, 兩指張開為縮短. 結果超出長度範圍時取最接近的邊界. 捏合在 Chromium 核心的 WebView 中以按住 Ctrl 的滾輪事件送出, 在 macOS 的 WKWebView 中可能改以 WebKit 專屬的手勢事件送出, 兩者皆須處理; 於 macOS 觸控板上的行為未實測. 游標不在曲線圖上時, 上述操作不縮放顯示範圍.
  - **縮放時維持不動的時刻.** 監看畫面的右緣維持為最新一筆取樣的時刻, 只改變左緣. 歷史畫面以滾輪或捏合縮放時, 游標所指的時刻維持於游標下方, 捏合事件不帶游標位置時取游標最後所在的位置. 縮放後顯示範圍超出捲動範圍時, 平移至捲動範圍內.
  - **顯示全部.** 歷史畫面的 "顯示全部" 按鍵使顯示範圍涵蓋所開啟記錄檔的開始時刻到結束時刻, 此狀態下按鍵以強調色的底色, 文字與邊框顯示為選取狀態. 以任何方式縮短長度即離開此狀態; 以任何方式把長度加長至捲動範圍的長度即進入此狀態. 每次開啟記錄檔時, 不論先前的長度為何, 歷史畫面皆處於此狀態; 從記錄檔清單再次開啟同一個檔案亦同. 各記錄檔的長度相差甚大, 沿用另一個檔案的長度對使用者沒有意義, 先看到整個記錄檔再放大所需的時段較為直接.
  - **控制項的顯示與記住.** 歷史畫面的 "顯示全部" 按鍵於記錄檔載入後才顯示. 長度改變時畫面立即更新. 監看畫面的長度於停止改變 400 ms 後才寫入設定檔; 寫入失敗時依 "狀態文字與錯誤的顯示" 跳出 "Operation Failed" 視窗, 畫面上的長度維持不變. 歷史畫面的長度與顯示全部狀態不寫入設定檔, 離開歷史畫面時隨記錄檔關閉而捨棄.
- **降採樣.** 顯示範圍內取樣筆數多於像素寬度時, 依像素分桶取最大, 最小與平均, 曲線以平均描繪並以淡色帶顯示最大與最小, 避免尖峰消失. 某個像素範圍內沒有任何取樣時該處留空, 不以前後數值內插.
- 圖表 x 軸以取樣時刻為準, 能處理不等距的取樣點 (間隔被改變後).
- **中斷連線.** 連線中的每台主機皆提供 "中斷連線" 操作. 使用者按下後 GUI 關閉該主機的連線, 遠端 gpumon 隨之結束, 該主機直接轉為未連線狀態, 其分頁立即移除, 既有歷史仍可查閱, 不顯示任何視窗; 其他主機的連線不受影響. 之後可按 "連線" 重新監看.
- **斷線處理.** 非預期斷線 (網路中斷, 逾時, 遠端程式自行結束) 時不跳出視窗, 該主機轉為重新連線中狀態, GUI 依第 4 章的規則自動重新連線. GUI 檢查出錯誤而自行斷線時 (例如平台不符, 遠端的協定版本高於 GUI 的協定版本), 顯示明確的錯誤訊息, 不自動重新連線, 錯誤視窗關閉後該主機轉為未連線狀態. 錯誤視窗同一時間只有一個, 視窗已開啟時, 之後檢查出的錯誤附加於其中, 逐台列出. 畫面隨時顯示連線狀態.
- **上傳通知視窗.** 連線流程需要上傳或更新遠端程式時, 於上傳前跳出通知視窗, 規則見第 4 章 "遠端程式的更新". 首次上傳時視窗的標題為 "上傳遠端程式", 更新時為 "更新遠端程式", 視窗的外觀沿用既有對話框的樣式. 視窗內的欄位標籤由上至下為 "Location", "Current version", "New version", "Current hash" 與 "New hash"; 後四個欄位只於更新時顯示, 兩個程式版號相鄰, 兩個內容雜湊值相鄰, 便於上下比對. 視窗不可用 Esc 或點擊視窗外的區域關閉; 按下 Enter 等同按下確認鍵.
- **對話框的顯示順序.** 密碼輸入視窗, 主機指紋的確認視窗, 免密碼登入的詢問與結果視窗, 上傳通知視窗, 連線錯誤視窗與 "Operation Failed" 視窗依出現的先後排成一列, 畫面上同一時間只顯示最早出現的一個, 該視窗關閉後才顯示下一個.
- **狀態文字與錯誤的顯示.** 重新連線中的狀態文字為 "Reconnecting, retry n of 5 - 原因", 重試達上限而轉為未連線時為 "Disconnected after 5 retries - 原因". 錯誤視窗中每台主機佔兩行, 上行為依語言設定顯示的錯誤說明, 下行以較小的字顯示後端的英文原文. 連線以外的操作失敗時 (例如設定寫入失敗), 另以標題為 "Operation Failed" 的視窗顯示.
- 每 5 秒送 `ping` 心跳.
- 收到無法解析的行 (例如遠端警告) 記錄到日誌, 不中斷.
- **語言.** 介面語言預設為英文, 不隨作業系統的語言設定變動. 設定頁面提供語言選項, 目前為 English 與繁體中文兩種, 使用者可隨時切換; 切換後立即生效, 不需重新啟動, 並記住選擇. 語言設定涵蓋視窗內的所有文字, 對話框, 系統匣或選單列的選單, 以及 GUI 產生的錯誤訊息. 應用程式名稱 "GPU Monitor" 不翻譯, 遠端程式送出的 `error` 訊息照英文原文顯示, 日期與時間的格式不隨語言變動, 安裝包只有英文. 所有介面文字集中於語言資源檔, 每種語言一個檔案, 程式內不寫死介面文字; 新增語言時增加一個資源檔與一個選項. 某段文字在所選語言的資源檔中沒有對應內容時, 顯示英文.
- **容量單位.** 容量單位有二進位與十進位兩種, 預設為二進位. 設定頁面以兩段式切換鍵提供此選項, 使用者可隨時切換; 切換後立即生效, 不需重新啟動, 並記住選擇. 二進位以 1024 進位, 單位為 KiB, MiB, GiB; 十進位以 1000 進位, 單位為 kB (小寫 k), MB, GB. 此設定套用於 GPU 卡片的記憶體讀數 (已使用量與總量), 曲線圖數值提示中的記憶體數值, 程序卡片的記憶體欄, 以及記錄檔清單與刪除確認視窗的檔案大小. GPU 卡片的讀數與曲線圖的數值提示以 GiB (十進位為 GB) 顯示, 取一位小數. 程序卡片的記憶體欄依大小選擇單位, 達 1 GiB (十進位為 10^9 位元組, 即 1 GB) 用 GiB (GB) 並取一位小數, 否則用 MiB (MB) 並取整數. 檔案大小小於 0.1 MiB (十進位為 0.1 MB) 用 KiB (kB) 並取整數, 達 1 GiB (GB) 用 GiB (GB), 其餘用 MiB (MB), 後兩者取一位小數. 容量單位一項的標題與選項文字如本節的中英用語對照表所列, 說明文字為英文 "Used for GPU memory and recording file sizes. ### 6.3 SSH 認證

- 支援 SSH 金鑰 (含 ssh-agent), 密碼, `~/.ssh/config` 的 HostName 查詢. 本機不需要安裝 SSH 用戶端程式.
- **登入方式的順序.** 依序為 ssh-agent 提供的金鑰, 金鑰檔, 密碼. 不支援 keyboard-interactive. 密碼不進日誌與錯誤訊息.
- **金鑰檔的來源.** 主機表單指定金鑰檔時, 只用該檔案; 留空時依序列出預設名稱的金鑰檔, 依序為 `~/.ssh/id_rsa`, `id_ecdsa`, `id_ed25519`. 不使用 `~/.ssh/config` 的 IdentityFile. 程式從中取用存在且能取得公鑰的金鑰檔; 不存在或無法取得公鑰的檔案略過, 不顯示錯誤.
- **ssh-agent 的金鑰.** ssh-agent 的金鑰排在金鑰檔之前, 已在 ssh-agent 中的金鑰檔不重複嘗試. 主機表單勾選 "只使用指定的金鑰檔" 時, ssh-agent 的金鑰只保留與上述金鑰檔相同者.
- **ssh-agent.** macOS 經 `SSH_AUTH_SOCK` 連線. Windows 經 named pipe `\\.\pipe\openssh-ssh-agent` 連線, 不支援 Pageant (未實測).
- **主機金鑰.** 程式以兩份 known_hosts 比對遠端主機的主機金鑰, 規則如下:
  - 程式自己的 known_hosts 位於應用程式資料目錄 (見 6.6), 格式同 OpenSSH. 檔案不存在時建立空檔案.
  - OpenSSH 的 `~/.ssh/known_hosts` 存在時讀取, 僅供比對, 程式永不寫入. 略過無法解析的行, 讀不到時視為空檔案.
  - 兩份 known_hosts 皆逐行檢查, 無法解析的行 (含超過 32 KiB 的行) 略過, 其餘照常比對; `@revoked` 與 `@cert-authority` 的語意不變. 程式自己的 known_hosts 有略過的行時, 以合格的行改寫檔案, 採原子寫入, 權限為 0600, 不留備份; 寫入新的主機金鑰前亦同. 該檔存在而讀不到時刪除並重建空檔案; 刪除或重建失敗時視為空檔案繼續連線, 所有主機皆為未知主機, 依下列流程詢問使用者. 此修正不通知使用者. known_hosts 與 `~/.ssh/config` 皆不造成連線錯誤.
  - 遠端主機的金鑰在任一份檔案中標為 `@revoked` 時, 不詢問使用者, 直接拒絕連線並說明該金鑰已撤銷, 說明中寫出該記錄所在檔案的實際路徑 (含 OpenSSH 檔案的路徑).
  - 協商時優先採用兩份檔案為該主機記錄的主機金鑰種類.
  - 兩份檔案中任一筆該主機的記錄與遠端主機的主機金鑰相同, 即通過比對.
  - 兩份檔案皆沒有該主機的記錄時, 跳出標題為 "未知的主機" 的視窗, 顯示遠端主機的指紋, 詢問使用者是否繼續連線. 按鍵為 "連線" 與 "取消", "連線" 為預設按鍵, Enter 等同 "連線", Esc 等同 "取消".
  - 有該主機的記錄但皆不相同時, 例如遠端主機重新安裝作業系統之後, 跳出標題為 "主機金鑰不符" 的視窗, 顯示新舊指紋, 警告可能遭到冒充, 詢問使用者是否更新記錄並繼續連線. 按鍵為 "更新並連線" 與 "取消". 此視窗沒有預設按鍵, 開啟時焦點位於 "取消", 使用者不會因按下 Enter 而誤接受不符的主機金鑰; Esc 等同 "取消".
  - 使用者同意時, 程式把主機金鑰寫入自己的 known_hosts, 並刪除其中該主機的舊記錄, 然後繼續登入. OpenSSH 檔案中的記錄不更動. 寫入失敗時仍繼續連線. 記錄的主機欄位為 `~/.ssh/config` 解析後的 HostName, 連接埠不是 22 時寫成 `[主機]:連接埠`, 不另記 IP 位址. 舊記錄的判定含雜湊過的主機名稱與萬用字元.
  - 使用者不同意時中止連線, 不顯示錯誤視窗.
  - 指紋以 SHA256 雜湊表示, 格式同 OpenSSH, 例如 `SHA256:` 開頭的字串.
  - 自動重新連線不跳出上述兩種視窗. 需要使用者確認指紋時停止重試, 依檢查出錯誤而斷線處理, 錯誤訊息說明遠端主機的指紋需要使用者確認.
- **逾時.** 建立連線與每一次遠端操作 (執行指令, SFTP 上傳) 皆設逾時上限, 超時視為遠端無回應, 依第 4 章 "連線結束的情形" 處理. 建立連線的上限為 10 秒, 等待使用者輸入密碼或確認指紋的時間不計入; 執行一個遠端指令的上限為 10 秒; 上傳遠端程式的上限為 60 秒. 自動重新連線時建立連線的上限依第 4 章為 5 秒.
- 不記住密碼, 每次連線由使用者輸入. 密碼不寫入磁碟, 也不存入作業系統的密碼儲存區.
- **密碼的輸入次數.** 一次連線中, 登入密碼遭遠端拒絕時再次要求輸入, 最多要求 3 次, 第 3 次仍遭拒絕即判定為認證失敗. 登入密碼的輸入視窗按下 "取消" 時中止該次連線, 不顯示錯誤視窗. 每一把有密碼保護的金鑰, 金鑰密碼錯誤時再次要求輸入, 最多要求 3 次. 金鑰密碼第 3 次仍錯誤, 輸入視窗留空送出, 或按下 "取消" 時, 略過該金鑰; 其後的金鑰亦不再嘗試, 改以密碼登入. 此為 SSH 函式庫一把金鑰無法簽章時的行為. 自動重新連線不要求輸入, 規則見下一條; 先前未解開的金鑰因此略過, 改以暫留的登入密碼登入.
- **密碼的暫留與銷毀.** 主機處於連線中或重新連線中狀態時, 登入密碼暫留於記憶體, 供自動重新連線使用. 主機轉為未連線狀態或程式結束時立即銷毀, 包括自動重新連線達到重試次數上限的情形. 程式自行保管的密碼以位元組陣列存放, 銷毀時以零覆寫 (推斷, 未實測). SSH 函式庫與密碼輸入視窗內的密碼副本無法覆寫, 只能等待記憶體回收, 此為已知且接受的限制.
- **有密碼保護的金鑰.** 遠端主機接受有密碼保護的金鑰檔, 要求以該金鑰簽章時, 才跳出視窗要求輸入金鑰密碼; 程式不事先判斷金鑰檔是否有密碼保護. 金鑰密碼不寫入磁碟, 也不存入作業系統的密碼儲存區, 解密完成後立即以零覆寫. 解密後的金鑰暫留於記憶體的期間與登入密碼相同, 銷毀時解除引用.
- **免密碼登入.** 以密碼登入成功後, 符合下列全部條件時, 跳出視窗詢問使用者是否設定免密碼登入:
  1. 該主機未記為不再詢問.
  2. 本次登入過程中, 遠端主機未曾要求以有密碼保護的金鑰簽章. 有此要求表示遠端主機已接受該金鑰, 不需要再設定.
  3. 本機有金鑰檔, 或本機沒有金鑰檔且 ssh-agent 也沒有金鑰. ssh-agent 的金鑰數以 "只使用指定的金鑰檔" 過濾前為準, 無法連上 ssh-agent 時視為沒有金鑰.
  4. 本次連線不是自動重新連線.

  視窗的標題為 "設定免密碼登入", 按鍵由左至右為 "不再詢問", "暫不設定" 與 "立即設定", 預設按鍵位於最右端, 與其他對話框一致. Enter 等同 "立即設定", Esc 等同 "暫不設定". 各按鍵的處理如下:
  - "暫不設定" 不做任何事, 下次以密碼登入時再次詢問.
  - "不再詢問" 把該主機記為不再詢問, 記錄存於設定檔 (見 6.6).
  - "立即設定" 先確認本機的金鑰檔. 本機沒有金鑰檔時, 產生一個沒有金鑰密碼的 Ed25519 金鑰檔. 其位置為主機表單的金鑰檔, 留空時為 `~/.ssh/id_ed25519`; 公鑰寫入同名加上 `.pub` 的檔案, 註解為 "本機使用者名稱@本機主機名稱", 與 ssh-keygen 相同. 所在目錄不存在時一併建立, 目錄的權限為 0700, 金鑰檔的權限為 0600, 公鑰檔為 0644. 該位置已有無法使用的檔案時不覆寫, 判定為產生失敗. 產生失敗時告知使用者, 不放置公鑰, 也不記為不再詢問.
  - "立即設定" 接著把本機第一個金鑰檔的公鑰附加至遠端的 `~/.ssh/authorized_keys`. 第一個金鑰檔依 "金鑰檔的來源" 的順序決定. 遠端的 `~/.ssh` 目錄或 `authorized_keys` 不存在時建立, 權限依序為 0700 與 0600; 既有的目錄與檔案不更動權限. 既有內容只附加, 不刪改, 也不檢查是否已有相同的公鑰. 附加的內容為公鑰, 同名 `.pub` 檔為同一把金鑰時附上其註解. 附加失敗時把該主機記為不再詢問.
  - 附加成功或失敗, 皆以標題同為 "設定免密碼登入" 的視窗告知使用者結果, 只寫結論, 不寫使用的金鑰檔; 只有本次產生了金鑰檔 (且不是產生失敗) 時, 另以一句 "已產生新的金鑰檔 {路徑}。" 寫出新金鑰檔的路徑. 失敗時比照錯誤視窗, 以較小的字另行顯示後端的英文原文. 按鍵為 "確認", Enter 與 Esc 皆關閉視窗.

  產生金鑰檔或附加公鑰失敗皆不影響本次連線, 連線流程照常繼續. 等待使用者回應期間, keepalive 的送出與連線中斷的判定皆與第 4 章的上傳通知視窗相同; 連線中斷時視窗關閉, 連線的中斷依第 4 章處理.
- **`~/.ssh/config` 的取用範圍.** GPU Monitor 對 `~/.ssh/config` 只作參考. 主機表單的預填取用 Port, IdentityFile, IdentitiesOnly (見 6.2 的 "主機表單的 `~/.ssh/config` 預填"); 連線只取用 HostName, 位址為 Host 名稱時查出實際位址; User, Port, IdentityFile, IdentitiesOnly 一律以主機表單的值為準, 不取用 User. 依 Include 讀入其他設定檔, 其餘設定項目忽略且不警告. 程式不支援 ProxyJump 與 ProxyCommand, 設有時忽略, 直接連線至該主機. Match 區塊整段忽略. Include 的相對路徑以設定檔所在的目錄為準, IdentityFile 的相對路徑以本機的家目錄為準. 設定值支援 `%h`, `%p`, `%r`, `%n`, `%d`, `%u`, `%%` 七種代碼.
  - 解析容錯: 有錯誤的行 (缺參數, 不合法的連接埠, 不合法的 IdentitiesOnly 值, 未結束的引號) 略過, 其餘照用; 格式錯誤的 Host 行使其整個區塊不符合任何主機; 讀不到的 Include 與巢狀超過 16 層的 Include 略過; 主檔案存在而讀不到時視為沒有設定; 超過 1 MiB 的行之後的內容略過.
  - 每個略過之處產生一則英文警告, 例如 `Skipped line N of ~/.ssh/config: invalid port "abc"`.
  - 連線時讀取 HostName 有警告且連線失敗時, 錯誤的英文說明後附加 `Parts of ~/.ssh/config were skipped because they could not be read or parsed`. 連線成功時不回報. 連線建立後遠端程式未送出裝置資訊的錯誤不附加.

### 6.4 記錄檔格式

記錄檔目前的格式版本為 2, 規則如下:

- 記錄檔位於應用程式資料目錄下的 `history/<主機目錄>/`.
- `<主機目錄>` 為該主機的識別 (見 6.6 "主機的識別"), 其中連接埠前的 `:` 換成 `+`, 例如 `user@host:2222` 的目錄為 `user@host+2222`, 連接埠 22 的目錄名稱不變; 再把不屬於英文字母, 數字, `.`, `_`, `@`, `-` 與該 `+` 的字元逐一換成 `_`. 換算結果為空字串或只由 `.` 組成時不建立記錄檔, 以免路徑超出 `history/`.
- 檔名為 `<YYYYMMDD-HHMMSS>.gpurec`, 日期與時間為該檔案第一筆取樣的時刻換算成本機時區後的值. 同名檔案已存在時, 於 `.gpurec` 之前依序加上 `-2`, `-3`, 直到不重複為止.
- 每次存檔附加一個經過壓縮的區塊. 檔案中段損壞時只失去損壞的區塊, 以及其後最多 10 分鐘的程序列表, 其餘資料照常讀取.
- 程式只建立版本 2 的記錄檔. 版本 1 的記錄檔只供讀取, 不再附加記錄. 識別字串不符的檔案不是記錄檔, 拒絕開啟; 格式版本為不認得的值時拒絕開啟, 並顯示該版本號.

### 6.5 視覺設計

**字型**

- 介面文字使用 IBM Plex Sans. 數值, 主機位址, 時刻, 路徑與指令使用 IBM Plex Mono, 使各列的數字上下對齊.
- 基準字級為 13 px.
- 字型檔隨程式內建, 執行期不自網路載入. 兩種字型的授權為 SIL Open Font License, 此項未查證.

**英文介面文字的大小寫**

英文介面文字的大小寫依其用途分為下列四類, 新增的文字依此決定寫法.

- 每個單字的首字母大寫, 冠詞, 連接詞與介系詞除外. 適用於按鍵, 選單項目, 分頁, 側欄的入口, 設定項目的標題, 以及視窗與對話框的標題, 例如 "Add Host", "Show All", "Bring All to Front", "Third-Party Licenses", "Size Units", "Filter Processes".
- 只有句首的字母大寫. 適用於欄位與控制項的標籤, 選項, 卡片與區段的標題, 圖例, 狀態文字, 說明文字, 滑鼠提示文字, 以及以問句作為標題的確認視窗, 例如 "User name", "Time range", "Any user", "Direct dependencies", "Fan speed", "Zoom out", "Delete 1 recording?".
- 全部大寫. 適用於 GPU 卡片的讀數名稱與表格的資料欄位名稱, 例如 "UTIL", "GPU MEM", "COMPONENT". 程序表格的 "Pin to top" 欄說明的是操作, 不是資料欄位, 依前一類.
- 全部小寫. 適用於接在數值之後的時間單位與記錄檔起訖時刻中的 "now", 例如 "5 min", "2 h".

專有名詞與縮寫維持其原有寫法, 例如 "GPU Monitor", "PID", "GiB", "WebView2 Runtime".

### 6.6 設定檔

本節定義 GUI 所記住的設定的儲存方式. 需記住的項目見 6.1 與 6.2 各條.

**存放位置**

- 應用程式資料目錄於 macOS 為 `~/Library/Application Support/gpumon/`, 於 Windows 為 `%LOCALAPPDATA%\gpumon\`. Windows 不使用隨帳號漫遊的 `%APPDATA%`, 因為記錄檔位於同一目錄且容量大.
- 設定檔為該目錄下的 `settings.json`, 記錄檔位於該目錄下的 `history/` (見 6.4), 程式自己的 known_hosts 為該目錄下的 `known_hosts` (見 6.3). 兩者的自我修正規則見 6.3 的 "主機金鑰".
- 設定檔與 `known_hosts` 的權限為 0600, 應用程式資料目錄的權限為 0700.
- 環境變數 `GPUMON_DATA_DIR` 有值時, 程式以其所指的目錄為應用程式資料目錄. 此功能供測試使用, 使測試不寫入真實的應用程式資料目錄.

**內容**

- 設定檔為一個 JSON 物件, 成員 `version` 為格式版本, 目前的值為 1.
- 頂層成員 `monitor_span_ms` 為監看畫面的顯示範圍長度, 單位為毫秒, 預設為 300000. 設定檔不含歷史畫面的顯示範圍. 頂層成員 `collapsed_procs` 為程序卡片已收合的主機識別字串陣列. 頂層成員 `collapsed_maxima` 為最大值卡片已收合的主機識別字串陣列. 設定檔不含取樣間隔.
- 頂層成員 `proc_sorts` 為各主機程序卡片的排序方式, 是以主機識別字串為鍵的物件, 值為含 `column` 與 `order` 兩個成員的物件. `column` 為 `gpu`, `pid`, `user`, `util`, `mem`, `command` 之一, `order` 為 `asc` 或 `desc`. 排序方式為預設 (GPU 欄遞增) 的主機不存放. 讀入時, `column` 不合法即改為 `gpu`, `order` 不合法即改為 `asc`.
- 頂層成員 `proc_filters` 為各主機程序卡片的過濾條件, 是以主機識別字串為鍵的物件, 值為含 `gpus`, `user`, `command` 三個成員的物件. `gpus` 為 GPU 編號的陣列, 空陣列表示沒有 GPU 條件; `user` 與 `command` 為字串, 空字串表示未設定. 沒有任何條件的主機不存放. 讀入時, 文字去除前後的空白, GPU 編號捨棄負數, 去除重複並由小到大排列.
- 頂層成員 `size_units` 為容量單位, 值為 `binary` (二進位, 1024 進位) 或 `decimal` (十進位, 1000 進位), 預設為 `binary`. 讀入時值不合法或型別不符, 即改用預設值.
- 頂層成員 `no_key_setup_prompt` 為記為不再詢問免密碼登入的主機識別字串陣列 (見 6.3).
- 設定檔不含登入密碼, 金鑰密碼或任何憑證.
- 設定檔不含程序的置頂與程序卡片的水平捲動位置.
- 曲線的選擇可以為空, 即使用者取消所有曲線.

**主機的識別**

- 比對主機是否相同時, 位址不分大小寫, 使用者名稱區分大小寫, 連接埠列入比對, 留空與 22 視為相同.
- 位址與使用者名稱不得含 `@` 或空白字元.
- 新增主機時已有相同的主機, 即拒絕新增.
- 主機的識別為 "使用者名稱@位址", 連接埠不是 22 (含留空) 時為 "使用者名稱@位址:連接埠"; IPv6 位址搭配非 22 的連接埠時, 位址以方括號括住, 例如 `user@[fe80::1]:2222`. 使用者名稱為空 (僅舊版主機可能發生) 時為位址, 非 22 連接埠時加上 ":連接埠". 畫面顯示的主機名稱, 記錄檔的 `host` 成員, 記錄檔目錄名稱的來源與判定重複的依據, 皆為此識別.
- 編輯主機後, 該主機的排列位置維持不變; 編輯使主機的識別改變時, GPU 卡片與程序卡片的收合狀態, 程序的排序方式, 過濾條件與置頂隨之轉移至新的識別; 免密碼登入的不再詢問不轉移而清除, 因為新的識別指向另一個遠端帳號. 刪除主機時一併清除其收合狀態, 排序方式, 過濾條件, 置頂與不再詢問.

**舊版設定檔的升級**

- 設定檔中沒有 `identities_only` 成員的主機為舊版主機. 程式啟動讀取設定檔時, 依 `~/.ssh/config` (以位址為 Host 名稱) 一次填入舊版主機的空白欄位. 使用者名稱空白時填 User, 連接埠留空時填 Port, 金鑰檔空白時填第一個 IdentityFile, "只使用指定的金鑰檔" 依 IdentitiesOnly 設定 (無設定為不勾選). 含 `@` 或空白的 User, 1 至 65535 以外的 Port 不填入. 填入後會與其他主機重複時, 該主機維持原欄位. 填完後寫回設定檔; 寫回失敗時以記憶體中的值繼續, 於下次變更時寫入.
- 升級使主機識別改變時, 以該識別保存的狀態 (GPU 卡片, 程序卡片與最大值卡片的收合狀態, 程序的排序方式與過濾條件, 免密碼登入的不再詢問) 轉移至新的識別; 所有主機的識別一次轉移, 互不混淆.
- 該主機既有的記錄檔 (`host` 成員恰為舊識別者) 改寫至新識別的目錄. 檔名不變, 撞名時加上 `-2`; 只改 `host` 成員, 其餘內容不變; 新檔寫入完成後才刪除原檔, 原目錄清空後一併刪除. 此步驟在寫回設定檔之前進行, 中途結束時下次啟動重做; 失敗只寫入日誌.
- 升級後使用者名稱仍為空的主機, 連線時以 "連線錯誤" 視窗回報 "連線設定不完整。請編輯此主機後再連線。", 英文原文為 `No user name is specified for <位址>. Edit the host and enter a user name`. 其顯示名稱沿用最近一次登入的使用者名稱, 或主機 ID.

**寫入與讀取**

- 寫入時先寫入同一目錄的暫存檔, 再更名取代設定檔, 程式於寫入中途異常結束時不留下內容不完整的設定檔.
- 設定檔不存在時使用預設值.
- 設定檔的內容無法解析時, 把原檔更名為 `settings.json.corrupt-<時間>` 保留, 程式以預設值啟動.
- 設定檔的格式版本高於程式所認得者時, 把原檔更名為 `settings.json.v<版本>-<時間>` 保留, 程式取用其中認得的成員.
- 不認得的成員略過. 型別不符的成員改用預設值, 其餘成員照常取用.
- 設定檔沒有 `monitor_span_ms` 與 `monitor_range`, 而有更早版本同時顯示所用的共用顯示範圍 `shared_range` 時, 以該選項的長度作為監看畫面的長度. 舊版的顯示方式與各主機的顯示範圍讀取時略過, 下次寫入後不再保留. 舊版設定檔中頂層與各主機項目的 `interval_ms` 同樣讀取時略過, 下次寫入後不再保留.
- 設定檔沒有 `monitor_span_ms` 而有舊版以選項表示的監看畫面顯示範圍 `monitor_range` 時, 以該選項的長度作為監看畫面的長度. 舊版的歷史畫面顯示範圍 `history_range`, `history_span_ms` 與 `history_all` 於讀取時略過. 舊版成員於下次寫入後不再保留.
- 顯示範圍長度與視窗大小超出合法範圍時取最接近的合法值; 歷史畫面的長度於設定檔中只限制為不短於 1 分鐘, 開啟歷史畫面時再依捲動範圍限制. 其他設定的值不合法時改用預設值.

## 8. 建置, 版本與打包

本節做法沿用 ~/myproj/remote 專案的 build.sh, msi/gui.wxs.in 與 internal/version/version.go, .pkg 部分為新增. 8.6 的做法沿用 ~/myproj/cheese 專案 app/ 的 build.sh 與 scripts/gen-licenses.sh.

### 8.1 建置環境

- 全部於 macOS 上建置, 含 Windows 與 Linux 目標, 不需 Windows 或 Linux 機器.
- 單一 Go module, `cmd/cli` 為遠端程式, `cmd/gui` 為本機 GUI; 共用套件放 `internal/`.
- macOS 26 起使用的圖示為 `assets/icon/gpumon.icon`, 由 Icon Composer 建立, 背景為 `#1d5fd1`, 預設與深色外觀相同, 前景為由 `assets/icon/app-foreground.svg` 產生的章魚圖層. `generate.sh` 以 Xcode 26 以上的 actool 將其編譯為 `assets/icon/Assets.car` 並納入版控, 因此只有重新產生圖示時需要 Xcode, 建置腳本不需要. 章魚造型更動時, 須在 Icon Composer 中以新產生的圖層替換並存檔.
- 應用程式圖示由 `assets/icon/app.svg` 產生, 取其 `.icns` 放入 .app, 其 `.ico` 於建置 Windows 執行檔前由建置腳本以獨立的工具 module `scripts/syso` 轉為只含圖示資源的 `cmd/gui/rsrc_windows_amd64.syso` (建置中間檔, 不入版控, 不含 application manifest), 由 Go 連結進執行檔. 圖示以資源 ID 3 存放, Wails 以此作為 Windows 視窗圖示, 檔案總管亦以此顯示執行檔圖示.
- GUI 內嵌 `assets/icon/app-1024.png`. macOS 直接執行未包裝於 .app 的執行檔時, 程式啟動後以此圖設定 Dock 圖示, 否則 Dock 只顯示系統預設的執行檔圖示. 執行檔位於 .app 的 `Contents/MacOS` 之內時不設定, Dock 圖示由 .app 內的 Assets.car 或 gpumon.icns 提供 (.app 的情形未實測).
- 本機 GUI 執行檔名為 gpumon (Windows 為 gpumon.exe), 應用程式顯示名稱為 "GPU Monitor" (視窗標題, 安裝包的產品名稱, 開始功能表與 .app 名稱皆用此名).
- 遠端程式建置產出名為 gpumon.bin, 由 GUI 內嵌並上傳, 上傳後遠端檔名為 gpumon.
- 建置順序為先建 `linux/amd64` 的 gpumon.bin, 再建 GUI (GUI 以 `go:embed` 嵌入剛建好的 gpumon.bin), 最後打包.
- GUI 的 Windows 目標以 CGO_ENABLED=0 建置, 加 `-H windowsgui` 避免多餘的 console 視窗; macOS 目標需 cgo, 以 CGO_CFLAGS, CGO_LDFLAGS 與 -extldflags 三處統一指定 -mmacosx-version-min.
- 建置腳本須同時相容 bash 與 zsh. 建置腳本只可直接執行, 以 `source` 執行時拒絕建置.
- macOS 的最低版本為 13.0, 即 Go 1.27 的連結器所支援的最舊版本.
- Wails 的命令列工具以 `go.mod` 的 tool 指示釘選, 建置腳本以 `go tool wails3` 執行, 不使用本機另行安裝的版本.
- 建置腳本的選項只有 `--all` 與其簡寫 `-a`. 未傳入時只建置執行檔, 即遠端程式與兩個平台的 GUI 執行檔; 傳入時另建置 8.3 與 8.4 的安裝包.

### 8.2 版本

- 版本單一來源為 `internal/version/version.go` 的常數 `VERSION`, SemVer 形式 x.y.z[-stage.N] (stage 為 alpha, beta 或 rc).
- 程式版號直接編輯該常數, 不另設維護腳本. 其中 x, y, z, N 皆為不補零的十進位整數. 建置腳本於建置前檢查該常數是否符合此格式, 不符合即中止建置.
- 建置 GUI 時, commit hash 與建置時間於建置期以 `-ldflags -X` 注入同一套件的變數; 未經建置腳本時兩者的值皆為 unknown, 建置時間顯示 unknown, commit hash 則不出現在完整版本字串中.
- 建置遠端程式時不注入 commit hash 與建置時間, 並以 `-buildvcs=false` 關閉 Go 自動寫入版本控管資訊的行為, 連同 `-trimpath`, 使遠端程式的檔案內容只由其原始碼, 相依套件, Go 版本與建置選項決定. 這些皆相同時, 每次建置產出的檔案內容相同, 第 4 章的內容雜湊值亦相同. 遠端程式的完整版本字串見 5.7.
- GUI 的完整版本字串為 x.y.z[-stage.N][+<commit>[-dirty]], 用於產出檔名與 GUI 顯示的版本. `<commit>` 為最後一次改動產品路徑的 commit 的 hash 前 7 個字元; 未經建置腳本建置, 或沒有任何 commit 改動過產品路徑時, 完整版本字串不含 `+<commit>[-dirty]` 一段, 只有程式版號. 建置時產品路徑有未提交的修改才加上 `-dirty`, 未追蹤的檔案亦視為未提交的修改. 產品路徑為內容會進入產出的路徑, 包括原始碼, 內嵌的素材, 授權清單的來源, 安裝包範本與建置工具, 清單由 `scripts/product_commit.sh` 維護, 建置腳本與發布腳本共用. 只改動文件等非產品路徑的 commit 不改變 `<commit>`. MSI Product Version 與 macOS Info.plist 的版本欄位只接受純數字, 另剝除為 x.y.z.
- GUI 與其內嵌的遠端程式使用同一份版本套件, 兩者的程式版號必然相同. 遠端主機上現有的遠端程式可能由其他版本的 GUI 上傳, 其程式版號不一定與本機的 GUI 相同, 處理方式見第 4 章.

### 8.3 Windows 安裝包 (.msi)

- 以 wixl (Homebrew 的 msitools 套件) 於 macOS 編譯, 建置腳本於缺少時自動安裝.
- 來源為 WiX XML 範本 `msi/gui.wxs.in`, 建置腳本以 sed 替換 `@VERSION@` (純數字) 與 `@FULLVERSION@` (完整版本) 後產出 `msi/gui.wxs`, 產出檔不入版控.
- UpgradeCode 為固定 GUID, 寫定後不得變更, 變更即視為另一產品.
- ProductCode 設為 `*`, 每次編譯自動產生新 GUID, 搭配 MajorUpgrade 達成安裝新版自動移除舊版; AllowSameVersionUpgrades 設 yes 允許同版本覆蓋, 降級維持拒絕.
- 安裝範圍 perUser, 不需管理員權限, 安裝目錄為 `%LOCALAPPDATA%\Programs\<廠商>\<產品名>`. 廠商為 Augustus Chen, 產品名為 GPU Monitor.
- REINSTALLMODE 設 amus, 強制重寫所有檔案, 避免升級時無版本檔案被判定不必複製, 隨後又被舊產品移除.
- 於 "新增或移除程式" 顯示的圖示為 `assets/icon/gpumon.ico`, 由 `<Icon>` 元素內嵌並以 ARPPRODUCTICON 指定.
- 只建立開始功能表捷徑, 不建立桌面捷徑. 開始功能表的捷徑直接置於程式清單, 不另設資料夾. wixl 不支援 `<UI>` 元素, 無法在安裝過程詢問使用者, 故捷徑不做成可勾選項.- Windows 需 WebView2 執行期, Windows 10 / 11 內建.
- 安裝包不簽章.

### 8.4 macOS 安裝包 (.pkg)

- 先組 .app bundle (Contents/MacOS 放執行檔, Contents/Resources 放 gpumon.icns 與 Assets.car, Contents/Info.plist 寫入 CFBundleVersion 與 CFBundleShortVersionString, 皆為純數字版本, 以及 LSMinimumSystemVersion, 指向 Assets.car 中圖示的 CFBundleIconName 與指向 gpumon.icns 的 CFBundleIconFile). 兩個鍵與 actool 產生的 Info.plist 片段相同; 各版本 macOS 實際採用哪一份圖示未實測.
- 以 macOS 內建的 `pkgbuild` 將 .app 打成 component package, 安裝目標為 /Applications; 再以 `productbuild` 包成可散布的 .pkg.
- Bundle identifier 為 `io.github.nexgus.gpumon`. .app 於 .pkg 內設為不可重新定位, Installer 固定安裝至 /Applications. .pkg 只可安裝於 arm64 的機器.
- 同名 .app 由 Installer 覆蓋, 達成升級.
- 安裝包與 .app 皆不簽章, 也不送交 Apple 公證.

### 8.5 產出與歸檔

- 產出放 `bin/` (不入版控), 檔名帶完整版本, 例如 `gpumon-<完整版本>-windows-amd64.msi`, `gpumon-<完整版本>-darwin-arm64.pkg` 與 `gpumon-<完整版本>-linux-amd64.bin`.
- 建置前把 `bin/` 內舊版產出依版本段歸檔至 `bin/archive/<版本>/`.
- 每次建置於 `bin/` 建立名為 `gpumon` 的符號連結, 以相對路徑指向該次建置的 macOS 執行檔, 供直接執行最新的建置. 此連結不隨舊產出歸檔, 由下次建置取代.

### 8.6 第三方授權清單

關於視窗的第三方授權分頁 (見 6.2) 所顯示的清單, 涵蓋隨安裝包散布的所有第三方元件, 分為三類:

| 類別 | 範圍 | 直接引用與間接引用的判定 |
|---|---|---|
| Go 的相依套件 | 實際編譯進 GUI 執行檔 (darwin 與 windows 兩個目標) 與內嵌的遠端程式 (linux 目標) 的 module | `go.mod` 的 require 未標為 indirect 者為直接引用, 其餘為間接引用 |
| 前端的 npm 相依套件 | 實際打包進前端產出的套件 | `package.json` 的 dependencies 所列者為直接引用, 其餘為間接引用 |
| 其他素材 | 字型, 圖示等既非 Go module 也非 npm 套件的素材, 由一份人工維護的清單記載 | 一律為直接引用 |

- 授權條文逐字取自各元件的授權檔, 元件附有 NOTICE 檔時一併納入.
- npm 套件未隨附授權檔時, 取專案內 `licenses/npm/<套件名稱>/` 所存的授權條文, 該條文逐字抄自該元件的原始碼儲存庫. 其他素材的清單為 `licenses/other-materials.json`.
- 任一元件找不到授權條文時, 建置中止.
- 清單由腳本產生為前端的資料檔, 該檔納入版本控管.
- 建置腳本每次建置皆重新產生清單, 不設選項. 其他素材的授權條文存於專案內, 產生清單不需網路.
- 清單內容依固定順序排列. 相依套件與其他素材沒有變動時, 重新產生的資料檔與原檔完全相同.

### 8.7 發布

- 發布腳本為專案根目錄的 `release.sh`, 以 forgectl 將安裝包上傳至 GitHub 的 `nexgus/gpumon` 並建立 release. 腳本須同時相容 bash 與 zsh, 只可直接執行.
- 版本取自 8.2 的 `VERSION` 常數. 發布腳本可傳入版本, 傳入的版本須與該常數相同. 只發布正式版本 x.y.z, 帶 stage 的版本一律中止.
- Release 的 tag 名稱為版本本身, 不加 `v`, 指向 8.2 所述最後一次改動產品路徑的 commit, 不一定是 HEAD.
- 以下任一情形中止發布: 產品路徑有未提交的修改; 該 commit 尚未 push 至 `origin/main`; `bin/` 內找不到以該 commit 建置的 .msi 或 .pkg; 找不到 release note.
- 上傳的 asset 只有 .msi 與 .pkg, 檔名去掉 commit hash, 例如 `gpumon-0.1.0-windows-amd64.msi` 與 `gpumon-0.1.0-darwin-arm64.pkg`.
- Release note 存於 `docs/releases/<版本>.md`, 以英文撰寫. 開發期的 release note 可命名為 `<版本>-rc.md`; 正式檔不存在而開發期檔存在時, 發布腳本於全部檢查通過後將其更名為正式檔名並 commit, 只提交該檔, 不 push.
